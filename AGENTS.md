# AI Assistant & Agent Guidelines for Sonicator

## Language of public text
Chat with the owner may be in Russian. Everything published on GitHub — release notes and titles,
issues, pull requests, commit messages, workflow and step names, repository documentation — is
written in English, the language of the project's public surface.

## Feature Backlog Source of Truth
The external roadmap and feature backlog for Sonicator is maintained at:
`~/Documents/orange303/Sonicator Features.md`

**Rule:**
Always consult `~/Documents/orange303/Sonicator Features.md` when:
- Planning new milestones or architectural stages.
- Proposing roadmap features or discussing backlog priorities.
- Reviewing feature requests or integration ideas (e.g., Sample Dicer / Loop Dicer integration, crash reporting, tag cloud, VST3/AU DAW plugins, AI agents, etc.).

## Releases
Publishing a release goes to **both** GitHub and Gumroad in the same pass, without asking for a
separate confirmation, once the installer builds are green. Tokens and authorisations are kept
outside the repository and reused. The exact recipe, product and page identifiers are in
`docs/RELEASE_INSTALLERS.md#publishing`.

## Knowledge Graph & Architecture
- Graphify knowledge graph is stored in `graphify-out/`.
- After modifying code, run `graphify update .` to keep the graph current.
- Architecture details are documented in `docs/ARCHITECTURE.md`.

## File Safety: exported audio is project media
`~/Library/Sonicator/exports/` — including `exports/drag/` — holds audio that DAW projects may
reference: selection exports and the WAVs materialised for drag-and-drop (EMU `.ebl`, REX2, REX
selections). These files are **not** test leftovers.

**Rule:**
- Never delete, move or "clean up" the exports folder or the drag cache without the owner's
  explicit request.
- Before removing any exported audio, check the DAW projects (Cubase `.cpr`, REAPER `.rpp`,
  Live `.als`, Bitwig `.bwproject`) for references to it.
- A cleanup of temporary files must name its targets explicitly, not a whole directory.

## Feature Specifications
- User manual (English, PDF): built with Typst from `docs/manual/`, screenshots generated by `tests/TestManualShots.cpp`; rebuild with `typst compile --font-path "$PWD/resources/fonts" --root . docs/manual/manual.typ docs/manual/sonicator-manual.pdf`. See `docs/manual/README.md` and the design `docs/superpowers/specs/2026-11-17-user-manual-design.md`.
- Batch Processing v1 and audio converter: implemented; see `docs/BATCH_PROCESSING.md`, acceptance `docs/BATCH_PROCESSING_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-15-batch-processing-tz.md`. The broader converter design `docs/superpowers/specs/2026-11-14-batch-audio-converter-design.md` covers later stages.
- User plugin system plan and requirements: `docs/superpowers/specs/2026-11-14-user-plugins-design.md` (design only; not implemented).
- Genre column: implemented (schema 17); see `docs/GENRE.md`, spec `docs/superpowers/specs/2026-11-14-genre-column-design.md`.
- Customizable keyboard shortcuts: implemented in `stage-settings-hotkeys-layout`; see `docs/COMMANDS.md`, `docs/SHORTCUTS.md`, spec `docs/superpowers/specs/2026-11-14-customizable-shortcuts-design.md`.
- Settings navigation: implemented in `stage-settings-hotkeys-layout`; see `docs/SETTINGS_HOTKEYS_LAYOUT_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-14-settings-navigation-design.md`.
- Workspace Studio styling (header, toolbar, table, Analysis, Preview, dialogs): implemented in `stage-workspace-studio`; see `docs/WORKSPACE_STUDIO_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-14-workspace-studio-design.md`, plan `docs/superpowers/plans/2026-11-14-workspace-studio.md`.
- Preview spectrum: the preview card switches between the waveform and a spectrogram with the tabs above the card, the `preview.toggleSpectrum` command (`V`) or the context menu. The time range, selection, zoom, loop drag, external drag and playhead are one implementation for both views; `core/dsp/Spectrogram` does the budgeted STFT/log mapping and `core/preview/SpectrogramService` runs it on a latest-wins worker. See `docs/PREVIEW.md`, acceptance `docs/PREVIEW_SPECTROGRAM_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-26-preview-spectrogram-design.md`.
- Spectral cache and 2D selection: a whole-file overview (`.sps` + PNG) under `~/Library/Sonicator/spectra` makes the spectrum open instantly, and `Spectral analysis (N)...` in the sample/folder menus precomputes it with progress. Inside the spectrum, Rect/Lasso/Wand build a `SpectralMask` whose masked WAV is prepared for drag and auditioned through the matched transport; MIDI Preview plays that same fragment. Both shipped in 0.4.0. See `docs/PREVIEW.md`, acceptance `docs/SPECTRAL_SELECTION_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-26-spectral-cache-and-selection-design.md`.
- Zero-crossing snap: the card's `Snap` chip, the `preview.toggleSnapToZero` command (`Z`, persisted in `AppSettings::snapToZeroCrossing`), makes a dragged range edge land on the nearest crossing of the source, so exports and loops do not click. `core/dsp/ZeroCrossing` averages the channels, looks five milliseconds either side, falls back to the quietest frame and leaves a silent window alone; only gestures snap, a programmatic range stays exact.
- DAW plugin P1: `SONICATOR` VST3/AU browser on the shared catalog with project state and disabled heavy jobs; see `docs/PLUGIN.md`, plan `docs/superpowers/plans/2026-11-15-plugin-product-p1.md`.
- Plugin Match BPM / Match Scale (P2): implemented in `stage-plugin-match` with offline Rubber Band 3.3.0 rendering, per-project toggles, prepared preview/waveform and shared matched drag. REX2/sampler/tracker/disc matching is refused, not guessed; manual DAW/auval acceptance and Windows/universal builds remain open. See spec `docs/superpowers/specs/2026-11-16-plugin-match-bpm-scale-design.md`, plan `docs/superpowers/plans/2026-11-16-plugin-match-bpm-scale.md`, acceptance `docs/PLUGIN_MATCH_ACCEPTANCE.md`.
- Catalog safety and plugin state: the plugin never migrates the shared catalog (schema 20 in `core/database/CatalogSchema.h`, read-only check in `core/database/CatalogCompatibility.h`); embedded dialogs and state restore while the editor is open live in `ui/shell/ThemedDialogs.h` and `plugin/PluginEditor.cpp`; see `docs/PLUGIN.md`, plan `docs/superpowers/plans/2026-11-15-plugin-safety-and-beta.md`.
- Round tag menu: Settings → General → TAGS enables a radial two-orbit tag picker opened from a Tags pill in the row menu or Ctrl/Cmd+T, ranked by a personal `tag_usage` counter (schema 20); AutoTag now takes the Type column first, auditions proposals on selection, and Assign last used tag has a default ⇧⌘T. See spec `docs/superpowers/specs/2026-11-18-round-tag-menu-design.md`, plan `docs/superpowers/plans/2026-11-18-round-tag-menu.md`, acceptance `docs/ROUND_TAG_MENU_ACCEPTANCE.md` and `docs/TAG_FOLLOWUPS_ACCEPTANCE.md`.
- Cloud tag map: the library has a second view, "Cloud". One node per tagged file; tag islands are packed touching into one continuous cloud, real timbre descriptors place files inside them, and 84-value vectors sharpen the local neighbourhood where they exist. No island discs or background glow are drawn: points of uniform brightness carry the colour, the hovered point gets a small halo and the selected point a larger accent glow, ambient sway is display-only, and a large, softly feathered hover lens magnifies the neighbourhood under the cursor. Spec `docs/superpowers/specs/2026-11-15-cloud-tag-map-design.md`, plan `docs/superpowers/plans/2026-11-15-cloud-tag-map.md`, notes and measurements `docs/CLOUD_MAP.md`. The layout is deterministic and cached by fingerprint (`core/cloud/`); the view draws world-space layers and never rebuilds on a filter change (`ui/cloud/`), while the tag and Type filters hide the non-matching points and take them out of the hit test and hover; hover audio is a separate voice in `PreviewOutput` (`core/audio/HoverAudition`). Untagged files are not on the map, and files without a decodable format stay silent with an honest caption.
- Linux release: AppImage and `.deb` for x86_64, built in CI inside `ubuntu:22.04` because an AppImage carries no glibc and the build host's glibc becomes every user's floor (2.35). Packaging is `packaging/linux/build-packages.sh`; state in `docs/LINUX_PORT.md`, owner results in `docs/LINUX_ACCEPTANCE.md`, spec `docs/superpowers/specs/2026-11-17-linux-release-design.md`, plan `docs/superpowers/plans/2026-11-17-linux-release.md`. ALSA and JACK are both compiled in; the VST3 plug-in for Linux and Flatpak are out of scope.
- CAF `.caf`: implemented in 0.4.0 (`core/caf/CafAudioFormat`) as a cross-platform reader: linear PCM 8/16/24/32-bit and 32/64-bit float in either byte order, µ-law, A-law, and Apple IMA4 (QuickTime layout, low nibble first); ALAC/AAC and more than two channels are refused with a reason. Registered before JUCE's formats so macOS CoreAudio cannot claim `.caf`, indexed by the scanner, and structurally checked in `validateContainer`. Writing CAF is out of scope. See `docs/CAF.md`.
- Slate Trigger `.tci`: deferred feasibility note in `docs/TCI.md`: proprietary bitstream instrument, MIT clean-room decoder `tci2wav` as prior art, blocked on a real `.tci` sample and a decision on partial stereo transients.
- Windows icon: the Start-menu shortcut is deliberately not advertised so it uses the executable icon; the MSI carries the juceaide-generated `icon.ico` for Apps & features, and the app sets its window icon on the peer. Automated checks now cover the executable icon, the single MSI icon row, the plain shortcut and the window's `WM_GETICON` handles; shell surfaces (pins, Alt+Tab, upgrade) still need the recorded manual matrix in `docs/RELEASE_INSTALLERS.md`.
- File safety: red `Delete from disk...` moves ordinary files to Trash and refuses container members, links and exports; `Find duplicates...` (library, row and folder menus; a folder scope only lists copies inside it) reviews byte-identical groups and offers Trash, permanent deletion or verified symbolic-link replacement with a recovery journal; Settings -> Editing chooses Trash or permanent disposal for replaced originals; `Ignore symlinks` next to `Hide empty` hides aliased rows (also checkable in the LIBRARY menu), backed by the additive `samples.is_link` flag and a one-time background pass. See `docs/FILE_SAFETY.md`, spec `docs/superpowers/specs/2026-11-21-file-safety-and-windows-icons-design.md`.
- Update check: the standalone checks GitHub once three seconds after launch and only a newer release opens a dialog that shows that release's notes in a scrolling field, a Support row with Ko-fi and Boosty, Release notes, a platform-specific Download from GitHub and Gumroad; Settings -> About still checks on demand. The plugin never checks. See `docs/ARCHITECTURE.md`, `docs/PRIVACY.md`.
- Type autodetection measurement: `services/training/evaluate-shipped.mjs` scores the shipped `resources/ml/global_model.json` against the contribution export with no training, keeping confirmed types and tag-derived labels apart and never using a copy of the same audio as its own prototype. The first run and the open defects (a raw local cosine outranking the calibrated model, the vocabulary gap, the hat/tamb and ride/hat confusions) are in `docs/AUTODETECT.md`; the generated tables are `docs/AUTODETECT_HELDOUT.md`. Since 0.3.3 a loaded schema-2 model answers alone and local prototypes no longer outvote it: on the independent set top-1 rose from 10.5% to 55.7% at 83.3% precision. The vocabulary gap and the percussion families still need labelled data.
