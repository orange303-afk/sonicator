# Cloud map — карта библиотеки по тегам и звуку

Второе представление библиотеки: `core/cloud/` считает раскладку, `ui/cloud/CloudView` рисует её,
`core/audio/HoverAudition` прослушивает точку под курсором.

ТЗ: `docs/superpowers/specs/2026-11-15-cloud-tag-map-design.md`.
План: `docs/superpowers/plans/2026-11-15-cloud-tag-map.md`.

## Что на карте

Один узел — один файл с тегами. Неразмеченные файлы (340 192 из 375 828 на каталоге владельца)
не показываются: у них нет острова.

| Данные | Файлов | Что дают |
|---|---|---|
| с тегами | 35 636 | все точки карты |
| с двумя и более тегами | 4 927 | точки-перемычки между островами |
| с базовыми дескрипторами | 33 862 | проекция внутри острова |
| с 84-мерным вектором v2 | 13 991 | уточнение локального соседства |
| без аудио (metadata-only, нечитаемые) | 1 774 | центр острова, без звука |

Покрытие v2 перекошено: Loop 1 545 из 1 546, Kick 1 776 из 2 363, но Chord 219 из 2 089,
Stab 103 из 1 951, Dubtechno 175 из 9 339. Поэтому карта — карта **тегов** с акустическим
уточнением там, где оно есть, а не глобальная проекция звука.

## Как считается

1. **Острова.** 47 тегов раскладываются пружинами по совместной встречаемости (вес — доля
   меньшего тега) и упаковываются **вплотную**: окружности касаются и перекрываются на 28 %.
   Карта читается как одно облако, а не как кольцо отдельных дисков. Радиус
   `13 + 1.15·√n`: тег с одним файлом остаётся видимым, Dubtechno не съедает карту.
2. **Якорь.** Точка садится в среднее центров тегов файла; несколько тегов дают перемычку.
3. **Проекция.** В неё входят только тембральные дескрипторы: RMS, пик, centroid, rolloff,
   flatness. Длительность, частота и каналы квантованы (тысячи файлов имеют ровно 1.0 с) и
   раньше выстраивали файлы в линии, поэтому они исключены. Значения мягко насыщаются
   (`tanh`) вместо жёсткого clamp: без яркой рамки из выбросов. Квадрат проекции затем
   переводится в диск и получает 2–3 низкие гармоники от `tag.id` — остров становится
   облаком с рваным краем. Детерминированный джиттер 10 % радиуса (хеш `sample_id`) рвёт
   остаточные полосы от одинаковых векторов.
4. **Уточнение v2.** 84 значения сжимаются до 8 компонент, kNN (k = 8) по сетке, две итерации
   притяжения, смещение не больше `0.4·R` острова. Точки занимают 92 % радиуса, поэтому соседние облака сливаются.
5. **Вырожденные случаи.** Файл без дескрипторов — ровно в центре острова, флаг
   `cloudNoPosition`. Одинаковые векторы разводятся золотой спиралью по возрастанию `id`.
   NaN не даёт NaN в координатах.

Детерминизм: без ГСЧ, вход сортируется по `id`, фиксированное число итераций. Один и тот же
fingerprint даёт побитово одинаковые координаты — это проверяет `TestCloudLayout`.

## Кэш и воркер

`~/Library/Sonicator/cache/cloud/layout-<fingerprint>.bin`, держится не больше двух файлов.
Fingerprint считается по версии алгоритма, тегам (id, цвет, количество), назначениям,
наличию дескрипторов и v2, самим значениям v2 и времени анализа. Смена фильтра fingerprint
не меняет: фильтр — это видимость, а не раскладка.

`CloudBuildService` открывает своё соединение с каталогом, читает размеченные файлы одним
пакетом, строит раскладку в фоновом потоке и публикует результат только для своего поколения.
Отмена проверяется между фазами. Пересчёт запускают: изменение тегов (проверяется дешёвым
опросом таблицы тегов раз в 100 мс), первая активация «Облака», смена каталога.

## Интерфейс

- Переключатель **List / Cloud** в шапке LIBRARY; режим сохраняется в `settings.json`.
- Наведение — подпись, ореол и звук (10 мс рампа, первые ≤ 10 с файла, LRU на один запрос).
  Звук молчит, пока выбран семпл или играет транспорт preview, и молчит для форматов, которые не открывает
  общий декодер (RX2, EXS, NKI, SF2, AKAI, трекеры — 5 % карты).
- Щелчок — выбор файла через тот же путь, что и строка списка (с подтверждением несохранённых
  правок волны). Если строки нет на загруженной странице, список остаётся без выделения:
  подменять его чужим файлом нельзя. Погашенные фильтром точки не исчезают и по-прежнему открываются щелчком: фильтр меняет видимость, а не право посмотреть файл.
- Колесо — зум к курсору, перетаскивание фона — панорама, **Back** — история камеры (20 шагов),
  **Overview** — вписать всё, двойной щелчок — приблизить остров.
- Перетаскивание точки наружу — тот же неразрушающий drag файла, что у строки списка (копия,
  не перемещение; кэш EBL переиспользуется). Правый клик — меню строки.
- Дисков, обводок и фонового свечения нет: только точки на фоне. Все точки одинаковой
  яркости; цвет — тег, размер 4 px в обзоре (слой строится под масштаб вписывания) и 2.6 px
  в зуме. Свечение оставлено только у выделенной точки (акцентный ореол и кольцо).
- **Анимация.** Вход 650 мс и качание облака ±1 px (0.06 Гц); 30 Гц. Камера и линза — 60 Гц. В обзоре весь кадр — один кэш-блит плюс лёгкая волна
  дыхания поля; в зуме (≤ 1500 видимых точек) точки рисуются живьём и дрейфуют на ±0.6 px.
- **Линза наведения.** Радиус 120 px (примерно вдвое больше площади), смещение точек наружу
  `1.05·(1−(d/R)²)^3`, точка под курсором не двигается. Край гасится очень длинной
  радиальной маской (переход на 80 % радиуса, smoothstep), поэтому пятно читается как
  размытие соседства, а не как круг; размер соседних точек растёт до 1.5×. Хит-тест, выбор и
  drag работают по несмещённым координатам.
- Подписи: в обзоре — 10 крупнейших, с пропуском пересечений и фейдом после остановки
  камеры; при зуме появляются остальные, при наведении подпись файла.

## Замеры

Каталог владельца, 35 636 точек, Apple Silicon:

| Операция | Debug | Release |
|---|---|---|
| чтение каталога (`loadCloudInput`) | 0.8–1.3 с | 0.46–0.48 с |
| раскладка (`buildCloudLayout`) | 5.8–14 с после упаковки; Release не замерен | — |
| compose кадра при смене камеры | 7–16 мс | 10 мс |
| кадр из кэша (наведение, подсветка) | 0.15–0.26 мс | 0.24 мс |
| пересборка вложенного кэша после правок | 17–28 мс Debug | — |
| кадр с линзой (тот же кэш + пятно) | ~8.7 мс Debug | — |

Кадр собирается заново только когда меняется камера: острова и точки лежат в двух world-space
слоях, для обзора — в одном общем, подписи отрисованы в картинки заранее. Пока камера движется,
подписи не рисуются; на покое кадр пересобирается один раз. Тест `Painting 35k points` печатает
оба числа.

## Проверка на реальных звуках

`tools/cloud-layout-report` (собирается с `-DSONICATOR_BUILD_TOOLS=ON`):

```
cloud-layout-report --db ~/Library/Sonicator/sonicator.sqlite --out /tmp/cloud-report
```

Пишет `layout.svg`, `layout.csv`, `neighbours.txt`. Соседи опорных точек на каталоге владельца
совпадают по паку и инструменту, например Kick из Samplephonics Dub Techno → Kick_05/28/01/33
того же пака; Bass из Vengeance → соседние Bass Cuts; Chord → E-Piano и органы того же банка.
Слушать: 12 опорных точек из `neighbours.txt`.

## Ограничения

- Соседство «подробное» только у 39 % точек; на Dubtechno, Chord и Stab карта опирается на
  базовые признаки и тег.
- 5 % точек без звука при наведении — честная подпись «no audio position».
- Проекция базовых дескрипторов даёт полосы (дискретные длительности), а не равномерное облако.
- Права на новые форматы прослушивания (RX2, трекеры, инструменты) — отдельная задача.
- Меню и drag работают с одной точкой; групповое выделение на карте — следующий этап.
