# SONICATOR 0.3.2

0.3.2 fixes the Cloud view on large libraries: the map no longer freezes the window while it is
built, opens on the last map you saw instead of an empty screen, and the hover lens no longer
redraws every point. Everything else is the 0.3.1 feature set.

Each installer contains the application and, where it exists, the DAW plug-in. The Catalina package
leaves out ONNX Runtime, whose bundled library requires macOS 13.3; the application and plug-ins work
normally and the optional neural classifier falls back to the built-in acoustic rules.

## What changed since 0.3.1

- **The Cloud view no longer freezes the window.** Two separate causes are gone. The background build
  was joined on the window's own thread, so re-opening Cloud or editing a tag waited for the previous
  layout to finish; the worker now runs to its next cancellation check and a newer build takes over
  without waiting. And the point layer was drawn as one path per colour: on a 52 000-file library a
  single path held 19 000 dots together and kept the window busy for tens of seconds. Dots are now
  filled one by one, and the layer builds in a fraction of a second instead of a minute.
- **Cloud opens on the map you last saw.** The previous layout of this catalog is put on screen
  before the catalog is read, and a quiet background check replaces it only if something actually
  changed. A retagged library no longer starts with an empty view and "Building the map..." for
  twenty seconds.
- **No more pointless rebuilds.** The layout fingerprint now follows the descriptor values and the
  stored feature vectors instead of the analysis timestamp, so a background reanalysis that produces
  the same numbers no longer rebuilds an identical map.
- **The hover lens only redraws the lens.** In the overview, a hover frame keeps the cached map and
  redraws just the files inside the lens disc; it used to redraw all 52 000 points on every frame at
  up to 60 Hz.
- **Build phases are logged.** `sonicator.log` records how long reading the catalog, building the
  layout and writing the cache took, and a cancelled or failed build says so instead of failing
  silently.

The catalog schema stays at 20; a 0.3.1 catalog opens without a migration. The first launch after
this update rebuilds the Cloud map once because the fingerprint changed; later launches open on the
cached map immediately.

## What is included

**macOS (universal, arm64 + x86_64, macOS 11 or newer)**
`SONICATOR-0.3.2-macOS-universal.pkg` — application, VST3 and AU. Components are selected
individually on the installer's customize screen.

**macOS 10.15 (Intel only)**
`SONICATOR-0.3.2-macOS-x86_64-10.15.pkg` — application, VST3 and AU. No ONNX Runtime.

**Windows (x64, Windows 10 or newer)**
`SONICATOR-0.3.2-Windows-x64.msi` — application and VST3. AU exists on macOS only.

**Linux (x86_64) — in development, may be unstable**
`SONICATOR-0.3.2-Linux-x86_64.AppImage` and `SONICATOR-0.3.2-Linux-amd64.deb` — the application
only; there is no VST3 plug-in for Linux yet. These are still an early preview: audio devices, DAW
drag-and-drop, HiDPI and Wayland remain unverified by the owner.

Install locations: `/Applications/SONICATOR.app`, `/Library/Audio/Plug-Ins/VST3`,
`/Library/Audio/Plug-Ins/Components` on macOS; `Program Files\SONICATOR` and
`Program Files\Common Files\VST3` on Windows; `usr/bin/SONICATOR` and `usr/lib/sonicator` for the
Linux package. The library, settings and exported audio are never touched by install, upgrade or
uninstall.

## Signing and Gatekeeper

The packages are **unsigned**: no Developer ID, no Apple notarization, and the macOS bundles carry an
ad-hoc signature. The Windows installer has no Authenticode signature, and the Linux packages have no
signature and no distribution repository. macOS may block the `.pkg` — use *System Settings → Privacy
& Security → Open Anyway* after the first attempt; Windows SmartScreen may warn — use *More info → Run
anyway*. The installers remove the quarantine attribute from SONICATOR's own bundles only.

## Verified

CI on disposable runners installs the packages, starts the installed application, validates the
plug-in with `pluginval` at strictness 10, runs `auval` for the native AU slice and reinstalls while
checking that the catalog, preferences and exported audio are unchanged. The Windows job runs the full
suite and gates the branch; the Linux job runs the suite under Xvfb and checks the package layout and
dependencies. The Cloud changes are covered by new tests: cancellation of the catalog read, the last
cached map belonging to its own catalog, the fingerprint ignoring analysis time, a dense 52k point
layer inside a frame budget, and a hover frame inside a frame budget.

## Known limits

- The Type and structure filters apply to the list; the Cloud view keeps showing every tagged file.
- Type and structure come from the analyzer or a manual correction; the application does not guess,
  so an unclassified file stays in the library when both structure filters are on.
- A Windows taskbar pin created under 0.1.0 can keep its blank image until it is recreated.
