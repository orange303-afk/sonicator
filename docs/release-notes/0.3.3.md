# SONICATOR 0.3.3

0.3.3 fixes type detection for a second person's library, makes the Cloud map follow the tag and Type
filters, and shows what changed in a new version right in the update window, with the support links
under it. Everything else is the 0.3.2 feature set.

Each installer contains the application and, where it exists, the DAW plug-in. The Catalina package
leaves out ONNX Runtime, whose bundled library requires macOS 13.3; the application and plug-ins work
normally and the optional neural classifier falls back to the built-in acoustic rules.

## What changed since 0.3.2

- **Type detection stops trusting a raw cosine over the model.** When the shipped model is loaded it
  now answers on its own; a local prototype no longer changes its order or fills a Type the model did
  not name. The two numbers were on different scales: a calibrated precision against an uncalibrated
  similarity. On the independent contributed library (3157 tag-derived rows) the first answer was
  right for 10.5% of files before and 55.7% now, and published answers were 10.3% correct before and
  83.3% now. Nothing was retrained and the model file is unchanged; manual Types are untouched, and
  the local path still answers when no model is shipped. The full comparison is in
  `docs/AUTODETECT.md` and `docs/AUTODETECT_HELDOUT.md`.
- **The Cloud map follows the tags and the Type filter.** Points that do not match are not drawn, do
  not answer hover and cannot be clicked or dragged; clearing the filters brings every point back in
  place. Search, folder, paging and the structure checkboxes stay filters of the list. With no match
  the map keeps its shape and says so instead of going blank. A filter never rebuilds the layout,
  changes the camera or moves a point.
- **The update window shows what changed.** The notes of the new release are read from the same GitHub
  answer as the version and shown in a scrolling field, under a *Support SONICATOR* row with *Ko-fi*
  and *Boosty* in the accent colour. When a release carries no notes the field says so and the
  download stays available. *Download from GitHub*, *Release notes*, *Gumroad* and *Later* are
  unchanged.
- **User manual** — rebuilt for 0.3.3 with the Cloud filters and the update window.

The catalog schema stays at 20; a 0.3.2 catalog opens without a migration. The filter and the notes
are view behaviour and a network answer, not stored schema.

## What is included

**macOS (universal, arm64 + x86_64, macOS 11 or newer)**
`SONICATOR-0.3.3-macOS-universal.pkg` — application, VST3 and AU. Components are selected
individually on the installer's customize screen.

**macOS 10.15 (Intel only)**
`SONICATOR-0.3.3-macOS-x86_64-10.15.pkg` — application, VST3 and AU. No ONNX Runtime.

**Windows (x64, Windows 10 or newer)**
`SONICATOR-0.3.3-Windows-x64.msi` — application and VST3. AU exists on macOS only.

**Linux (x86_64) — in development, may be unstable**
`SONICATOR-0.3.3-Linux-x86_64.AppImage` and `SONICATOR-0.3.3-Linux-amd64.deb` — the application
only; there is no VST3 plug-in for Linux yet. These are still an early preview: audio devices, DAW
drag-and-drop, HiDPI and Wayland remain unverified by the owner.

Install locations: `/Applications/SONICATOR.app`, `/Library/Audio/Plug-Ins/VST3`,
`/Library/Audio/Plug-Ins/Components` on macOS; `Program Files\SONICATOR` and
`Program Files\Common Files\VST3` on Windows; `usr/bin/SONICATOR` and `usr/lib/sonicator` for the
Linux package. The library, settings and exported audio are never touched by install, upgrade or
uninstall.

## Signing and Gatekeeper

The packages are **unsigned**: no Developer ID, no Apple notarization, and the macOS bundles carry an
ad-hoc signature. The Windows installer has no Authenticode signature, and the Linux packages have no
signature and no distribution repository. macOS may block the `.pkg` — use *System Settings → Privacy
& Security → Open Anyway* after the first attempt; Windows SmartScreen may warn — use *More info → Run
anyway*. The installers remove the quarantine attribute from SONICATOR's own bundles only.

## Verified

The Windows suite covers the classifier change and the Cloud filter: a local prototype no longer
outranks the model, a weak model answer is not turned into a local one, and a hidden point leaves the
hit test, the hover and the click while the camera stays put. The update parser is tested with notes,
without notes and with a non-string body, and the update window is painted offscreen with long notes.
The full Windows suite passes (1331 cases, 1322 passed, 9 platform skips, 0 failures). The held-out
evaluation was re-run on the contributed export and its tables are in `docs/AUTODETECT_HELDOUT.md`.

## Known limits

- The tag and Type filters apply to the Cloud map; the search text, the folder scope and the structure
  filters still describe the list only.
- Type and structure come from the analyzer or a manual correction; the application does not guess,
  so an unclassified file stays in the library when both structure filters are on.
- `fx`, `riser`, `impact`, `downfilter`, `synth`, `drop` and `foley` still cannot come out of the type
  model; they need labelled data, not a merge rule.
- A Windows taskbar pin created under 0.1.0 can keep its blank image until it is recreated.
