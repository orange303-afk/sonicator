# SONICATOR 0.2.0

The 0.2.0 release makes removing files and cleaning duplicate samples deliberate and recoverable,
keeps the catalog compatible with 0.1.x, adds an update notice at launch, and ships an installer
for Macs that cannot install the universal package.

## Download

| Your system | File |
|---|---|
| macOS 11 or newer, Apple silicon or Intel | `SONICATOR-0.2.0-macOS-universal.pkg` |
| macOS 10.15, Intel only | `SONICATOR-0.2.0-macOS-x86_64-10.15.pkg` |
| Windows 10 or newer, 64-bit | `SONICATOR-0.2.0-Windows-x64.msi` |
| Ubuntu 22.04 or newer, Debian 12 or newer, 64-bit | `SONICATOR-0.2.0-Linux-amd64.deb` |
| Any other 64-bit Linux | `SONICATOR-0.2.0-Linux-x86_64.AppImage` |
| User manual (PDF) | `sonicator-manual.pdf` |

Each installer contains the application and, where it exists, the DAW plug-in. Nothing else is
needed. The Catalina package leaves out ONNX Runtime, whose bundled library requires macOS 13.3;
the application and plug-ins work normally and the optional neural classifier falls back to the
built-in acoustic rules.

## What changed since 0.1.1

- **Delete from disk** — a separate red item in a row's context menu for one file or a
  multi-selection. It confirms the paths, total size and the DAW-reference risk, moves ordinary
  files to the platform Trash and never falls back to permanent deletion. Container members,
  symbolic links, Sonicator exports and files with unsaved waveform edits are refused. A failed
  move leaves the file and its catalog row in place and is reported individually.
- **Duplicate cleanup** — `Find duplicates...` in the library, row, folder and favorites menus.
  Groups are byte-identical files (same size and full SHA-256), re-verified immediately before any
  action. A folder scope only lists copies inside that folder. The review window keeps one
  original per group, checks copies explicitly, auditions a copy on click through the main preview,
  and offers three actions:
  - move redundant copies to Trash;
  - delete them permanently;
  - replace them with symbolic links to the kept original.
  Link replacement stages the old copy in a recovery journal and restores it if anything fails;
  an interrupted run is recovered on the next start. The summary reports bytes freed for permanent
  deletion and verified links, and bytes moved to Trash separately, since Trash holds them until it
  is emptied.
- **Replaced originals** — next to `Always overwrite original files`, Settings → General → EDITING
  now chooses `Move to Trash` (default) or `Delete permanently` for the file an overwrite replaces.
  The old file is kept until the new one is published; a permanent choice always shows one explicit
  warning, even with the overwrite shortcut on. The setting never applies to Delete from disk or
  to duplicate cleanup.
- **Ignore symlinks** — a toolbar checkbox next to `Hide empty` (and a LIBRARY-menu item on narrow
  windows) hides rows whose path is a symbolic link, including copies replaced by links in
  duplicate cleanup. An additive `samples.is_link` column is not a schema-version bump, so a 0.1.x
  build still opens the same catalog; an older catalog gets one background pass the first time the
  option is enabled.
- **Update notice** — the standalone checks GitHub once, three seconds after launch. Only a newer
  release opens a window with `Release notes`, `Download from GitHub` for this platform and
  `Gumroad`; a failed or equal check is silent. Settings → About keeps its on-demand check, and the
  DAW plug-in never checks.
- **macOS 10.15 installer** — an Intel-only package for Macs that cannot install the universal one,
  built with the same three components and without ONNX Runtime.
- **Fix: the window could freeze after a large duplicate cleanup** — catalog row removal scanned
  the whole samples table for each deleted path because `container_path` had no index. The column is
  now indexed, and the catalog update runs off the message thread with an `Updating the catalog...`
  status.
- **Windows icon** — automated checks now cover the executable's 16/32/48/256 px icons, the single
  MSI icon row, the plain Start-menu shortcut and the running window's large and small icon
  handles. A taskbar pin created under 0.1.0 can keep its blank image until it is recreated;
  unpin and pin again after installing this version.
- **User manual** — rebuilt for 0.2.0 with the new installers, file safety and update notice.

The catalog schema stays at 20. The new `samples.is_link` column and its index are additive and
readable by 0.1.x.

## What is included

**macOS (universal, arm64 + x86_64, macOS 11 or newer)**
`SONICATOR-0.2.0-macOS-universal.pkg` — application, VST3 and AU. Components are selected
individually on the installer's customize screen.

**macOS 10.15 (Intel only)**
`SONICATOR-0.2.0-macOS-x86_64-10.15.pkg` — application, VST3 and AU. No ONNX Runtime.

**Windows (x64, Windows 10 or newer)**
`SONICATOR-0.2.0-Windows-x64.msi` — application and VST3. AU exists on macOS only.

**Linux (x86_64) — in development, may be unstable**
`SONICATOR-0.2.0-Linux-x86_64.AppImage` and `SONICATOR-0.2.0-Linux-amd64.deb` — the application
only; there is no VST3 plug-in for Linux yet.

> ⚠️ **The Linux builds are an early preview.** They are published so Linux users can try the port
> and report problems, and they are *not* in the same state as the macOS and Windows packages. No
> owner acceptance has been run: audio devices (ALSA, JACK and PipeWire), drag-and-drop into DAWs,
> HiDPI and Wayland are unverified, and rough edges are expected. See `docs/LINUX_PORT.md` and
> `docs/LINUX_ACCEPTANCE.md` in the source for what has and has not been checked.

Install with `sudo apt install ./SONICATOR-0.2.0-Linux-amd64.deb`, or `chmod +x` the AppImage and
run it from any directory (on a machine without FUSE, add `--appimage-extract-and-run`).

Install locations: `/Applications/SONICATOR.app`, `/Library/Audio/Plug-Ins/VST3`,
`/Library/Audio/Plug-Ins/Components` on macOS; `Program Files\SONICATOR` and
`Program Files\Common Files\VST3` on Windows; `usr/bin/SONICATOR` and `usr/lib/sonicator` for the
Linux package. The library, settings and exported audio are never touched by install, upgrade or
uninstall.

## Signing and Gatekeeper

The packages are **unsigned**: no Developer ID, no Apple notarization, and the macOS application and
plug-ins carry an ad-hoc signature. The Windows installer has no Authenticode signature either, and
the Linux packages have no signature and no distribution repository.

- macOS may block the `.pkg` itself. After attempting to open it, use *System Settings → Privacy &
  Security → Open Anyway* when the system offers that option.
- After installation the selected components have their `com.apple.quarantine` attribute removed
  automatically — only SONICATOR's own bundles, with a bundle-identifier check and without following
  symlinks. Global security settings are not changed.
- Windows: SmartScreen may warn; use *More info → Run anyway*.
- Linux: nothing is signed and no apt repository exists, so upgrades are a manual `.deb` install or
  a replaced AppImage.

## Verified

CI on disposable runners installed the packages and started the installed application. On macOS it
ran `pluginval` at strictness 10 for VST3 and AU, ran `auval`, reinstalled while checking that the
catalog, settings and exported media stayed byte-identical, and hid the build-tree ONNX runtime to
prove the bundle is self-contained. On Windows it exercised repair, a major upgrade from a
higher-version fixture, per-component installs, uninstall, the Start-menu shortcut, the executable
icon at four sizes and the running window's icon handles, with the same user-data checks. On Linux
it built on the glibc 2.35 baseline, ran the full suite under Xvfb, started the built application
headless, and read the produced packages back to check their contents, dependencies and glibc
ceiling.

The duplicate cleanup, deletion, symlink and overwrite-disposal paths have regression tests for
byte comparison, journal recovery, link creation, refused files and freed-byte reporting.

Not covered: AU on Apple Silicon (CI runs on Intel for the universal package), real DAWs
(Cubase/Logic/REAPER), Windows audio/MIDI and SmartScreen, the visual taskbar-pin matrix on real
Windows machines, and the Linux acceptance list — the Linux application has never been run on a real
desktop by the owner. The full lists are in `docs/RELEASE_INSTALLERS_ACCEPTANCE.md`,
`docs/FILE_SAFETY.md` and `docs/LINUX_ACCEPTANCE.md`.

## Source

SONICATOR is AGPL-3.0-or-later, so the matching source ships with every binary: it is this
repository at tag `v0.2.0`. All packages were built from that tag's commit, which is recorded in
`source-commit.txt` in the workflow artifacts. Rebuild and relink instructions are in
`docs/RELEASE_INSTALLERS.md` and `packaging/`, and each build's source archive and checksums stay
in the workflow artifacts.
