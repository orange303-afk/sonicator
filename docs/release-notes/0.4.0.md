# SONICATOR 0.4.0

0.4.0 gives the preview card a second face: a spectrogram that opens instantly, can be prepared for a
whole folder ahead of time, and is a canvas you can select in. Rect, Lasso and the magic wand draw a
time-and-frequency selection, and that selection is a fragment you can hear, drag into a DAW and play
from MIDI. Everything else is the 0.3.3 feature set.

## What changed since 0.3.3

- **The preview card has a spectrum view.** The tabs above the card switch between the waveform and a
  spectrogram, and so do the `preview.toggleSpectrum` command (`V`) and the card's context menu. A
  `Log / Linear` pill switches the frequency axis. The time range, the zoom, the loop, the external
  drag and the playhead are one implementation for both views: everything you already do on the
  waveform works on the spectrum. A long range is analysed with a coarser time step and labelled
  *overview*. The view and the scale are remembered between launches.
- **The spectrum opens instantly.** The first view of a file computes a whole-file picture and keeps
  it under `~/Library/Sonicator/spectra`: the grid itself and a PNG of it. Selecting that file again
  — in this session or after a restart — draws it at once and only asks for a detail pass when you
  zoom in. An entry belongs to the file's path, size and modification time, so editing or replacing
  a file simply rebuilds its picture.
- **`Spectral analysis (N)…` prepares a selection or a folder.** It sits in the sample context menu
  under *Processing* and in the folder menu, runs two workers with progress in the status line and a
  cancel, skips files that are already cached and reports how many failed. The plug-in hides it with
  the other processing jobs. Settings → Library has *Cache spectrograms*, the current size and a
  *Clear cache* button; the cache keeps the newest 2000 entries under 512 MB.
- **Select inside the spectrum with Rect, Lasso and the magic wand.** Three new tools build a
  time-and-frequency selection: a rectangle drag, a freehand lasso closed on mouse-up, and a wand
  that fills the region around the click within 3 / 6 / 12 / 24 dB (click the `dB` pill to cycle).
  Each tool has its own cursor, a plain drag replaces the selection, Shift adds and Alt subtracts,
  and Clear, Escape or the context menu empty it. The selection is drawn exactly on the band it
  covers and stays put while you zoom and pan. The time range keeps working for Play, Loop and MIDI.
- **The 2D selection is audio.** It is prepared as a masked WAV: the range is analysed, every bin
  outside the selection is removed and the result is as long as the selection, with silence around
  it, so it keeps its place when dropped into a DAW. Grab the highlighted area to drag the fragment
  out, or press Play to audition it — the card keeps showing the original spectrum, the playhead
  follows the selection, Loop repeats it, and Stop returns to the source. MIDI Preview plays the same
  fragment, so a key sounds the selected band and time only; clearing the selection hands the whole
  sample back. Match and the spectral audition do not run together.
- **The looped audition holds up.** The transport that plays a masked fragment attached a read-ahead
  buffer while its reader looped, and the two wrapped the position differently: the second pass came
  out rung, choppy or silent. It now reads straight from the file while looping, exactly as the
  ordinary preview does.
- **Range edges snap to zero crossings.** *Snap* in the card's toggle row, the `Z` command or that
  shortcut rebound in Settings → Hotkeys makes a dragged selection edge land on the nearest zero
  crossing of the source, so an exported fragment or a loop starts and ends at silence and does not
  click. The magnet reaches five milliseconds either side of the pointer and mixes the channels, so a
  stereo edge is quiet in both; without a crossing it takes the quietest frame, and a range set by the
  application stays exactly where it was. Off by default and remembered between launches.
- **CAF files are part of the library.** Core Audio Format — what Logic Pro, Pro Tools and
  `afconvert` write — is read by Sonicator's own decoder on every platform: linear PCM at 8, 16, 24
  and 32 bits and 32/64-bit float in either byte order, µ-law and A-law, and Apple IMA4 packets.
  Scanning, waveform, playback, analysis, editing and drag work with no format-specific code. ALAC,
  AAC and every other compressed codec are refused with a named reason rather than half-decoded, and
  files wider than stereo are refused too. Writing CAF stays out of scope.
- **User manual** — rebuilt for 0.4.0 with a chapter on the spectrum, the tools and the cache
  (Figures 12.1 and 12.2), and CAF in the format appendix.

The catalog schema stays at 20; a 0.3.3 catalog opens without a migration. The spectral cache is a
separate folder of accelerator files, not catalog data, and deleting it only costs a recomputation.

install, upgrade or uninstall.

## Signing and Gatekeeper

The packages are **unsigned**: no Developer ID, no Apple notarization, and the macOS bundles carry an
ad-hoc signature. The Windows installer has no Authenticode signature, and the Linux packages have no
signature and no distribution repository. macOS may block the `.pkg` — use *System Settings → Privacy
& Security → Open Anyway* after the first attempt; Windows SmartScreen may warn — use *More info → Run
anyway*. The installers remove the quarantine attribute from SONICATOR's own bundles only.

## Verified

The Windows suite covers the stage end to end: the cached picture matches the computed grid, a
changed or truncated entry is a miss and never a wrong picture, pruning keeps the newest entries;
rectangles, lassos and wand rasters cover exactly their time and frequency; a full mask reconstructs
the signal (RMS error under 2 %) while a band mask removes everything outside its band; the exported
WAV is exactly as long as the range; the overlay is measured on a rendered card, column by column,
and only differs inside the selection; a press on the selection asks for an external drag and leaves
the mask unchanged, while Shift keeps drawing; the looped audition sounds in every block past four
passes; MIDI plays the prepared fragment and hands the source back when the selection is cleared.
CAF is decoded from generated files in both byte orders, at 16 and 24 bits and as float, through
µ-law, A-law and an IMA4 packet that must survive a round trip, with six refusal cases and a
truncated file landing in the library as invalid. Snapping is measured on a square wave whose
crossings sit on known frames: the nearest one wins, a tie is deterministic, a signal without a
crossing takes its quietest frame, a silent window is left alone, a dragged edge lands exactly on
the crossing, and a range set by the application does not move. The full Windows suite passes (1383 cases,
1374 passed, 9 platform skips, 0 failures).

## Known limits

- A 2D selection is not stored in the catalog, a project or the plug-in state: it lives as long as
  the card shows that source, and Clear or Escape empties it. There is no undo of a mask edit.
- The cache stores the logarithmic overview, so the `Linear` axis is analysed on demand and never
  opens instantly.
- Container sources (REX2, SoundFont, tracker, disc) never get a cache entry and, in MIDI Preview,
  can only be limited to the selection's time window, because the MIDI sampler cannot adopt a
  rendered WAV.
- A spectral selection longer than 60 seconds is refused with a message rather than exhausting
  memory: the inverse transform holds the whole range.
- CAF covers linear PCM, µ-law, A-law and Apple IMA4 only: ALAC, AAC and other compressed CAF files
  are refused with a named reason, files wider than stereo are refused, and CAF is read-only (the
  batch converter does not write it).
- The drag-out and the audition of a masked fragment were verified outside a DAW; the owner's
  manual acceptance with Cubase, REAPER, Live and Bitwig is still open.
- The tag and Type filters apply to the Cloud map; the search text, the folder scope and the structure
  filters still describe the list only.
- Type and structure come from the analyzer or a manual correction; the application does not guess,
  so an unclassified file stays in the library when both structure filters are on.
- `fx`, `riser`, `impact`, `downfilter`, `synth`, `drop` and `foley` still cannot come out of the type
  model; they need labelled data, not a merge rule.
- A Windows taskbar pin created under 0.1.0 can keep its blank image until it is recreated.
