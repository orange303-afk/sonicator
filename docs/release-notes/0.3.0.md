# SONICATOR 0.3.0

The 0.3.0 release adds a Type filter and two structure filters to the library, keeps a sorted page in
the catalog's own order, reads long durations as a clock, stops the search history from blocking the
first keystroke, and finishes the Windows port: its full test suite now passes and the shell icon is
drawn at the same size as its neighbours.

application and plug-ins work normally and the optional neural classifier falls back to the built-in
acoustic rules.

## What changed since 0.2.0

- **Type filter** — a `Type` pill in the toolbar opens the standard types and your custom ones.
  Choosing `Snare` shows files whose effective Type is Snare, whether the analyzer or a manual
  correction set it, and combines with tags, the search field and the structure filters. The pill
  reads `Type: Snare` while it is active; `All types` clears it. Typing `type:snare` still works and
  adds to the pill instead of replacing it.
- **Show loops and Show one-shots** — two checkboxes next to `Hide empty`. They filter on the
  structure the analysis confirmed, not on tempo: a loop whose BPM is unknown still passes
  `Show loops`, and a one-shot that carries a tempo still passes `Show one-shots`. Both on keeps the
  whole library, including files the analysis has not classified; one on keeps only that category;
  both off keeps only the rows that are neither, so phrases and unclassified files stay visible. The
  choice is remembered, and `Clear filters` turns both back on.
- **Fix: a sorted page kept the page's order, not the catalog's** — with a page size other than
  `All`, the table sorted the returned rows again by file name, so an ascending BPM page could read
  95, 100, 90. A page now keeps the order the catalog query produced, which is the whole-catalog
  order; Type, Key and Genre had the same problem.
- **Length reads as a clock** — durations below a minute keep two decimals (`0.35 s`, `59.50 s`);
  longer files read `01:30` and `01:02:05`. The Analysis card uses the same format.
- **Search history no longer blocks typing** — a click in the search field places the caret and you
  start typing at once; the clock button at the right of the field opens the last ten searches.
  Settings → SEARCH → `Open search history on click` restores the earlier behaviour for anyone who
  preferred it. The setting applies to the standalone application and to the DAW plug-in, where the
  old popup cost an extra dismissal before the first keystroke.
- **Windows: the plug-in takes keyboard focus** — a click that lands in the plug-in window also asks
  the window for keyboard focus, so typing starts in the search field instead of reaching the DAW's
  arrangement shortcuts. Reported on 0.2.0 in Fender Studio Pro (Studio One).
- **Windows: the port is finished** — the full test suite passes on Windows (1320 cases, 9 platform
  skips, no failures). The changes behind it are not test-only: the catalog now stores the platform
  separator, folder scopes and favourites match either separator, batch preflight identifies a file
  by volume and file index instead of a `stat` inode that is always zero on Windows, and a cancelled
  export closes its file before removing the partial one.
- **Windows: the taskbar icon has the standard size** — the mark is trimmed to a 2 % margin, so the
  rounded tile fills its canvas like the icons beside it. The macOS icon keeps the inset canvas its
  platform's grid expects.
- **User manual** — rebuilt for 0.3.0 with the new filters, the length format and the search setting.

The catalog schema stays at 20; a 0.2.0 catalog opens without a migration. The new filters and
preferences are view settings, not stored schema.

## What is included

**macOS (universal, arm64 + x86_64, macOS 11 or newer)**
`SONICATOR-0.3.0-macOS-universal.pkg` — application, VST3 and AU. Components are selected
individually on the installer's customize screen.

**macOS 10.15 (Intel only)**
`SONICATOR-0.3.0-macOS-x86_64-10.15.pkg` — application, VST3 and AU. No ONNX Runtime.

**Windows (x64, Windows 10 or newer)**
`SONICATOR-0.3.0-Windows-x64.msi` — application and VST3. AU exists on macOS only.

**Linux (x86_64) — in development, may be unstable**
`SONICATOR-0.3.0-Linux-x86_64.AppImage` and `SONICATOR-0.3.0-Linux-amd64.deb` — the application
only; there is no VST3 plug-in for Linux yet.

> **The Linux builds are an early preview.** They are published so Linux users can try the port and
> report problems, and they are *not* in the same state as the macOS and Windows packages. Audio
> devices (ALSA, JACK and PipeWire), drag-and-drop into DAWs, HiDPI and Wayland remain unverified
> by the owner. See `docs/LINUX_PORT.md` and `docs/LINUX_ACCEPTANCE.md` in the source for what has
> and has not been checked.

Install with `sudo apt install ./SONICATOR-0.3.0-Linux-amd64.deb`, or `chmod +x` the AppImage and
run it from any directory (on a machine without FUSE, add `--appimage-extract-and-run`).

Install locations: `/Applications/SONICATOR.app`, `/Library/Audio/Plug-Ins/VST3`,
`/Library/Audio/Plug-Ins/Components` on macOS; `Program Files\SONICATOR` and
`Program Files\Common Files\VST3` on Windows; `usr/bin/SONICATOR` and `usr/lib/sonicator` for the
Linux package. The library, settings and exported audio are never touched by install, upgrade or
uninstall.

## Signing and Gatekeeper

The packages are **unsigned**: no Developer ID, no Apple notarization, and the macOS application and
plug-ins carry an ad-hoc signature. The Windows installer has no Authenticode signature either, and
the Linux packages have no signature and no distribution repository.

- macOS may block the `.pkg` itself. After attempting to open it, use *System Settings → Privacy &
  Security → Open Anyway* when the system offers that option.
- After installation the selected components have their `com.apple.quarantine` attribute removed
  automatically — only SONICATOR's own bundles, with a bundle-identifier check and without following
  symlinks. Global security settings are not changed.
- Windows: SmartScreen may warn; use *More info → Run anyway*.
- Linux: nothing is signed and no apt repository exists, so upgrades are a manual `.deb` install or
  a replaced AppImage.

## Verified

CI on disposable runners installs the packages, starts the installed application, validates the
plug-ins with `pluginval` at strictness 10, runs `auval` for the native AU slice, and reinstalls
while checking that the catalog, preferences and exported audio are unchanged. The Windows job builds
the MSI, runs the installer lifecycle tests and the full suite, and the suite is a required check.
The Linux job runs the suite under Xvfb and checks the package's dependency list and file layout.

Locally, the Windows Debug suite passed twice with the release tree (1320 cases, 1311 passed, 9
skipped for platform reasons: symbolic links without Developer Mode, Windows ACLs instead of POSIX
mode bits, and a directory timestamp Windows refuses to backdate).

## Known limits

- The Type and structure filters apply to the list. The Cloud view keeps showing every tagged file;
  its hover and selection behaviour is unchanged.
- Type and structure come from the analyzer or a manual correction. A file nobody classified stays
  in the library when both structure filters are on, and is filtered out of either single-category
  view: the application does not guess.
- A Windows taskbar pin created under 0.1.0 can keep its blank image until it is recreated; unpin
  and pin again after installing this version.
- Developer ID signing, Apple notarization, Windows Authenticode and a Linux repository can be added
  later without changing plug-in identities or the installer's UpgradeCode.
