# Folder navigation and instrument preview

## Folder tree

The sidebar contains registered library roots and folders represented by catalogued files. Empty added roots remain visible; folders with no indexed audio are not separately discovered. Select **All samples** for the entire catalog, or a folder for its files and every descendant. Left/Right collapse/expand the selected folder. Children are materialised on expansion; paths are grouped once per unique folder. Selection and expanded branches survive scan completion.

Folder queries use the existing path index with separator-aware prefix bounds (Drums does not match Drums2); no schema migration or audio reanalysis. Results remain paged at 10,000 rows. Filename search and header sorting remain page-local, including inside a folder.

## Ordinary preview

**Auto Preview** is on by default: selecting a new file plays it, including when MIDI Preview is enabled. Turning it off makes selection silent; explicit **Play** remains available in both modes. **Auto Preview**, **MIDI Preview**, **Skip Silence**, **Loop** and **Gate** are persisted in `settings.json` and restored on the next launch. Programmatic selection restoration does not call the selection action. Reloading an unchanged selected path preserves its transport position. **Play** restarts after EOF; with **Loop** off, EOF stops permanently until another explicit Play. A changed file (size/mtime) is reloaded rather than treating its old preview as current.

Buttons and checkboxes do not take keyboard focus on click; nonmodal toolbar and preview actions restore focus to the file list so Up/Down continue navigating. Search and the folder tree retain their own keyboard behaviour when explicitly focused; modal dialogs/choosers must retain focus while open. The header uses a larger tightly cropped wordmark without a separate decorative icon; the OS app icon uses the user-selected glossy silver tile with a blue chevron (original and derivative retained in `resources/branding/`).

**Skip Silence** is off by default. When enabled, the next start from Stop/EOF begins one frame before the first finite nonzero decoded sample in any channel. It does not trim files, apply a noise threshold or alter playback already in progress. Pause/resume retains its position. Entirely silent audio starts at zero. Detection is performed on the control thread using bounded decode blocks, not on the audio callback; scanning a long entirely silent file can take time.

## Dragging original files

Select one or more library rows and drag them out of the window. The OS receives standard file URLs with `canMoveFiles = false`: Finder and the desktop copy, messengers attach, and DAWs import onto a track. The library original is never moved, renamed or deleted, and the app never needs per-target integration.

- A multi-row drag carries every selected existing original in current table order; missing files are skipped. If none remain, no drag starts and the status explains why.
- The row under the mouse is selected before the drag when it was not already selected. A normal click still seeks/previews.
- A drag starts after 5 px, so a click does not accidentally start an OS drag. Dragging does not alter the selection.
- Only external file drag is supported in this stage: no internal drag between app panes, no MIDI drag, and no multi-range drag.

## Waveform selection and export

Drag across the waveform by more than about 3 px to select a time range. Endpoints are clamped to the file and finalized in either direction. A plain click seeks and clears the selection; dragging from inside an existing selection starts the external file drag instead of editing it. A new file, `setFile`, or **Escape** clears the selection when the preview has keyboard focus. A **Clear** button appears while a selection exists and follows the same no-keyboard-focus policy as the transport buttons.

The overlay draws a translucent accent range, start/end lines and a compact `0.250–1.100 s` label. While a selection exists, a background worker exports it. The status reads **Preparing selection…**, then **Ready — drag the selection into a DAW**, or shows the explicit export error. Dragging before the file is ready is refused with that status; no export runs inside the mouse event, so the OS drag starts immediately once ready.

**Play** with a selection seeks to its start. The 30 Hz preview stops at the end, or seeks back to the start when **Loop** is on. This is preview accuracy (one timer tick), not sample-accurate editing. **Auto Preview** on row change still plays the whole file; loading a new file clears the selection first. A selection also bounds **MIDI Preview** for ordinary files and a selected tracker/disc source: each new note starts at the range start and one-shots to its end, or loops inside it while **Loop** is on. With no selection the whole source plays; SF2/EXS/NKI zone maps and REX slice maps are unaffected because their MIDI mapping is not a single time range.

Selection export is WAV only and never modifies the source. It preserves the source sample rate and channel count; 16-bit sources stay 16-bit PCM, 24/32-bit integer sources become 24-bit PCM, float sources become 32-bit float, and compressed sources become 24-bit PCM. There is no gain change, normalization, fade or time-stretch. Export writes `destination + ".part"` in bounded chunks and renames only after success, so a failed or cancelled export leaves no partial file.

REX2 selections are rendered from the decoded PCM kept for the preview, not through `AudioFormatManager` (which cannot read `.rx2`). The rendered file is a normal 24-bit WAV with the source rate and channels, so the same drag works in a DAW, Finder or a messenger. Exported selections live under `Sonicator/exports/` and are **not** deleted automatically: a DAW project or a message may still reference them. The folder grows until you remove files manually; a cleanup action is a later Settings feature. More than 64 channels is refused explicitly rather than downmixed.

External drag into DAWs/messengers is verified on macOS in this stage. Windows uses the same JUCE file-URL path but still needs separate verification.

## SoundFont 2 instruments and samples

Loading a `.sf2` keeps the existing preset selector and adds a sample selector for the unique audio sources used by that preset. Unused bank headers are not listed, repeated zones over one source are one row, and a stereo pair is one row keyed by its left header. Each row carries a stable per-generation id, its name, key/velocity range and an explicit reason when its PCM is unusable. Identical names remain distinguishable by row position and id.

Selecting a sample changes the waveform, ordinary Play/Pause/Stop/seek and the WAV selection export. It never changes the MIDI mapping: **MIDI Preview** still plays the selected preset with its original zones. The first usable sample is selected deterministically on load; silent session restore loads it without starting playback. An empty, unsupported or missing instrument clears the old waveform and shows the reason.

While no range is selected, a successful MIDI note updates the waveform to the source that actually started, matching the note's velocity zones. A NoteOn without a matching zone, or one rejected by the 128-voice limit, does not change it. Multiple layers choose the first started source in zone order; telemetry reports how many layers started, and a stereo pair is one source. NoteOff does not clear the waveform. Clearing the selection re-enables MIDI-follow. Changing the displayed sample publishes only the audition source under the existing device callback lock; it does not reattach the output or reset sounding MIDI voices.

A waveform selection pins the sample, range and prepared export. Further MIDI notes keep sounding but do not replace the waveform or the export job. **Clear** and **Escape** lift the pin; Escape does not stop MIDI. Manually choosing a preset, sample or file clears the previous range and cancels its job. A generation check discards a late trigger from a bank that has already been replaced.

SF2 audition and export use the original PCM at its sample rate and channels, with no MIDI transpose, velocity gain, pan, envelope, FX or normalisation. Export writes 16-bit PCM, matching the bank data; the parser reads 16-bit PCM without the optional `sm24` chunk, so 24-bit source precision is not claimed. Waveform and export bounds use the sample's real `start`/`end`, and a stereo pair requires equal bounds and sample rate; malformed pairs are reported instead of read past the PCM. The original bank is never modified.

## Tracker modules (MOD/XM/S3M)

Tracker files are recognised from their content, not their extension: a 31-sample MOD signature, a structurally valid 15-sample MOD, an XM header or an S3M `SCRM` header. A renamed S3M under a `.mod` name opens as S3M; an unrecognised `.mod` is catalogued with an explicit error instead of an audio row. Scanning only probes headers; no module is rendered or decoded during a library scan.

Opening a module selects **Whole song** by default. **Auto Preview** starts the composition; silent session restore loads it without playback. The header shows the detected format, channel count, sample-slot count and the estimated duration from the player. There is **no song overview waveform yet**. While the whole song is selected, the waveform area shows a full-height progress/scrub bar with the current and total time in `minutes:seconds:milliseconds` (`00:14:787 / 04:47:647`); click or drag anywhere on it to seek. The first sample is never shown as a stand-in, and selecting a source sample replaces the bar with that sample's waveform. Play/Pause/Stop/seek apply to the composition. Loop follows the preview toggle; libxmp's order flow, subsongs and tempo changes are played by the engine, so the shown duration is an estimate, not a fixed BPM claim.

Selecting a sample from the selector **stops the song** and keeps its position. The waveform then shows the selected source PCM, and Play/space auditions exactly that source at its own rate. **Pause** is immediate (the preallocated ring is kept for resume but is not audible or consumed). Returning to **Whole song** resumes from the kept position; **Stop** resets the composition to the beginning even when a sample is currently selected. A selection pins the source, range and prepared WAV; changing the sample or returning to the song cancels that job. Sample slots are identified by position, so duplicate and empty names remain distinct. Empty slots, AdLib/FM instruments and slots with an unsupported variant say so instead of pretending to be silent samples.

MIDI Preview plays the **selected sample chromatically**, not the module's instrument map: 128 preallocated voices, note 60 at the sample's reference rate, 2 ms attack and a 2-second NoteOff release, one-shot to the end of the source. A tracker loop is used only when the Loop toggle was on at note-on; ordinary Play applies the same declared loop points (forward or ping-pong) while Loop is on. Ringing voices keep their own retained source, so choosing another sample does not cut them; **Stop** and AllSoundOff silence them. The existing 1.2x MIDI gain and output safety knee apply to the mixed output, never to the source PCM.

Export uses the existing background worker. A waveform selection exports the selected source range; the **Drag sample** button prepares and drags the whole source when no range is selected. The WAV carries the decoded source frames at its reference rate and channel count, with no tracker volume, MIDI transpose, velocity, pan, envelope, FX, normalisation or resampling. 8-bit MOD/S3M/XM sources are expanded to 16-bit WAV, which is the declared lossless widening policy; there is no hidden reduction of wider sources. Export file names include the container and slot number, so equal sample names do not collide.

Playback runs libxmp on a dedicated worker and fills a bounded preallocated ring (about two seconds at the device rate, at most 8 MiB). The audio callback only copies from that ring; loading, seeking, stopping and sample decoding happen on the message or worker thread. A sample-rate change restarts the player; seeking is quantised to the tracker row that contains the requested time. The whole-song path is not exposed to the audio callback as a library call, so a slow or pathological module cannot block the device.

**Coverage and limits.** MOD supports 15- and 31-sample layouts, `M.K.`, `M!K!`, `FLT4`, `FLT8`, `OCTA`/`OKTA`, `CD81`, `xCHN`, `xxCH` and `xxCN` tags, signed 8-bit PCM, finetune tuning and forward loops. A small payload shortfall (up to 4 KiB or 1% of the declared sample bytes) is clamped and reported as truncated; larger truncation is rejected. XM supports v0x0102-0x0104 headers, the standard 263-byte instrument header followed by its sample headers, XM 1.04 per-instrument sample data and the XM 1.02/1.03 instrument-first layout, 8/16-bit delta decoding, instrument-local sample lists, relative note/finetune, forward and ping-pong loops; stereo-stored samples are reported as unsupported. S3M supports sample instruments, signed/unsigned 8/16-bit PCM, C2 speed, forward loops and `SCRS` headers; AdLib instruments and packed samples are listed with a reason. MT2, IT, STM/MTM/669 and the other rare families are **not** claimed in this delivery. There is no tracker editing, pattern display, stem export, Amiga filter emulation or exact historical-player equivalence. A format can be playable while one of its sources is not extractable; the sample row says so.

Verified read-only against 48 modules of the Chicago Music Trader collection: all 48 opened, 666 source samples decoded, 8/8 sampled modules produced audible playback, and every source hash was unchanged. Two real XM modules (`DREAM.XM`, `TUESDAY.XM`) were additionally opened and decoded after the XM layout correction. This is a bounded sample, not a full-corpus listening test.

## MIDI Preview

Enable **MIDI Preview** to play the selected sample from a hardware MIDI input. **Auto Preview** independently controls automatic audition on selection; ordinary preview and MIDI voices are mixed when both are active. On first activation all currently available inputs are enabled. **Audio settings** includes input selection; use it to enable devices connected later. Changing MIDI Preview stops current playback/voices; press Play or select a different file to audition again.

- 16 voices, mono/stereo audio, note 60 at original pitch; 12 semitones per octave, velocity-sensitive.
- Attack 2 ms, release 20 ms; NoteOff and sustain pedal supported. At the voice limit new notes are ignored rather than abruptly stealing an audible voice.
- Those 16-voice/20 ms settings apply to ordinary single-file MIDI playback. SF2, EXS24, supported NKI instruments and a selected tracker sample use **128 preallocated voices and a 2-second NoteOff release**, ending earlier if a non-looping source reaches EOF. EXS/NKI one-shot zones ignore NoteOff and finish naturally. Real SF2 exclusive groups retain a separate 20 ms choke ramp, including voices already in their longer NoteOff release. Explicit Stop and AllSoundOff still silence voices immediately; overflow panic also clears ordinary-sampler sustain state.
- MIDI Preview has an additional **1.2× gain (+20%, about +1.58 dB)** before the existing master gain and output safety knee. It affects ordinary-file, SF2, EXS/NKI and REX MIDI voices only; Play/space audition, ordinary transport, velocity mapping and source-PCM WAV export are unchanged. REX applies it only to slice voices, not its internally mixed whole-loop audition. Dense chords may enter the safety knee, so their final peaks need not increase by exactly 20%.
- Linear interpolation changes speed and pitch together; this is a preview sampler, not a formant-preserving or band-limited pitch shifter. Extreme upward transpositions may alias.
- Loop and Skip Silence are captured for each new voice. A waveform selection is captured too: ordinary-file and selected tracker/disc sources start and end at the range; Loop wraps inside it. Instrument zone maps and REX slices ignore the range. Loop edges have a short fade, finite one-shots fade toward EOF. Dense MIDI chords have a soft output safety knee above 0.9; single voices have headroom.
- MIDI note events are quantised to the next device audio block; no sample-accurate DAW scheduling is claimed. Input uses a bounded 2048-event queue; overflow/contention resets voices rather than leaving stuck notes. SysEx is ignored.
- Decoded MIDI audio is limited to 128 MiB and two channels. Oversized or multichannel files produce an explicit error, never a silent truncation; ordinary streaming preview remains available.
- Sample loading and source publication occur outside the audio callback. Instrument replacement detaches the output; choosing only a displayed/audition sample uses a short device callback lock without restarting the MIDI engine. Render voices use preallocated state and no file/SQLite access. Existing JUCE transport/device-control locking remains; the whole application is not claimed formally lock-free.

Software-rendered tests cover actual samples and MIDI messages. Physical MIDI hardware, audible click checks and hot-plug behaviour still need owner acceptance on the real setup.

## EXS24 and NKI instruments

EXS24 files are read as Apple's little-endian 84-byte block format: instrument counts, zone key/velocity/root/fine-tune fields, sample start/end and loop points, and sample file references. Zone payloads of the real library are 96, 104, 108 or 136 bytes; the sample reference is read from the correct tail position for each size, and loops are enabled only by the loop-on bit in byte 33. Sample references use sample-block order, because some writers leave every block header index at zero. The sample block title is the file name; its path field is treated as a hint, because HFS absolute paths from another machine are usually stale. The reader tries the exact path, the stored relative path, suffixes of the stored path under the instrument folder and its parents, then a bounded basename search below the instrument folder. Two basename matches produce an explicit **Ambiguous sample name** error; the reader never guesses. Big-endian EXS24 blocks are reported as unsupported.

NKI is read only when it contains the zlib-compressed `K2_Container` or `NiSS_Program` XML. The supported subset maps `lowKey`/`highKey`, `lowVelocity`/`highVelocity`, `rootKey`, `zoneTune`, `sampleStart`/`sampleEnd` and the `file_ex2` or `file` sample reference, including Kontakt's path escaping and NiSS backslash paths. The NI file containers (`/\ NI FC MTD`), other binary containers and encrypted content are reported as unsupported. KSP scripts, groups, effects, crossfades, reverse zones and NKI loop points are outside this subset; a zone with loop data is played one-shot and the limitation is shown. No Kontakt compatibility beyond this XML subset is claimed.

EXS24 and NKI share the SF2 sample selector, waveform, audition, MIDI Preview and selection export. **Auto Preview** starts the first resolved sample on load for EXS24/NKI (SF2 still opens silently until a sample is chosen). EXS one-shot zones (zone flag bit 0) and single-key NKI drum-map zones ignore NoteOff and ring out to the sample end, so a short key press does not cut a kick or hit; wide-key sustained zones still release on NoteOff. A single-key NKI patch therefore behaves as a one-shot in preview. MIDI always uses the instrument's original key/velocity map; the preview header shows the selected sample's range as `MIDI 36–47`, and the transport line reports `voices N · MIDI <note> ok` or `no zone`, so an out-of-range note is visible instead of looking like a broken instrument. A note outside the map stays silent by design. EXS24 often represents a stereo sample as separate left/right sample blocks with no reliable pair link, so those are listed as two sources; SF2 stereo headers still collapse to one source. The selected source is decoded once into an immutable snapshot; the source format is preserved on export (16-bit stays 16-bit, 24/32-bit integer becomes 24-bit PCM, float becomes 32-bit float). Instruments are decoded with a 256 MiB cap and a 4096-source cap; exceeding a limit or a missing sample is shown explicitly, and a partially resolved instrument only plays its resolved zones. `.exs` and `.nki` are indexed metadata-only so they appear in the library; unsupported NKI containers carry a status instead of pretending to be playable. The originals and their samples are never modified.
