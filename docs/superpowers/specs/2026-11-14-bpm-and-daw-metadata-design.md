# Ручной BPM и метаданные при drag в DAW — ТЗ

Дата: 2026-11-14. Статус: черновик на утверждение.

## Зачем

Темп и тональность сэмпла уже определяются автоматически и видны в библиотеке, но поправить их
руками нельзя. Пользователь хочет:

- поставить BPM вручную, в том числе **настучать** его под играющий луп;
- получить BPM (и, если есть, тональность) в DAW при перетаскивании файла.

Это делает библиотеку пригодной для работы с лупами без внешних инструментов и снимает главную
боль: DAW не знает темп перетащенного сэмпла.

**Критерий успеха:** правый клик по строке → BPM → Set/Tap; значение сохраняется как ручное,
переживает повторный анализ и попадает в обучение. Перетаскивание лупа в DAW даёт файл, который
DAW видит с правильным темпом (в DAW, читающих ACID) и корневой нотой.

## Цели

- Ручной BPM: меню, ввод числа, tap-темпо, снятие ручного значения; пачкой на всё выделение.
- Tap: мышью и **Space**, с запуском лупа из диалога (для одиночной строки).
- Ручной BPM — источник истины для отображения, фильтров, сортировки и contribution.
- Drag в DAW: WAV-копия в кэше с чанками `acid` (темп, корень, размер) и `smpl` (корень). Не-WAV
  форматы конвертируются в WAV, если BPM или тональность известны.
- Всё с тестами, без новых зависимостей.

## Не цели

- Ручная правка тональности, типа, структуры — отдельный этап. Key только читается для метаданных.
- Редактирование BPM внутри аудио (варп, тайм-стретч) и «подгонка» длины лупа под темп.
- Автоматическое определение темпа по выделению.
- Конвертация REX2 в WAV для drag — REX в этом этапе отдаётся как сейчас.
- Синхронизация с DAW по сети, плагин-версия.

## Анти-цели (провал, даже если «работает»)

- Ручной BPM затирается повторным анализом или исчезает после перезапуска.
- Ручной BPM не попадает в contribution, хотя человек его поправил.
- Tap считает мусор: один случайный промах ломает результат, или значение «прыгает» после каждого тапа.
- Drag изменяет оригиналы в библиотеке.
- Копия в кэше перезаписывается при каждом drag или растёт без переиспользования.
- Space в диалоге запускает воспроизведение вместо тапа.

## Что уже есть (опора)

- `smart_overrides` (`SmartField::Bpm`, `SmartOverride.numericValue`) и отображение «(manual)» в
  списке. UI для BPM отсутствует.
- `SampleRepository::setSmartOverride` / `clearSmartOverride` / `smartDisplays` / `smartOverrides`.
- `contributionRecords` берёт темп только из `smart_results` — это надо расширить.
- `core/smart/WavMetadata` читает `acid`: root в смещении 4, beats в 12, метр в 16/18, tempo float
  в 20.
- JUCE пишет `acid` из metadata-ключей `acid tempo`, `acid beats`, `acid root set`,
  `acid root note`, `acid numerator`, `acid denominator`; `smpl` — из `MidiUnityNote`,
  `NumSampleLoops`, `Loop0Start/End/Type`. На little-endian `acid tempo` — обычное число (`String(bpm)`).
- `ExternalFileDrag::materialiseForDrag` уже делает кэш-копии WAV для EBL и переиспользует их по
  хэшу пути; `dragCacheFolder()`.

## Подходы

**BPM, интерфейс.**

- **A. Диалог tap-темпо + пункты меню** (выбран). Отдельное окно с большой кнопкой, Space, Return,
  Esc, кнопкой запуска лупа. Предсказуемо, легко тестируется, не конфликтует с пробелом плеера.
- B. Тап прямо по ячейке BPM. Скрыто, конфликтует с выделением строк, плохо для пачки.
- C. Глобальная горячая клавиша без диалога. Space уже занят плеером, состояние непонятно.

**DAW-метаданные.**

- **A. WAV-копия в кэше с чанками** (выбран). Оригинал не трогается, кэш переиспользуется, темп
  виден DAW, которая читает ACID/smpl.
- B. Отдавать оригинал и писать sidecar (`.asd` и т.п.) — зависит от DAW, хрупко.
- C. Менять оригинал при drag — недопустимо.

## Решения, принятые с владельцем

- Пачка: Set/Tap/Clear применяются ко всем выделенным строкам.
- Space в диалоге — тап. Return — применить, Esc — отмена.
- Не-WAV форматы при известном BPM/Key конвертируются в WAV для drag.
- «Clear manual BPM» снимает только темп; тональность не трогает.
- Ручной BPM важнее машинного и уходит в contribution.

## Как это работает

### Меню BPM

В контекстном меню строки — подменю `BPM`:

```
Set BPM…
Tap BPM…            (Space в диалоге)
Clear manual BPM
```

- `Set BPM…` — themed-ввод, 20…300, принимает `128` и `128.5`; запись override на все выделенные.
- `Clear manual BPM` — снимает override у всех выделенных; неактивно, если ни у кого нет ручного.
- Пункты активны, если есть хотя бы одна строка (для Set/Tap), и файл доступен.

### Tap BPM

Отдельное окно (`ui/library/TapTempoDialog`):

- Заголовок: имя файла (или «N samples»).
- Большая кнопка `Tap`, крупное текущее значение BPM (`—`, пока меньше двух тапов).
- `Start loop` / `Stop`: включает Loop и запускает **выделение**, если оно есть, иначе файл целиком.
  Повторное нажатие останавливает. Если превью занято другим источником — только тап без звука.
- `Apply` (Return) — пишет значение всем выделенным; `Cancel` (Esc) — ничего.
- Space нажимает Tap, не запуская воспроизведение. Пробел работает, пока окно в фокусе.
- Счёт: последние 8 интервалов; интервалы, отличающиеся от медианы больше чем на 25 %, отбрасываются;
  BPM = 60000 / среднее. Первое значение появляется после **трёх тапов** (два валидных интервала):
  до этого показывается «—» и `Apply` неактивен. Пауза 3 с — сброс.
- `Start loop` активен только при одной выделенной строке: для пачки превью не загружает аудио, и
  тапают без звука. «Выделение» — это диапазон на волне; если его нет, играет файл целиком.
- Значение округляется до 0.1, при записи — то же; список показывает целое, если близко к целому.

### Хранение и отображение

- Override: `setSmartOverride(id, SmartField::Bpm, { numericValue = bpm })`; снятие —
  `clearSmartOverride`.
- `smartDisplays` уже показывает override; после записи список обновляется, в колонке BPM —
  значение с «(manual)», сортировка и фильтры используют его.
- `touchFeedback(ids)` — чтобы contribution переслал изменённые строки.

### Contribution

`contributionRecords` должен брать темп из override, если он есть:

```sql
COALESCE((SELECT o.numeric_value FROM smart_overrides o
          WHERE o.sample_id=f.sample_id AND o.field='bpm'
            AND o.cleared=0 AND o.not_applicable=0 AND o.numeric_value>0), r.bpm)
```

`has_bpm` — истина, если итоговое значение > 0. Это единственное изменение обучения в этапе.

Границы: ручной BPM попадает в contribution только если у строки **уже есть** запись фидбэка
(теги или подтверждённый тип). Сэмпл без типа и тегов, как и раньше, не отправляется: BPM сам по
себе не обучающая метка, а `ContributionPayload::buildBatch` такие записи отбрасывает. Новых
записей фидбэка при выставлении BPM не создаём и признаки не пересчитываем. `Clear manual BPM`
тоже вызывает `touchFeedback`, если запись есть, — строка вернётся к машинному темпу и перешлётся.

### Drag в DAW с метаданными

- Источник данных: `SmartDisplay` выбранных строк (BPM, `hasBpm`, key). Если BPM ручной — он уже в
  `SmartDisplay.bpm`.
- Тональность → корневая нота: первая нота из `key` (`C`, `F#`, `A minor`), MIDI = 60 + полутон от C.
  Если тональности нет — корень не пишется.
- Условие материализации: BPM или тональность известны **и** это не сомнительное значение:
  берём только `Resolved` или ручной override. `Conflicting`, `Ambiguous`, `Unknown`, `Stale` в DAW
  не пишем — иначе туда уедет догадка.
- Формат: WAV.
  - WAV-оригинал **копируется побайтно** (без перекодирования: сохраняются RF64, неизвестные чанки,
    разрядность и существующий `smpl`), затем в копию вставляются/заменяются нужные чанки.
  - AIFF/MP3/OGG и другие читаемые форматы декодируются через `AudioFormatManager`
    (`registerSonicatorFormats`) и пишутся WAV: 32-битный float остаётся float, иначе 24 бита;
    частота и каналы сохраняются.
- Чанки пишутся вручную на уровне RIFF, без JUCE-metadata: JUCE всегда добавляет `smpl` с корнем
  C4, если есть любые метаданные, а нам нужен `acid` без выдуманного корня.
  - Известен BPM → `acid` (24 байта): flags, root, beats = round(длительность_сек × BPM / 60),
    meter 4/4, tempo float 20-го смещения. Существующий `acid` заменяется, а не дублируется.
  - Известна тональность → `MidiUnityNote`/`smpl` с корнем, если `smpl` уже был — заменяется корень,
    луп сохраняется; если `smpl` не было, добавляется короткий `smpl` только с корнем.
  - BPM без тональности → только `acid`. Тональность без BPM → только `smpl`, `acid` не пишется.
  - Корень из исходного `smpl` при неизвестной тональности сохраняется как был.
- Кэш: `dragCacheFolder()/<hash>/<stem>.wav`, hash = SHA-256 от `path | mtime | размер | bpm | key |
  root`; подпапка на хэш разводит одинаковые имена, а DAW видит привычное `<stem>.wav`.
  Существующий файл переиспользуется, если не старше источника.
- Суффикс с BPM/Key в имени не добавляем. *(Моё решение: если ваша DAW не читает ACID, добавим
  суффикс отдельным маленьким этапом.)*
- Стерео-пара: скрытый партнёр получает те же темп и корень, что и видимая строка (это тот же звук),
  но своим путём и своим кэшем.
- Проблемы (не декодируется, нет места) — в строку статуса, остальные файлы выделения всё равно
  уходят.
- REX2, EBL и disc-сэмплы в этом этапе проходят как раньше, без метаданных.

## Устройство (для исполнителя)

- `core/smart/TapTempo.{h,cpp}` — чистый счётчик: `void tap(int64_t timeMs)`, `double bpm() const`,
  `void reset()`, `bool hasValue() const`, `int tapCount() const`.
- `core/export/DragMetadata.{h,cpp}` —
  `struct DragMetadata { bool hasBpm; double bpm; bool hasRoot; int rootMidi; }`,
  `juce::File materialiseWithMetadata(const juce::File& source, DragMetadata, const juce::File& cacheDir,
  juce::String& error)` и небольшая RIFF-утилита `insertOrReplaceChunk(file, id, payload)` /
  `removeChunk(file, id)` с тестами на сохранность остальных байтов и на замену существующего чанка.
- `core/smart/KeyNames.h` — helper `int rootMidiFromKey(const juce::String& key)` (C4 = 60).
- `ui/library/TapTempoDialog.{h,cpp}` — окно; колбэки `onStartLoop`, `onStopLoop`,
  `std::function<void(double)> onApply`.
- `FileListPanel`: прокинуть `smartDisplays` и id в drag (уже есть оба); кэш-материализация вместо
  простой передачи путей.
- `MainComponent`: пункты меню BPM, вызов диалогов, запись override, `touchFeedback`, обновление
  списка после записи.

## Тесты

- TapTempo: 120 BPM из интервалов 500 мс; джиттер ±3 %; один выброс (1100 мс) отброшен; сброс после
  3 с; значения нет до трёх тапов, после третьего — есть.
- BPM override: `smartDisplays` показывает значение и `bpmOverride == Value`; после
  `clearSmartOverride` — машинное; `contributionRecords` возвращает ручной BPM, а после
  `touchFeedback` — новую `updatedAt`.
- `rootMidiFromKey`: `C` → 60, `F#` → 66, `A minor` → 69, пусто → -1.
- Drag metadata: AIFF → WAV с `acid`/`smpl`, наш `WavMetadata` читает тот же темп и корень; WAV без
  метаданных отдаётся как есть (путь не меняется); WAV с BPM материализуется, чанки на месте,
  побайтовое содержимое PCM не меняется; существующий `acid` заменяется (чанк один); BPM без
  тональности не добавляет `smpl`; тональность без BPM не добавляет `acid`; повторный вызов
  переиспользует файл (mtime не изменился); оригинал не изменён.
- Диалог: Space вызывает тап (вызвать `keyPressed` напрямую), Return применяет, Esc закрывает без
  применения.
- Все тесты — только во временных папках; живой каталог и `settings.json` не трогать.

## Оценка

Для одного разработчика, знакомого с кодом:

| Часть | Оценка |
|---|---|
| `TapTempo` + тесты | 0,5 дня |
| Override BPM: SQL contribution, `touchFeedback`, тесты | 0,5 дня |
| Меню BPM, Set/Clear, пачка, обновление списка | 0,5 дня |
| Диалог Tap (Space, луп, Apply/Esc) + тесты | 1 день |
| Drag metadata: RIFF-чанки, конвертация форматов, кэш, тесты | 1,5 дня |
| Документация, прогон, ручная проверка в DAW | 0,5 дня |
| **Итого** | **~4,5 рабочих дня** |

Риски: приём `acid` зависит от DAW (Reaper/Bitwig/Cubase читают, Ableton/Logic — по-разному);
проверка на вашей DAW — обязательная часть приёмки. Конвертация MP3/OGG в WAV добавляет декодирование
в drag, на больших файлах первый drag будет заметно медленнее.

Если считать в этой сессии: около 3 часов работы агента с учётом сборок, плюс ваша ручная проверка
drag в DAW.
