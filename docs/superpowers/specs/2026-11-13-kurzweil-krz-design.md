# ТЗ: банки Kurzweil K2000 (`.krz`) — игра с MIDI и Extract, как у SF2

Дата: 2026-11-13. Статус: утверждено пользователем 2026-11-13.
План: `docs/superpowers/plans/2026-11-13-kurzweil-krz.md`.
При реализации этот файл копируется в `docs/superpowers/specs/2026-11-13-kurzweil-krz-design.md`.

## Зачем

Бэклог (`Sonicator Features.md`, строка 19): после samplerdisc научиться читать и экспортировать
банки Kurzweil `/Volumes/1TBSSD/samples/_Kurzweil/Kurzweil K2000 KRZ` — те, в которых есть
встроенные сэмплы, а не только пресеты под заводскую ROM. Цель — чтобы звуки K2000 стали
рабочим материалом библиотеки так же, как банки SoundFont: банк виден в списке, играет
программами с MIDI, а его сэмплы извлекаются в WAV и попадают в библиотеку.

samplerdisc `.krz` не читает (см. `2026-11-12-emu-ebl-design.md`, «Не входит»), поэтому
эталона для побайтной сверки нет.

## Корпус пользователя

- 238 файлов `.krz` в одной папке. 234 с магией `PRAM`, 4 с `SROM`.
- 205 содержат PCM (`osize < размер файла`), 33 — только объекты (пресеты под ROM).
- 23 файла — части многодисковых наборов `имя.kr1.krz`, `имя.kr2.krz`. Объекты лежат целиком
  в первой части; PCM начинается в первой и продолжается во второй (у `basvoice.kr1` заявлено
  ~1,77 МБ PCM при меньшем остатке файла).
- Рядом лежат `Kurzweil K2000 ROM`, `Kurzweil Kit 01…08` (WAV) — это обычные WAV, к задаче
  не относятся.

## Формат (источники — спецификация, код не копируется)

- Geoffrey Mayer, «KurzFile» (файлы `*-Keymap.txt`, `*-Sample Header.txt` и др.).
- hed0rah, «krz anatomy»: https://hed0rah.github.io/audio_files_anatomy/krz-anatomy.html
- Chicken Systems: `.krz`, `.k25`, `.k26` устроены одинаково.

Кратко:

- **Заголовок 32 байта, big-endian.** `0x00` магия `PRAM` (или `SROM`), `0x04` `osize` —
  абсолютное смещение начала PCM и одновременно конец секции объектов. `osize == размер файла`
  — банк без сэмплов.
- **Объекты с `0x20`:** блоки, каждый начинается с отрицательной длины блока (int32); `0` —
  конец секции. В блоке один или несколько объектов (старые файлы и SROM — все в одном блоке).
  Заголовок объекта: `type/id` (u16), длина объекта (u16), смещение к данным (u16), имя ASCII
  с нулём и выравниванием. Тип = `hash >> 10`, id = `hash & 0x3FF`: 36 программа, 37 кеймап,
  38 сэмпл. Прочие типы пропускаются.
- **Сэмпл (sample header):** Sound Block 12 байт (число sound file headers, флаг стерео), затем
  32-байтные Sound File Headers: корневая клавиша, флаги (бит `0x80` — петля **выключена**,
  режим воспроизведения normal/reverse/bidirectional, RAM/ROM), громкость, начало/альт. начало/
  петля/конец в **словах** от начала PCM, частота. Мультисэмпл — несколько headers в одном
  объекте, к ним обращаются по sub-sample number из кеймапа.
- **Частота:** источники расходятся (у hed0rah — период в нс, `rate = 1e9/period`; у Mayer —
  Гц × 1000). Правильную трактовку исполнитель выбирает по корпусу (критерий ниже).
- **Кеймап:** заголовок 28 байт: `method`, `cents per entry`, число записей − 1, `entry size`,
  восемь смещений на уровни скорости ppp…fff. Запись ключа по `method` (1…6 байт): тюнинг
  (1 или 2 байта), громкость, номер сэмпла, sub-sample. **Ширина записи берётся из
  `entry size`**, не угадывается. Первая запись — C0; если записей меньше 128, последняя
  распространяется до верха.
- **Программа:** слои (обычно до 3) с диапазоном клавиш и скоростей и ссылкой на кеймап
  (вторым кеймапом в слое может быть правый канал стерео). Остальное — VAST (DSP-цепочки,
  огибающие, LFO) — не интерпретируется.
- **PCM:** signed 16-bit **big-endian**, общий блок от `osize`. Адрес сэмпла: `osize + слово × 2`.
- **Части `.krN`:** у второй и следующих частей заголовок, по `0x20` заведомо неверная длина
  блока, PCM с `0x24` — продолжение PCM предыдущей части.

## Цели

1. **Парсер `KrzBank` на C++** (`core/kurzweil/`). Ограниченный, только на чтение: каждое
   смещение и длина проверяются по размеру файла, повреждённый файл отклоняется с понятной
   причиной, без падений и чтений за границей. Многочастные наборы склеиваются: открытие
   `x.kr1.krz` подтягивает `x.kr2.krz`, `x.kr3.krz`… из той же папки; отсутствующая часть —
   ошибка с именем файла.
2. **Модель — существующий `FileInstrument` (`core/sampler/`).** KRZ играет через тот же
   `FileInstrument` + `ExternalKitSampler`, что EXS24 и NKI (`AudioEngine::externalMode`).
   `Sf2Bank` и `Sf2KitSampler` **не меняются**. В `FileInstrument` добавляется то, чего ему
   не хватает: список программ банка (имя, номер) и выбор текущей; для EXS/NKI это одна
   программа, их поведение не меняется. Перевод KRZ → модель:
   - программа K2000 = программа инструмента;
   - источник (`sources`/`audio`) = объект-сэмпл с декодированным PCM (16-bit BE → float),
     со своей частотой; мультисэмпл и стерео — один источник на sub-sample / канал;
   - зона = ключ (или диапазон соседних ключей с одинаковой записью) кеймапа слоя,
     пересечённый с диапазоном клавиш и скоростей слоя и уровнем скорости кеймапа;
     `start/end/loopStart/loopEnd` — кадры внутри источника;
   - `rootKey` из Sound File Header, `tuningCents` из записи кеймапа, `attenuationDb` из
     громкости кеймапа и сэмпла, `looping` из флага петли;
   - стерео: каналы — две зоны с одинаковым диапазоном и `pan` −1 / +1. Это покрывает и
     стерео-флаг Sound Block, и слой с двумя кеймапами (левый/правый), без поля связки
     в источнике.
3. **Игра с MIDI как у SF2.** Клик по строке `.krz` открывает банк в превью: первая программа
   с играбельными зонами, переключатель программ в панели превью (как у SF2), MIDI-превью
   включается, монитор нот работает. Звучит «кеймап без VAST»: без фильтров, огибающих
   программы, эффектов.
4. **Extract.** «Extract samples…» в контекстном меню и drag&drop работают для `.krz`
   так же, как для SF2: `<имя банка> samples/001 Имя.wav`, затем скан и smart-анализ папки
   результата. Извлекаются все объекты-сэмплы с PCM, в том числе те, на которые не ссылается
   ни одна программа; мультисэмпл — по файлу на sub-sample. Стерео-флаг Sound Block даёт
   один стерео WAV; два моно-сэмпла, спаренные только слоем программы, извлекаются двумя
   файлами (пара — свойство программы, не сэмпла). Для KRZ в WAV пишется `smpl` с корневой
   нотой и петлёй: корень и петля протягиваются через `EmbeddedSampleSet` в экспорт. Для
   SF2 и трекеров вывод Extract не меняется (`smpl` у них сейчас нет — это отдельная задача).
5. **Каталог.** `.krz`/`.k25`/`.k26` — metadata-only формат, как `.sf2`: строка с форматом
   `KRZ`, размером, без анализа PCM при скане. Части `.kr2.krz` и далее в списке не
   показываются (как `.bin`, закрытый своим `.cue`); строка — первая часть.
6. **Банки без сэмплов.** Строка есть, но при открытии превью пишет «Банк ссылается на
   заводские сэмплы K2000, своих сэмплов в файле нет»; Extract для таких строк недоступен
   или даёт отчёт «0 сэмплов, причина…». `SROM`-файлы — то же самое, если в них нет PCM.
7. **Документация и авторство.** `docs/KURZWEIL_KRZ.md` (формат, решения, итоги прогона
   корпуса), запись в `THIRD_PARTY_NOTICES.md` об источниках спецификации, отметка в бэклоге.

## Не входит в этап

- VAST: DSP-алгоритмы, фильтры, огибающие и LFO программ, эффекты KDFX, сетапы, песни.
- Reverse и bidirectional воспроизведение: играются вперёд, режим только сохраняется в модели
  (в Extract не влияет).
- Заводская ROM K2000: сэмплы, на которые ссылаются ROM-кеймапы, не эмулируются, такие зоны
  молчат и пропускаются.
- Сэмплы KRZ отдельными строками в каталоге (модель «как образ Akai») — пользователь выбрал
  модель SF2.
- Образы дисков Kurzweil KMSI.
- Запись `.krz`.
- Дампы заводской ROM K2000: они защищены авторским правом Kurzweil и не лицензированы,
  ни в сборку, ни в тесты не берутся. Возможная будущая настройка «папка ROM пользователя»
  не входит в этап.

## Анти-цели

- Изменение исходных файлов.
- Регресс SF2, EXS24, NKI: существующие тесты и поведение превью остаются как были.
- Угадывание раскладки записи кеймапа вместо `entry size`.
- Падение, зависание или чтение за границами файла на любом файле корпуса и на испорченных
  данных.
- Тишина без объяснения: банк открылся, а программа молчит — это видно как ошибка/сообщение.

## Критерии приёмки

1. Юнит-тесты на синтетических `.krz`: моно с петлёй и без; стерео; мультисэмпл; кеймапы с
   методами `0x03`, `0x13`, `0x0F`; несколько уровней скорости; программа с двумя слоями;
   многочастный набор `.kr1/.kr2`; банк без PCM; отказы — не `PRAM/SROM`, `osize` за файлом,
   блок за файлом, сэмпл за пределами PCM, нулевая длина блока раньше объектов.
2. Регресс: существующие тесты SF2, EXS24/NKI (`FileInstrument`, `ExternalKitSampler`)
   и превью зелёные без правок ожиданий.
3. Сэмплер на синтетическом KRZ: нота в зоне звучит с правильной частотой воспроизведения
   (отношение к корню), нота вне диапазона слоя — тишина, петля держится до note-off.
4. Extract на синтетическом банке: ожидаемое число WAV, PCM совпадает с декодером, стерео
   одним файлом, `smpl` с корнем и петлёй.
5. Opt-in `[.krz-corpus]` (`SONICATOR_KRZ_DIR`): **все** 238 файлов открываются или
   отклоняются с причиной; у 205 банков с PCM — хотя бы одна играбельная программа или
   объяснение; все адреса сэмплов в пределах PCM; все частоты в диапазоне 8–96 кГц
   (по этому же прогону выбирается трактовка поля частоты). Необъяснённых отказов 0;
   иначе стоп-условие.
6. Opt-in `[.krz-factory]` (`SONICATOR_KRZ_FACTORY_DIR`): официальные архивы Kurzweil со
   страницы K2000 (K2FACT, K2TOK2VP, K2VXTOK2, K26PRGSU, K2KFARM, OPRGSDEM, CPRGSDEM,
   K2VXFARM, VXDEMOS1, VXDEMOS2, K2KGM3, K2KGMA2, K2KGMF1), распакованные в
   `/Volumes/1TBSSD/samples/_Kurzweil/Factory`. Каждый файл открывается или отклоняется
   с причиной; банки только с ROM-ссылками дают сообщение про заводские сэмплы, а не
   ошибку разбора. Архивы в репозиторий не кладутся.
7. Полный `ctest` зелёный. Вручную пользователем: 5 банков разного типа (`acguit`,
   `b3`, `akaifunk`, `basvoice.kr1`, `chorus`) играют с MIDI на правильной высоте, Extract
   даёт WAV, которые звучат так же.

## Стоп-условия (вернуться к пользователю)

- Файлы корпуса, которые не удаётся разобрать по описанию формата.
- Ни одна трактовка частоты не даёт правдоподобных значений для всего корпуса.
- Список программ в `FileInstrument` требует менять ожидания существующих EXS/NKI-тестов.

## Подходы

- **A. KRZ → общая модель, общий сэмплер (выбран пользователем).** Уточнено после
  проверки: общая модель уже есть — `FileInstrument` + `ExternalKitSampler` (EXS24, NKI),
  её зоны хранят границы и петли внутри источника, что совпадает с устройством K2000.
  Пользователь выбрал её вместо выноса модели из `Sf2Bank`: SF2 не трогается, новый —
  парсер и список программ.
- A′. Вынести модель из `Sf2Bank` и играть через `Sf2KitSampler` (исходная формулировка).
  Отклонено: в коде остались бы два общих сэмплера и появился бы риск для SF2.
- B. Отдельный `KrzKitSampler`. Дублирует движок голосов, особенностей K2000 без VAST
  для него почти нет.
- C. Конвертация KRZ в SF2 в памяти. Лишний сериализатор, тяжёлая отладка; Extract всё
  равно требует прямого доступа к сэмплам.

## Решения исполнителя (мои, если не поправите)

- Папка кода `core/kurzweil/`; перевод в `FileInstrument` — там же.
- Восемь уровней скорости кеймапа (ppp…fff) делят MIDI-скорость 1–127 поровну
  (по 16, последний до 127). Таблицы скорости K2000 не эмулируются.
- Неполный многочастный набор (нет `.kr2`): объекты читаются, источники, чей PCM целиком
  есть в доступных частях, играют и извлекаются, остальные пропускаются с предупреждением
  (`FileInstrument::partial` + `warnings`, в Extract — «пропущено: нет части x.kr2.krz»).
  В прогоне корпуса это объяснённый случай.
- Поддерживаем расширения `.krz`, `.k25`, `.k26`; в корпусе только `.krz`.
- Если в банке нет программ, но есть кеймапы — пресетом становится каждый кеймап; если нет
  и кеймапов — каждый сэмпл на всю клавиатуру от своего корня.
- Программа без единой играбельной зоны в списке пресетов не показывается.
- Порядок Extract — порядок объектов-сэмплов в файле, имя WAV — имя объекта (для
  мультисэмпла — с номером sub-sample).
