# ТЗ: сэмплы Akai S3000 с образов BIN/CUE (диски Robert Miles)

Дата: 2026-11-12. Статус: черновик на утверждение.
После утверждения переносится в `docs/superpowers/specs/2026-11-12-akai-s3000-bincue-design.md`.

## Зачем

Sonicator уже читает образы Akai S1000/S3000, но звук декодируется только в одном проверенном
варианте: заголовок сэмпла 150 байт (образ Real Mega Rhythm). Остальные варианты сознательно
отклоняются. На реальных дисках S3000 заголовок другой, поэтому их сэмплы нельзя прослушать
или экспортировать. Цель этапа: сэмплы с двух дисков Robert Miles
(`/Volumes/1TBSSD/samples/_RobertMiles/TZRMRM1AK.cue`, `TZRMRM2AK.cue`) слушаются, попадают
в каталог и экспортируются в WAV. Корректность звука подтверждается побайтовой сверкой
с независимым конвертером.

## Что уже работает (не трогаем без нужды)

- BIN/CUE MODE1/2352: `CueSheet` → `cueTrackLayout` → `makeTrackSource` → `BlockByteSource`
  (`core/disc/DiscBrowserService.cpp:272-350`). Для `.bin` ищется соседний `.cue`.
- Разбор Akai: таблица разделов `0x4500`, том `+0xca`, FAT `+0x70a`, FAT в big- или little-endian,
  цепочки, склейка L/R (`core/disc/AkaiFilesystem.cpp`).
- Каталог: `indexDiscContents` создаёт для Akai-сэмплов строки только по метаданным
  (`core/disc/DiscContentIndexer.cpp`). Прослушивание идёт через `DiscBrowserService::previewEntry`.
- Экспорт исходных кадров без обработки: 16-бит в 16-бит.

## Проверенные факты об образах (только чтение, 2026-11-12)

- CUE: `FILE "TZRMRMnAK.BIN" BINARY / TRACK 01 MODE1/2352 / INDEX 01 00:00:00`.
- Таблица разделов в user data на `0x4500`: 9 разделов (8 × 7680 + 4095 = 65 535 блоков ≤ 69 798
  блоков образа). Тома типа 3 (S3000), например `GRAN PIANO 1`. Маркеры FAT `00 40` × 3
  (big-endian). Значит, проба и открытие файловой системы по существующим правилам проходят.
- Заголовок сэмпла S3000:
  - `0x00` id = 3;
  - `0x02` корневая нота (60);
  - `0x1a` кадров, u32 LE;
  - `0x1e` start, u32 LE;
  - `0x22` end, u32 LE;
  - `0x8a` частота, u16 LE (44 100).
  - **Длина заголовка 192 байта**: `declaredBytes = 192 + 2 × frames`. Проверено на двух сэмплах:
    150 720 = 192 + 2 × 75 264 и 77 888 = 192 + 2 × 38 848.
  - Число 190 из прежней документации на данных не подтверждается.
- PCM: signed 16-bit LE моно, начинается сразу после 192-байтного заголовка.
- Независимая сверка: `Converted/808 CLAPS.wav` (моно, 16 бит, 44 100 Гц, 38 751 кадр) совпадает
  с кадрами диска `[start=40, start+38 750)` байт в байт. Последний кадр WAV обнулён конвертером.
  Кадр диска с индексом `end`=38 790 в WAV не попал. В WAV есть чанк `smpl` с корневой нотой 60.
  Вывод: `Converted` — это вывод стороннего конвертера, обрезанный по start/end. Он годится
  как эталон для диапазона `[start, end)`.
- `Converted`: около 1 600 WAV в корне и 421 в `Loops`. Имена соответствуют Akai-именам; бывают
  ведущие пробелы, например `"     COW 1.wav"`. Одинаковые имена на разных томах не исключены.

## Цели

1. **G1. Декодер S3000.** `decodeAkaiSample` принимает заголовок длиной 150 или 192 байта.
   Длина выбирается по точному равенству `L + 2 × frames == declaredBytes`; оба варианта
   одновременно совпасть не могут. Любая другая длина, включая 190, отклоняется со статусом
   `unsupported` и текстом `unverified`, как сейчас. Данные читаются с позиции `L`.
2. **G2. Поля заголовка.** Отдельная функция разбора возвращает id, длину заголовка, кадры,
   частоту, корневую ноту, start и end. Ею пользуются декодер и эталонный тест.
3. **G3. Диски Robert Miles открываются целиком.**
   - Через `.cue` и через `.bin` с соседним `.cue`.
   - Список разделов, томов и записей строится; все записи-сэмплы декодируются без ошибок.
   - Прослушивание, MIDI и экспорт WAV работают в приложении.
4. **G4. Каталог.** `indexDiscContents` по обоим `.cue` создаёт строки Akai-сэмплов. Проверяется
   на временной базе.
5. **G5. Эталонная сверка.** Opt-in тест сравнивает декодированные кадры с WAV из `Converted`.
6. **G6. Обобщённый тест реального образа.**
   - Принимает `.cue`.
   - Ожидаемые числа задаются через переменные окружения, а не зашиты под Real Mega Rhythm.
   - Образ не меняется: размер, mtime и SHA-256 сохраняются.
7. **G7. Документация.** `docs/DISC_IMAGES.md` обновлён: вариант 192, отказ от 190, результаты
   сверки, диски Robert Miles.

## Не входит в этап

- Программы и кейгруппы как играемый инструмент.
- Обрезка по start/end и лупы при прослушивании и экспорте. **Моё решение:** отдаются все кадры
  сэмпла, как того требует действующая политика «export is the source frames only». Start и end
  нужны только для сверки.
- Корневая нота, лупы и длительность в строках каталога. Для ноты и лупов в `SampleRecord` нет
  полей, а строки диска остаются `metadataOnlyVersion`. Это отдельный шаг.
- Другие сэмплеры (E-MU, Roland и т. п.), образы дискет, BIN без CUE.

## Анти-цели (провал, даже если «работает»)

- Любая запись в образ или в `Converted`.
- Угадывание длины заголовка: всё, кроме 150/192 с точным равенством, отклоняется.
- Регресс уже поддержанного варианта на 150 байт.
- Изменение пользовательского `~/Library/Sonicator/sonicator.sqlite` тестами: каталог
  проверяется только на временной базе.

## Критерии приёмки

1. Юнит-тесты `[disc-akai-pcm]`:
   - 150 и 192 декодируются, данные начинаются с `L`;
   - 190 отклоняется;
   - поля заголовка разбираются;
   - заголовок с id 3 длиной 192, у которого число кадров не сходится, отклоняется.
2. `[.disc-corpus]` на `TZRMRM1AK.cue` и `TZRMRM2AK.cue`:
   - `probe == akaiRaw`;
   - 0 ошибок декодирования среди всех записей-сэмплов (по отдельности, включая правые
     половины пар);
   - у каждой декодированной записи частота в диапазоне 8000–96000, значения конечны, пик > 0
     хотя бы у 95 % записей (тишина на дисках встречается);
   - `indexDiscContents` на временной базе даёт `imagesIndexed == 1` и `entries > 0`;
   - образ не изменён.
3. `[.disc-reference]` на обоих дисках против `Converted` (включая `Loops`):
   - для каждой пары «запись диска ↔ WAV» с уникальным на обеих сторонах именем
     (без учёта регистра и пробелов по краям) кадры `[start, end)` совпадают с первыми
     `end − start` кадрами WAV **байт в байт**;
   - **несовпадений 0**;
   - тест печатает: сколько пар сравнено, сколько WAV без пары, сколько неоднозначных имён,
     у скольких длина отличается от `end − start + 1`. Сравнено должно быть не меньше 500 пар.
     Если меньше, сначала разобраться с сопоставлением имён, а не снижать порог.
4. Ручная проверка в собранном приложении:
   - открыть `TZRMRM1AK.cue`, прослушать 3 сэмпла, один из них стерео-пару;
   - экспортировать один сэмпл в WAV;
   - экспортированный файл совпадает с данными диска (полная длина) и содержит эталонный
     фрагмент из `Converted`.
5. Полный `ctest` зелёный. Скрытый тест `[.disc-corpus]` на Real Mega Rhythm проходит с прежними
   числами, если образ найден. Если не найден, это явно указывается в отчёте.

## Стоп-условия (вернуться к пользователю)

- Встретился сэмпл с длиной заголовка, отличной от 150 и 192, или с другим id.
- Есть хотя бы одно несовпадение байтов в эталонной сверке.
- Конвертер, судя по данным, менял сами значения PCM (нормализация, дизеринг), а не только
  обрезал.
