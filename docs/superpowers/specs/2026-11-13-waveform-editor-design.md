# Быстрый редактор волны в окне предпросмотра — ТЗ

Дата: 2026-11-13. Статус: черновик на утверждение.

## Зачем

Владелец хочет **быстро поправить файлы своей библиотеки**, не уходя во внешний редактор: отрезать
лишнее, развернуть, сделать фейды, нормализовать, свести в моно — и сохранить. Окно предпросмотра
(`PreviewPanel` + `WaveformDisplay`) уже показывает волну и умеет выделять регион; его надо
расширить до простого редактора.

Критерий успеха: правый клик по волне → операция → результат сразу видно и слышно → Cmd/Ctrl+S →
«Overwrite» или «Save copy» → каталог знает о новом содержимом файла.

## Цели

- Контекстное меню по правому клику на волне с операциями (список ниже).
- Правки в памяти, с Undo/Redo, без записи на диск до сохранения.
- Cmd/Ctrl+S → диалог `Overwrite` / `Save copy` / `Cancel`.
- После сохранения каталог обновлён: перезаписанный файл переанализирован, копия добавлена.
- Несохранённые правки не теряются молча (диалог при уходе с файла и при выходе).

## Не цели

- Многодорожечный/мультиклип монтаж, рисование карандашом, кроссфейды между
  файлами, плагины эффектов, пакетная обработка многих файлов.
- Ресэмплинг, смена разрядности/частоты, тайм-стретч, питч-шифт.
- Редактирование карт инструментов (SF2/EXS/NKI-зоны, REX-слайсы, трекерные паттерны).

## Анти-цели (провал, даже если «работает»)

- Испорченный или наполовину записанный оригинал при сбое записи.
- Тихая потеря несохранённых правок при переходе к другому сэмплу.
- Тихая запись на диск без явного Cmd+S/подтверждения.
- Потеря у перезаписанного файла пользовательских тегов/оценок/фидбэка в каталоге.
- Подвисания UI на длинных файлах при каждой операции.

## Подходы (рассмотрены)

- **A. Правка буфера в памяти + сохранение по Cmd+S** — **выбран**. Файл декодируется в буфер,
  операции меняют буфер, есть Undo/Redo, волна и звук идут из буфера; Cmd+S пишет файл. Единственный
  вариант, который естественно даёт и Undo, и запрошенный диалог сохранения.
- B. Каждая операция сразу пишет в файл (Undo через резервную копию). Отвергнут: Cmd+S теряет смысл,
  каждое действие — запись и переиндексация.
- C. Неразрушающий список правок с пересчётом. Отвергнут: избыточно для быстрой правки.

## Что редактируется

| Источник | Правка | Overwrite | Save copy |
|---|---|---|---|
| Обычный файл WAV / AIFF / FLAC | да | да, тот же формат, частота, разрядность, каналы | да |
| Обычный файл других форматов (MP3, OGG, прочие читаемые) | да | **нет** (пункт неактивен) | да, в WAV |
| Сэмпл из образа диска, SF2/EXS/NKI-источник, трекерный сэмпл, стерео-пара L/R | да | **нет** | да, в WAV |
| REX2, Reason-патч, трекер «весь трек», инструмент без выбранного источника | нет (меню неактивно) | — | — |
| Файл с > 2 каналами | нет (меню неактивно, подсказка «only mono/stereo») | — | — |

Модель данных — `SampleAudio` (`core/sampler/SamplerTypes.h`: моно/стерео, `left`/`right`). Больше двух
каналов она не держит, поэтому такие файлы не редактируются.

## Поведение

### Меню (правый клик по волне)

```
Undo                   ⌘Z
Redo                  ⇧⌘Z
───────────────────────
Delete region          ⌫
Crop to selection
Silence region
───────────────────────
Reverse
Fade in
Fade out
Normalize (-0.1 dBFS)
Gain…
Convert to mono
Remove DC offset
Trim silence
───────────────────────
Zoom to selection
Zoom to fit            ⌘0
───────────────────────
Save…                  ⌘S
```

- Операции действуют на **выделение**; без выделения — на **весь файл**. Delete / Crop / Silence без
  выделения неактивны. Trim silence всегда работает по всему файлу (края).
- Точное поведение операций:
  - **Delete region** — вырезать кадры выделения, хвост сдвигается. Выделение снимается, курсор на
    месте разреза.
  - **Crop to selection** — оставить только выделение. Выделение снимается.
  - **Silence region** — нули в выделении, длина та же.
  - **Reverse** — разворот кадров в диапазоне.
  - **Fade in / Fade out** — линейная по амплитуде огибающая 0→1 / 1→0 на всю длину диапазона.
    *(Решение исполнителя: форма кривой; линейная — по умолчанию.)*
  - **Normalize** — общий для всех каналов коэффициент, пик диапазона → −0.1 dBFS (как в
    `AudioExporter::exportSampleFile`). Тишина не трогается.
  - **Gain…** — маленький диалог с числом в дБ (−24…+24, шаг 0.1). Клиппинг допускается, но после
    операции, если пик > 0 dBFS, в строке статуса предупреждение «clipping». Значения не обрезаются
    до записи во float; при записи в целочисленный формат — клип при конвертации.
  - **Convert to mono** — среднее (L+R)/2 по всему файлу (игнорирует выделение); неактивно для моно.
  - **Remove DC offset** — вычесть среднее каждого канала в диапазоне.
  - **Trim silence** — срезать начало и конец, где |x| ниже −60 dBFS по всем каналам; оставить
    5 мс запаса с каждой стороны. *(Порог и запас — решение исполнителя, вынести в константы.)*
- Горячие клавиши, пока фокус в окне приложения и не в текстовом поле: ⌘Z / ⇧⌘Z, ⌫ (Delete region при
  наличии выделения), ⌘S. На Windows/Linux — Ctrl.

### Зум и прокрутка

Работают для **любой** волны в превью, не только при правке (обычные файлы, образы дисков,
сэмплы инструментов, REX).

- **Ctrl+колесо** (на macOS также **Cmd+колесо**): зум по горизонтали вокруг точки под курсором.
  Точка под курсором остаётся на месте.
- **Щипок двумя пальцами на тачпаде** (`mouseMagnify`): тот же зум вокруг курсора.
- **Прокрутка при зуме**: горизонтальный свайп двумя пальцами или Shift+колесо двигают видимую
  область. Вертикальное колесо без модификаторов ведёт себя как сейчас: в режиме Loop меняет размер
  региона вокруг центра.
- **Границы**: от «весь файл» до примерно 1 пикселя на сэмпл, дальше не приближает. Минимальный
  масштаб — весь файл, отдалить сильнее нельзя.
- **Двойной клик** сохраняет текущее поведение. Сброс зума — пункт меню `Zoom to fit` (⌘0).
  Плюс `Zoom to selection`, если есть выделение. Оба пункта стоят в контекстном меню отдельным
  блоком над `Save…`.
- **Обзорная полоска**: при зуме внизу волны появляется тонкая полоса со всем файлом и рамкой
  видимой области. Рамку можно тащить мышью. *(Моё решение: без неё легко потеряться в длинном
  файле.)*
- **Воспроизведение**: если курсор воспроизведения уходит за правый край, вид не прокручивается
  автоматически. *(Моё решение: при правке скачущий вид мешает. Автоследование можно добавить
  позже.)*
- **Всё в координатах вида**: выделение, перетаскивание и resize региона, seek кликом, drag в DAW,
  курсоры и слайсы REX считаются через видимый диапазон, а не через всю длину.
- **Детализация**: при зуме пики пересчитываются для видимого диапазона.
  - Из буфера правки или `SampleAudio` — напрямую.
  - Для обычного файла `AudioThumbnail::drawChannels` с поддиапазоном. Если его разрешения
    (512 сэмплов на точку) не хватает, при глубоком зуме читаем сэмплы видимого куска из файла.
    *(Способ — решение исполнителя. Требование: на ~1 пиксель/сэмпл видны отдельные сэмплы.)*
- **Смена источника** сбрасывает зум. Операция правки сохраняет вид, ограниченный новой длиной.

### Индикация

- Есть несохранённые правки → у имени файла в `PreviewPanel` суффикс ` •` (например `Clap_15.wav •`).
- Волна перерисовывается из буфера сразу после операции; позиция воспроизведения ограничивается новой
  длиной; если шло воспроизведение — продолжается с той же позиции (или с конца, если вышла за длину).
- Волна при правке рисуется **по обоим каналам**, как сейчас у обычного файла (сейчас `setPeaks`
  показывает только левый канал — для редактора это надо расширить).

### Undo/Redo

- Стек снимков буфера (каждая операция кладёт копию «до»). Лимит — по памяти, напр. 256 МБ на стек,
  старые снимки выпадают. *(Точный лимит/стратегия — решение исполнителя; можно хранить только
  изменённый диапазон.)*
- Undo до исходного состояния снимает признак `•`.
- Стек сбрасывается при загрузке другого источника и после успешного сохранения (Overwrite или
  Save copy — во втором случае превью переключается на копию, см. ниже).

### Сохранение (⌘S / пункт Save…)

Без несохранённых правок ⌘S ничего не делает. Иначе — модальный диалог:

```
Save changes to “Clap_15.wav”?
[ Overwrite ]  [ Save copy ]  [ Cancel ]
```

- **Overwrite** (только обычные WAV/AIFF/FLAC):
  1. Запись во временный файл в той же папке тем же форматом, частотой, разрядностью и числом
     каналов (Convert to mono → 1 канал).
  2. Проверка записанного (длина/формат, по образцу `AudioExporter::validateWavOutput`).
  3. Атомарная замена оригинала (`juce::TemporaryFile::overwriteTargetFileWithTemporary`).
     Если путь — симлинк, пишем рядом с реальной целью и заменяем её (ссылка остаётся ссылкой).
     Права доступа и расширенные атрибуты macOS (Finder-теги и цвета) копируются с оригинала на
     новый файл до замены. Жёсткие ссылки при этом разрываются — допустимо. *(Моё решение.)*
  4. Переанализ одного файла в фоне и обновление его строки в каталоге (см. «Каталог»).
  5. Undo-стек очищается, признак `•` снимается, превью перезагружается из нового файла.
  Ошибка на любом шаге → оригинал не тронут, сообщение в строке статуса, правки в памяти остаются.
- **Save copy**:
  - Имя: `<stem> edit.wav` рядом с оригиналом (для образов дисков/инструментов — рядом с
    контейнером; если папка недоступна для записи — в папку экспорта
    `AudioExporter::defaultExportFolder()`). Если занято — `<stem> edit 2.wav`, `edit 3` …
    Никогда не перезаписывает существующий файл.
  - Формат копии: тот же, что у оригинала, если это WAV/AIFF/FLAC; иначе WAV (разрядность
    оригинала, если известна, иначе 24 бит).
  - Копия добавляется в каталог и наследует **пользовательские теги и звёздочку** оригинала.
    *(Моё решение: копия того же звука почти всегда нужна с теми же тегами.)*
  - Стерео-пара L/R: копия — один стерео-файл `<общая основа без L/R> edit.wav` в папке L-файла;
    наследует объединение тегов обеих сторон и звёздочку, если она стоит хотя бы у одной. *(Моё
    решение.)*
  - После сохранения превью **переключается на копию** (в библиотеке выделяется её строка), правки
    становятся «сохранёнными» для копии, оригинал остаётся без изменений.
- **Cancel** — ничего.

### Метаданные файла при записи

- Сохранять то, что JUCE переносит через `metadataValues` читателя: WAV `smpl` (loop-точки, root key),
  `cue`, BWF/`bext`, `acid`, AIFF маркеры/loop.
- Если правка меняла длину или положение кадров (Delete, Crop, Trim silence, Reverse), loop/cue-точки
  пересчитываются: точки внутри удалённого куска — удаляются, после него — сдвигаются, при Reverse —
  зеркалируются; точки за новой длиной — удаляются. Луп, у которого после правки start ≥ end, удаляется.
- Чего JUCE не переносит — теряется; это допустимо, но перечислить в заметке к коммиту.

### Несохранённые правки при уходе с файла

Перед любой сменой источника (выбор другой строки в библиотеке, в том числе стрелками; открытие
образа диска; очистка выделения библиотеки; выбор другого семпла/пресета в комбобоксах превью;
закрытие приложения) при наличии `•` — модальный диалог:

```
“Clap_15.wav” has unsaved edits.
[ Save… ]  [ Discard ]  [ Cancel ]
```

- **Save…** — тот же диалог Overwrite / Save copy; после успешного сохранения переход продолжается,
  при Cancel/ошибке — переход отменяется.
- **Discard** — правки выбрасываются, переход продолжается.
- **Cancel** — выделение в библиотеке возвращается на редактируемый файл, переход не происходит.

### Каталог

- Overwrite: переанализировать **один** файл (как в `IndexingService`: `BasicAnalyzer().analyzeAndHash`
  + `SampleRepository::upsert`) в фоне, не через сканирование папки. `upsert` делает
  `INSERT … ON CONFLICT(path) DO UPDATE` (`SampleRepository.cpp:818`) — id строки сохраняется, значит
  `sample_tags` и `starred` переживают Overwrite; `smart_results` помечаются устаревшими (так и надо).
- ML-фидбэк (`ml_feedback_samples`) перезаписанного файла: метка сохраняется. `file_hash`,
  `features` и `features_v2` пересчитываются по новому звуку. `updated_at` обновляется, чтобы запись
  снова ушла на отправку (contribute). Решение владельца.
- Save copy **не наследует** ML-фидбэк, только теги и звёздочку. Так в обучение не попадут почти
  одинаковые примеры. Решение владельца.
- Если идёт индексация, переанализ одного файла не должен с ней конфликтовать (параллельная запись в
  репозиторий — по существующим правилам блокировок `SampleRepository`).
- Save copy: та же процедура для нового пути + перенос тегов оригинала.
- Пока файл открыт на правку, индексатор может переанализировать оригинал — это нормально, буфер в
  памяти от этого не зависит.

## Ограничения и устройство (для исполнителя)

- C++/JUCE, без новых зависимостей. Сборка — пресеты в `CMakePresets.json`
  (`~/Library/Caches/sonicator-build`).
- Логику правки вынести в **ядро** без UI, напр. `core/edit/AudioEditBuffer.{h,cpp}` (буфер, операции,
  undo/redo, пересчёт маркеров) и `core/edit/AudioEditWriter.{h,cpp}` (запись/атомарная замена/имя
  копии). Это даёт юнит-тесты без окна.
- Воспроизведение правленого буфера — тем же путём, что сэмплы из образов дисков
  (`AudioEngine::setDiscSample` / `PreviewPanel::loadDiscSample`), но **без** потери идентичности
  обычного файла (имя, путь для Overwrite, выделение строки). Выделение, Loop, MIDI Preview и drag в DAW
  должны работать на правленом буфере (drag в DAW — экспортирует текущий буфер/выделение из него).
- Тяжёлые операции на длинных файлах (> ~10 с аудио) не должны блокировать UI заметно; если операция
  дольше ~100 мс — допустимо выполнить в фоне с блокировкой меню на время работы. *(Решение
  исполнителя.)*
- Декод при первом редактировании: буфер создаётся лениво — при первой операции, не при каждом
  просмотре файла, чтобы листание библиотеки не замедлилось.
- Тесты: на операции буфера (включая маркеры), на имя копии, на атомарность Overwrite (ошибка записи
  оставляет оригинал байт-в-байт), на сохранение тегов при Overwrite. Тесты пишут только во временные
  папки и временный каталог; живой `~/Library/Sonicator/sonicator.sqlite` и `settings.json` не трогать.
- Документация: раздел в `docs/ARCHITECTURE.md`; после изменения кода — `graphify update .`.

## Оставлено исполнителю

Форма фейд-кривой, порог/запас Trim silence, лимит памяти undo, фоновое выполнение операций, точная
раскладка диалогов (стандартные JUCE `AlertWindow`), где именно в `MainComponent` перехватывать смену
источника.
