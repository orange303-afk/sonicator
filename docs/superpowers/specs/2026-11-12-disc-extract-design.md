# ТЗ: Extract сэмплов из образов дисков (правая кнопка по образу, drag&drop, выделенные сэмплы)

Дата: 2026-11-12. Статус: на утверждение.
После утверждения переносится план: `docs/superpowers/plans/2026-11-12-disc-extract.md`.

## Зачем

Образы ISO/CUE/BIN открываются в Sonicator и играются, но вытащить из них сэмплы можно только
по одному через превью. Нужно извлекать сэмплы образа пакетно, чтобы они сразу попадали
в библиотеку, сканировались и анализировались — то есть становились обычными рабочими файлами.

## Что уже есть

- **Extract** (`core/extract/ExtractService`, `ui/extract/ExtractDialog`) уже извлекает встроенные
  сэмплы из MOD/XM/S3M/SF2: пишет `001 Name.wav` в папку `<имя источника> samples` рядом
  с исходником или в выбранную папку, пропускает пустые и полностью тихие, умеет отмену,
  ведёт прогресс и список проблем. Образы дисков он не понимает.
- **Правая кнопка по строке** (`MainComponent::showSampleContextMenu`): пункт «Extract samples…»
  появляется для выделенных файлов, которые `embeddedSources()` признаёт встроенными банками.
  Образ диска (`.iso`, `.cue`, `.bin`) в этот список не попадает; строки сэмплов внутри образа
  (`SampleRecord::isDiscEntry()`) вообще не имеют пути к файлу и пропускаются.
- **Чтение образа** — `DiscBrowserService`: асинхронный воркер `open → list(recursive) → decode`,
  умеет `.cue` с выбором дорожки, ISO-9660 и сырой Akai, склеивает L/R в стерео.
- **Библиотека** — `IndexingService::start(folders)` регистрирует папки корнями и сканирует;
  `startSubtree(folder)` сканирует без регистрации; `SmartAnalysisService::startFolder(folder)`
  считает smart-метаданные. После Split уже есть готовый образец цепочки (`pendingSplitScan`).
- **Перетаскивание**: наружу из приложения работает только из окна волноформы и с кнопки
  drag в превью. Приём файлов из Finder приложение не поддерживает вообще.

## Цели

1. **Правая кнопка по образу в списке.** Пункт «Extract samples…» для выделенных строк-образов
   (`.iso`, `.cue`, `.bin`; `.bin` с соседним `.cue` открывается через cue). Открывается тот же
   диалог Extract: «рядом с исходником» (по умолчанию) или выбранная папка, нормализация.
2. **Правая кнопка по сэмплам образа.** Для одной или нескольких выделенных строк-сэмплов
   внутри образа (`isDiscEntry()`) — извлекаются только они. Стерео-пара даёт один стерео WAV.
   Смешанное выделение (образ + его сэмплы + обычные файлы) разбирается по типам: образы целиком,
   сэмплы по одной записи, банки как сейчас.
3. **Drag&drop файла в приложение.** Окно принимает один или несколько образов (и папок? — нет,
   только файлы) из Finder; бросок открывает диалог Extract с этими образами. Обычные аудиофайлы
   и папки бросок не перехватывает (их поведение не меняем).
4. **Результат попадает в библиотеку.** После батча:
   - если папка результата уже внутри корня библиотеки — `IndexingService::startSubtree`;
   - если снаружи — `IndexingService::start` (папка становится корнем, как при добавлении папки);
   - затем `SmartAnalysisService::startFolder` по папке результата.
   Всё это в существующей последовательной манере (как `pendingSplitScan`), с сообщением в статусе.
5. **Имя и раскладка** не меняются: `<имя образа> samples/001 Name.wav`, стерео-пара — один файл,
   пустые и полностью тихие пропускаются, программы и прочие типы записей не извлекаются
   (считаются в «пропущено»).

## Не входит

- Extract по правому клику на папке (пользователь уточнил: не нужно).
- Перетаскивание строк из списка наружу в Finder (сейчас наружу работает только волноформа;
  расширение drag-out — отдельная задача).
- Извлечение программ/кейгрупп как инструментов, MDX, аудио-дорожек CD.
- Автоматические теги (AutoTag) после извлечения — только smart-метаданные.

## Анти-цели (провал, даже если «работает»)

- Изменение или удаление исходного образа: он открывается только на чтение.
- Перезапись существующих WAV: только свободные имена (существующее правило `uniqueSampleFile`).
- Зависание окна: всё извлечение и последующие проходы — в фоновых потоках, отмена работает.
- Тихая подмена: если образ не открылся или у сэмпла ошибка, это видно в итоговом отчёте диалога.

## Решения (мои, если не поправите)

- Извлечение образа идёт **из файла**, а не из каталога: работает и для неиндексированного образа.
- Извлечение одной записи идёт через `DiscBrowserService` того же образа (decode с partner для
  стерео), поэтому имена и PCM совпадают с тем, что играет превью.
- Порядок записей — порядок обхода `list(recursive)`: разделы → тома → записи; нумерация
  сквозная по образу, поэтому одинаковые имена в разных томах не сталкиваются.
- Если выбрано несколько образов, у каждого своя папка `<имя> samples`.
- Скан и анализ запускаются один раз на все папки результата после завершения батча
  (в том числе после частичной отмены — для уже записанных файлов).

## Критерии приёмки

1. `[extract][disc]`: синтетический образ Akai (фикстура из `TestAkaiFilesystem`) — Extract пишет
   ожидаемое число WAV, PCM совпадает с `decodeSample`, стерео-пара — один стерео файл,
   тихий сэмпл пропущен, программы не пишутся.
2. `[extract][disc]`: синтетический ISO с WAV внутри — извлекается с сохранением кадров и частоты.
3. `[extract][disc]`: отмена посреди образа оставляет готовые WAV и не оставляет `.part`.
4. `[extract][menu]`: пункт «Extract samples…» есть для строки `.cue`/`.iso`/`.bin` и для строки
   сэмпла образа; его нет для обычного WAV; заголовок для нескольких строк называет количество.
5. `[extract][drop]`: окно принимает бросок `.cue`/`.iso`/`.bin`, не перехватывает `.wav` и папки.
6. `[extract][library]`: после извлечения вызывается скан папки результата (subtree, если папка
   внутри корня; с регистрацией корня, если снаружи), затем smart-анализ этой папки.
   Проверяется на временной базе.
7. Opt-in на реальном образе (`SONICATOR_DISC_IMAGE`): извлечение первых 5 сэмплов
   `TZRMRM1AK.cue` в временную папку, PCM побайтно равен декодеру, образ не изменён.
8. Полный `ctest` зелёный; в интерфейсе вручную: правая кнопка по `TZRMRM1AK.cue` → Extract →
   файлы на месте, появились в библиотеке и получили smart-метаданные.

## Стоп-условия

- `ExtractService` не удаётся расширить без дублирования половины `run()` — тогда сначала
  выносим общий проход в отдельный класс и это отдельная задача плана.
- Для стерео-пары извлечение через `DiscBrowserService` даёт каналы, отличные от `decodeSample`.
