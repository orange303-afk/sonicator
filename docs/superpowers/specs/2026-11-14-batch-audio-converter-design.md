# Пакетный конвертер аудио — план и ТЗ

Дата: 2026-11-14. Статус: проектное ТЗ, реализация не начата.

## Задача и границы

Добавить `Convert` в контекстное меню файла, выделенных файлов и папки **внутри Sonicator**. Команда открывает диалог настроек и создаёт для каждого подходящего исходного аудиофайла по одному результату в каждом выбранном выходном формате. Исходные файлы не изменяются. Интеграция с контекстным меню Finder/Проводника — отдельный этап, не часть первой реализации.

Родственный пункт внешнего бэклога: «Многофункциональный конвертер форматов с настройками (wav, mp3, flac, aif, ogg и другие, включая старые и экзотические)» в `~/Documents/orange303/Sonicator Features.md`.

## Сценарии и интерфейс

1. Правый клик по строке библиотеки, нескольким выбранным строкам или папке дерева → `Convert…`. Для папки обходить вложенные папки рекурсивно. Виртуальная папка `All samples` и виртуальные объекты внутри контейнеров требуют отдельного решения; в первой версии команда доступна только для обычных файлов и физических папок.
2. Диалог показывает число найденных входных файлов, число ожидаемых выходных файлов, неподдерживаемые источники и пример имени результата. Неподдерживаемый файл пропускается с явной причиной в итоговом отчёте. Если подходящих файлов нет, запуск недоступен.
3. Назначение: флажок `Save next to originals` (по умолчанию включён) или выбор выходной папки. Для папки и отдельного назначения по умолчанию сохранять относительную структуру подпапок; для нескольких источников из разных корней группировать их по имени исходного корня, предотвращая совпадения путей.
4. Выходные форматы выбираются несколькими флажками; минимум один обязателен. Одно преобразование создаёт декартово произведение «источник × выбранные форматы». Выбранные параметры общие для задания, а ограничения и параметры конкретного кодека показаны рядом с форматом.
5. Частота: `Same as source`, 44,1 / 48 / 88,2 / 96 / 192 кГц, только если выбранные форматы поддерживают значение. Каналы: `Same as source`, моно, стерео. Сведение стерео в моно — усреднение L/R с проверкой пиков; моно в стерео — копирование сигнала в оба канала. Для источников с более чем двумя каналами первая версия выдаёт явное `unsupported channels`, без неявного выбора каналов.
6. Для PCM форматов: 16-bit integer, 24-bit integer, 32-bit float там, где формат это поддерживает; `Same as source` лишь когда его можно однозначно представить в целевом формате. При уменьшении целочисленной разрядности применять dither. Для MP3/AAC/Opus/Vorbis/WMA показывать битрейт или качество кодека, а не «битность». FLAC/ALAC имеют lossless compression level, который влияет на размер и скорость, но не на точность PCM.
7. Конфликт имён: до запуска выбрать политику `Rename` (безопасное значение по умолчанию), `Skip` или `Replace`. Для `Replace` нужен отдельный явный выбор в диалоге; запись выполнять через временный файл и атомарную замену после проверки результата. Если целевой путь совпадает с исходным, автоматически предложить другое имя; запрещать прямую запись поверх читаемого источника.
8. Во время задания показывать текущий файл, формат, прогресс, число успехов/пропусков/ошибок, `Cancel`. После завершения дать отчёт по каждому сбою и кнопку открытия папки результатов. Отмена удаляет только незавершённые выходы, сохраняет готовые результаты.

## Выходные форматы

| Этап | Формат / расширение | Настройки |
|---|---|---|
| 1 | WAV `.wav`, AIFF `.aif`/`.aiff` | Частота, каналы, поддерживаемая PCM разрядность |
| 1 | FLAC `.flac` | Целочисленная разрядность, уровень сжатия |
| 1 | MP3 `.mp3`, OGG Vorbis `.ogg` | Битрейт или качество; ограничения кодека по частоте и каналам |
| 2 | AAC `.m4a`, ALAC `.m4a`, Opus `.opus`, WavPack `.wv` | Параметры конкретного кодека |
| Исследование | WMA `.wma`, CAF `.caf`, AU `.au`, IFF 8SVX `.iff`, VOC `.voc`, ADPCM WAV `.wav` | Добавлять после проверки кодировщика, лицензии, платформ и тестовых файлов |

`.aif` и `.aiff` — один формат с выбором расширения по умолчанию `.aif`. AAC и ALAC делят расширение `.m4a`, поэтому при выборе обоих нужно различать имена результатов (`name.aac.m4a`, `name.alac.m4a`) и показывать это в превью. Аналогично различать варианты одного контейнера. WMA включать только после подтверждённой поддержки записи на целевых платформах; её наличие в списке кандидатов не является обещанием первой версии.

Старые форматы и контейнеры с несколькими семплами (SF2, REX2, XI, SFZ, NKI, образы дисков и т. п.) сначала требуют выбора, какие именно вложенные аудиообъекты выводить. Их нельзя молча трактовать как один обычный файл. Первая версия принимает обычные аудиофайлы, для которых уже доступно декодирование полного звука; фактический список источников определяется проверкой reader и подтверждается тестами, а не только расширением.

## Технический план

1. **Контракт задания.** Отдельные модели `ConversionRequest`, `OutputPreset`, `ConflictPolicy` и результата по каждому сочетанию источник/формат. До запуска построить неизменяемый список входов и целевых путей, проверить коллизии внутри задания и доступное место (оценка, не гарантия).
2. **Фоновый конвейер.** Повторно использовать существующие декодеры Sonicator там, где они предоставляют полное PCM аудио. Чтение чанками → преобразование каналов → качественный ресемплинг → квантование/dither при необходимости → кодировщик. Декодировать один источник один раз для нескольких форматов, если это возможно при ограниченной памяти; не сохранять весь длинный файл в RAM. Кодек MP3/Vorbis/прочие добавить как явные зависимости с проверенной совместимостью лицензий и сборки для macOS/Windows.
3. **Безопасная запись.** Создавать временный файл в конечной директории, завершать и проверять кодек/длительность/каналы/частоту, затем переименовывать. Ошибки одного результата не останавливают остальные. Исходник всегда открыт только для чтения. Не выполнять декодирование/кодирование на audio callback или message thread.
4. **UI.** Подключить команду в `MainComponent` к существующим меню строк и дерева папок; отдельный диалог настроек, снимок выделения при открытии, один активный worker с отменой и опросом прогресса. Существующий `AudioExporter` и `SelectionExporter` относятся к экспорту WAV выделения и не должны случайно менять его поведение.
5. **Каталог.** После успешного задания предложить индексировать новые файлы в наблюдаемых корнях или использовать существующий `New files`; выбрать один вариант при реализации и показать результат пользователю. Никогда не переносить теги/оценки на новые файлы автоматически без отдельного решения.

## Критерии приёмки

- Один файл → два выбранных формата → два читаемых файла с ожидаемыми частотой, каналами и длительностью.
- Несколько файлов и рекурсивная папка → правильное число выходов и сохранённая относительная структура; совпадающие базовые имена не перезаписывают друг друга.
- Настройки, невозможные для одного из выбранных форматов, явно недоступны или блокируют запуск с понятной причиной; «битность MP3» не предлагается.
- Изменение частоты и mono/stereo даёт предсказуемый результат без заметного сдвига длительности; проверить короткие, длинные, тихие и пиковые сигналы.
- При ошибке, отмене и нехватке места исходные файлы остаются байтово неизменными, частичные выходы удаляются, готовые выходы и отчёт сохраняются.
- При `Rename`, `Skip`, `Replace` соблюдается выбранная политика; `Replace` не оставляет повреждённый прежний файл при неудаче.
- UI остаётся отзывчивым на большой папке; память ограничена размером буферов, а прогресс и отмена работают между файлами и во время длинного файла.
- Сборка и основные сценарии проверены на поддерживаемых macOS и Windows. Кодеки, которые нельзя собрать или лицензировать для обеих платформ, не появляются в первом выпуске.

## Открытые решения до реализации

- Уточнить набор и лицензии кодировщиков, особенно MP3, Vorbis, WMA, AAC и Opus.
- Решить, нужен ли отдельный `Convert` для предпросмотра из образа/инструмента или это остаётся в `Extract`.
- Утвердить политику переноса аудиометаданных (BPM, key, loop points, BWF, ID3, Vorbis comments): по умолчанию сохранять только совместимые и проверенные поля, честно показывая потери.
- Решить, выполнять ли автоматическое индексирование созданных файлов после задания.

Планирование не означает реализацию. При начале работ сверить документ с текущей архитектурой, бэклогом и доступными кодеками.
