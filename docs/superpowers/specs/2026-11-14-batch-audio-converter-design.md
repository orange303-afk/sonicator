# Batch Processing и конвертер аудио — план и ТЗ

Дата: 2026-11-14. Статус: общий замысел. Первый этап (Batch Processing v1) реализован по
[подробному ТЗ 2026-11-15](2026-11-15-batch-processing-tz.md); Split, MP3/OGG и перезапись
оригиналов остаются будущими этапами.

## Задача и границы

Добавить `Batch Processing…` (или `Convert / Process…`) в контекстное меню файла, выделенных файлов и папки **внутри Sonicator**. Диалог позволяет выстроить цепочку офлайновой обработки и затем записать результат в один или несколько форматов. Простая конвертация — задание без дополнительных обработок. По умолчанию оригиналы сохраняются; отдельная явно выбранная опция позволяет перезаписать оригиналы при соблюдении ограничений ниже. Интеграция с контекстным меню Finder/Проводника — отдельный этап.

Родственный пункт внешнего бэклога: «Многофункциональный конвертер форматов с настройками (wav, mp3, flac, aif, ogg и другие, включая старые и экзотические)» в `~/Documents/orange303/Sonicator Features.md`.

## Сценарии и интерфейс

1. Правый клик по строке библиотеки, нескольким выбранным строкам или папке дерева → `Batch Processing…`. Для папки обходить вложенные папки рекурсивно. Виртуальная папка `All samples` и виртуальные объекты внутри контейнеров требуют отдельного решения; в первой версии команда доступна только для обычных файлов и физических папок.
2. Диалог показывает число найденных входных файлов, выбранные операции и их порядок, число ожидаемых выходных файлов или диапазон при разбиении, неподдерживаемые источники и пример имени результата. Неподдерживаемый файл пропускается с явной причиной в итоговом отчёте. Если подходящих файлов нет, запуск недоступен.
3. Назначение: флажок `Save next to originals` (по умолчанию включён) или выбор выходной папки. Для папки и отдельного назначения по умолчанию сохранять относительную структуру подпапок; для нескольких источников из разных корней группировать их по имени исходного корня, предотвращая совпадения путей. `Overwrite originals` — взаимоисключающий режим назначения, при котором путь записи определяется каждым исходным файлом.
4. Выходные форматы выбираются несколькими флажками; минимум один обязателен. Для каждого результата цепочки создаётся по одному файлу в каждом выбранном формате. Без Split by silence это «источник × форматы»; после split — «полученные фрагменты × форматы». Выбранные параметры общие для задания, а ограничения конкретного кодека показаны рядом с форматом.
5. Частота: `Same as source`, 44,1 / 48 / 88,2 / 96 / 192 кГц, только если выбранные форматы поддерживают значение. Каналы: `Same as source`, моно, стерео. Сведение стерео в моно — усреднение L/R с проверкой пиков; моно в стерео — копирование сигнала в оба канала. Для источников с более чем двумя каналами первая версия выдаёт явное `unsupported channels`, без неявного выбора каналов.
6. Для PCM форматов: 16-bit integer, 24-bit integer, 32-bit float там, где формат это поддерживает; `Same as source` лишь когда его можно однозначно представить в целевом формате. При уменьшении целочисленной разрядности применять dither. Для MP3/AAC/Opus/Vorbis/WMA показывать битрейт или качество кодека, а не «битность». FLAC/ALAC имеют lossless compression level, который влияет на размер и скорость, но не на точность PCM.
7. Конфликт имён новых результатов: до запуска выбрать политику `Rename` (по умолчанию), `Skip` или `Replace existing output`. Последняя заменяет уже существующий **выходной** файл после записи и проверки временной копии. Она не включает перезапись оригиналов. Для оригиналов предназначен отдельный режим `Overwrite originals` ниже.
8. Во время задания показывать текущий файл, формат, прогресс, число успехов/пропусков/ошибок, `Cancel`. После завершения дать отчёт по каждому сбою и кнопку открытия папки результатов. Отмена удаляет только незавершённые выходы, сохраняет готовые результаты.

## Цепочка Batch Processing

Диалог содержит упорядоченный список операций: добавить, убрать, включить/выключить и переставить шаг. Превью одного выбранного файла позволяет сравнить исходник и результат до запуска всей партии; настройки партии и порядок шагов сохраняются как пресет. Каждый шаг обязан объявлять, меняет ли он число файлов, длительность, частоту, каналы или метаданные. Невозможное сочетание блокирует запуск с объяснением.

| Операция | Настройки и поведение |
|---|---|
| Split by silence | Порог dBFS, минимальная длина паузы и фрагмента, запас до/после звука. Даёт 0, 1 или несколько фрагментов; при отсутствии реального разделения результат остаётся целым. Нумерация фрагментов стабильна. |
| Trim silence | Порог и запас в миллисекундах; обрезает только тишину по краям каждого входящего фрагмента. Полностью тихий результат не превращать молча в файл нулевой длины. |
| Normalize | Peak target dBFS (стандартно −0.1 dBFS); один коэффициент на все каналы результата. Для пустого/тихого сигнала показывать `no change`. Позднее можно добавить loudness normalization как отдельную операцию с измерением LUFS и true peak. |
| Remove DC offset | Вычесть среднее каждого канала в пределах текущего фрагмента; показывать измеренное смещение в превью. |
| Gain | Значение в dB; показать предупреждение о клиппинге и предложить защиту/нормализацию отдельным шагом. Не включать скрытый limiter. |
| Fade in / Fade out | Длительность, форма кривой; действует на каждый итоговый фрагмент. |
| Channel conversion | Stereo → mono и mono → stereo по правилам раздела сценариев; может быть отдельным шагом или частью Output. |
| Resample | Целевая частота; обычно часть Output, но отображается в схеме обработки. |

Порядок операций имеет значение: например, `Remove DC → Split → Trim → Normalize → Fade` даст другой результат, чем нормализация до разбиения. По умолчанию предложить этот порядок, но разрешить менять его; после Split все следующие шаги выполняются **для каждого фрагмента отдельно**. Шаги, которым нужен анализ всего файла или фрагмента, могут делать предварительный потоковый проход; память остаётся ограниченной. Форматирование/кодирование выполняется после всех операций. Исходный файл декодируется настолько мало раз, насколько позволяет ограничение памяти и необходимость анализа, без сохранения длинного файла целиком в RAM.

Дополнительные кандидаты после первого набора: polarity invert, reverse, peak limiter, loudness normalization, bit-depth/dither, channel swap, padding silence и обработка метаданных. Каждый должен иметь явную настройку и собственные критерии приёмки; не добавлять их как скрытые побочные эффекты Normalize или Gain. Для операций, уже имеющихся в редакторе/`SplitService`, переиспользовать алгоритм или общий контракт там, где это сохраняет поведение, но не привязывать пакетное задание к интерактивному undo-буферу.

## Перезапись оригиналов

`Overwrite originals` — **отдельная опция** в секции Output, выключена по умолчанию. Она заменяет именно входные файлы результатом обработки, а не только разрешает коллизии в выбранной выходной папке. Перед запуском показывать количество заменяемых оригиналов, список примеров, параметры записи и явное подтверждение. Пользователь должен иметь возможность просмотреть результат хотя бы для одного типичного файла.

- Доступна, только когда на **каждый входной файл получается ровно один выходной файл того же контейнера/расширения**. Поэтому одновременно выбранные несколько форматов и `Split by silence` делают её недоступной; можно сначала запустить эти задания как новые файлы. Нельзя включить замену оригинала из образа диска, банка, синтетического пути или источника без поддерживаемого writer.
- При перезаписи исходника формат, частоту, каналы и разрядность разрешено менять, если исходный контейнер может корректно сохранить выбранные параметры. Если кодек нельзя записать, показать причину и предложить `Save copy` в поддерживаемом формате.
- Для каждого файла: прочитать оригинал без записи; создать временный файл в той же директории; полностью завершить и проверить новый файл (декодируемость, длительность/число кадров с учётом операций, частота, каналы и формат); затем атомарно заменить оригинал. Сбой до замены оставляет исходные байты неизменными. Перед заменой убедиться, что оригинал не изменился с момента начала задания.
- Предусмотреть необязательную резервную копию оригиналов в отдельной папке/под заданным суффиксом; для первой версии режима перезаписи она включена по умолчанию. Если не удаётся создать и проверить копию, этот оригинал не заменять. Откат уже заменённых файлов при последующей ошибке партии — отдельное действие по сохранённым копиям, а не молчаливая попытка.
- Переносить совместимые права доступа и метаданные файловой системы, а также совместимые аудиометаданные/loop points по явным правилам. Когда обработка меняет длину или частоту, пересчитывать или удалять несовместимые позиции маркеров с предупреждением. Каталог Sonicator должен переанализировать заменённый файл, сохранив его ID, теги, избранное и ручные исправления.
- Одна неудача не останавливает всю партию; итоговый отчёт по каждому исходнику различает `replaced`, `unchanged`, `failed` и `cancelled` и указывает путь резервной копии. Отмена не откатывает уже успешно заменённые файлы автоматически.

## Выходные форматы

| Этап | Формат / расширение | Настройки |
|---|---|---|
| 1 | WAV `.wav`, AIFF `.aif`/`.aiff` | Частота, каналы, поддерживаемая PCM разрядность |
| 1 | FLAC `.flac` | Целочисленная разрядность, уровень сжатия |
| 1 | MP3 `.mp3`, OGG Vorbis `.ogg` | Битрейт или качество; ограничения кодека по частоте и каналам |
| 2 | AAC `.m4a`, ALAC `.m4a`, Opus `.opus`, WavPack `.wv` | Параметры конкретного кодека |
| Исследование | WMA `.wma`, CAF `.caf`, AU `.au`, IFF 8SVX `.iff`, VOC `.voc`, ADPCM WAV `.wav` | Добавлять после проверки кодировщика, лицензии, платформ и тестовых файлов |

`.aif` и `.aiff` — один формат с выбором расширения по умолчанию `.aif`. AAC и ALAC делят расширение `.m4a`, поэтому при выборе обоих нужно различать имена результатов (`name.aac.m4a`, `name.alac.m4a`) и показывать это в превью. Аналогично различать варианты одного контейнера. WMA включать только после подтверждённой поддержки записи на целевых платформах; её наличие в списке кандидатов не является обещанием первой версии.

Старые форматы и контейнеры с несколькими семплами (SF2, REX2, XI, SFZ, NKI, образы дисков и т. п.) сначала требуют выбора, какие именно вложенные аудиообъекты выводить. Их нельзя молча трактовать как один обычный файл. Первая версия принимает обычные аудиофайлы, для которых уже доступно декодирование полного звука; фактический список источников определяется проверкой reader и подтверждается тестами, а не только расширением.

## Технический план

1. **Контракт задания.** Отдельные модели `BatchRequest`, `ProcessStep`, `OutputPreset`, `ConflictPolicy`, `OverwritePolicy` и результата по каждому источнику/фрагменту/формату. До запуска построить неизменяемый список входов, предполагаемых целевых путей и ограничений режима перезаписи, проверить коллизии внутри задания и доступное место (оценка, не гарантия). Число выходов после Split может быть известно только после анализа.
2. **Фоновый конвейер.** Повторно использовать существующие декодеры Sonicator там, где они предоставляют полное PCM аудио. Чтение чанками → упорядоченные шаги обработки → преобразование каналов → качественный ресемплинг → квантование/dither при необходимости → кодировщик. Допускать дополнительные проходы для анализа, но не сохранять длинный файл целиком в RAM. Кодек MP3/Vorbis/прочие добавить как явные зависимости с проверенной совместимостью лицензий и сборки для macOS/Windows.
3. **Безопасная запись.** Создавать временный файл в конечной директории, завершать и проверять формат, длительность и параметры, затем переименовывать или безопасно заменять оригинал по выбранной политике. Ошибки одного результата не останавливают остальные. Исходник открыт только для чтения до последнего шага замены. Не выполнять декодирование/кодирование на audio callback или message thread.
4. **UI.** Подключить команду в `MainComponent` к существующим меню строк и дерева папок; отдельный диалог с цепочкой операций и Output, снимок выделения при открытии, один активный worker с отменой и опросом прогресса. Существующий `AudioExporter` и `SelectionExporter` относятся к экспорту WAV выделения и не должны случайно менять его поведение.
5. **Каталог.** После успешного задания предложить индексировать новые файлы в наблюдаемых корнях или использовать существующий `New files`; выбрать один вариант при реализации и показать результат пользователю. Никогда не переносить теги/оценки на новые файлы автоматически без отдельного решения.

## Критерии приёмки

- Один файл → два выбранных формата → два читаемых файла с ожидаемыми частотой, каналами и длительностью.
- Цепочка `Remove DC → Split by silence → Trim silence → Normalize → Gain/Fade` создаёт ожидаемые фрагменты; перестановка шагов меняет результат предсказуемо, а сохранённый пресет воспроизводит его.
- Без Split операции идут по целому файлу; после Split каждый следующий шаг действует на каждый фрагмент отдельно. Отчёт связывает каждый выход с исходником, фрагментом, цепочкой и форматом.
- Несколько файлов и рекурсивная папка → правильное число выходов и сохранённая относительная структура; совпадающие базовые имена не перезаписывают друг друга.
- Настройки, невозможные для одного из выбранных форматов, явно недоступны или блокируют запуск с понятной причиной; «битность MP3» не предлагается.
- Изменение частоты и mono/stereo даёт предсказуемый результат без заметного сдвига длительности; проверить короткие, длинные, тихие и пиковые сигналы.
- При ошибке, отмене и нехватке места ещё не заменённые исходные файлы остаются байтово неизменными; частичные выходы удаляются, готовые выходы и отчёт сохраняются. В обычном режиме все оригиналы остаются неизменными.
- При `Rename`, `Skip`, `Replace existing output` соблюдается выбранная политика; замена выходного файла не оставляет повреждённый прежний файл при неудаче.
- `Overwrite originals` заменяет подтверждённые оригиналы при одном выходе на вход и поддерживаемом исходном формате; до успешной проверки временного файла и резервной копии оригинал остаётся неизменным. Изменение частоты/каналов/разрядности отражается в повторном анализе каталога без потери тегов и ручных значений.
- Режим перезаписи недоступен при Split, нескольких форматах или незаписываемом исходном контейнере; ошибки и отмена не портят ещё не заменённые оригиналы, а отчёт перечисляет уже заменённые и их копии.
- UI остаётся отзывчивым на большой папке; память ограничена размером буферов, а прогресс и отмена работают между файлами и во время длинного файла.
- Сборка и основные сценарии проверены на поддерживаемых macOS и Windows. Кодеки, которые нельзя собрать или лицензировать для обеих платформ, не появляются в первом выпуске.

## Открытые решения до реализации

- Уточнить набор и лицензии кодировщиков, особенно MP3, Vorbis, WMA, AAC и Opus.
- Решить, нужен ли отдельный `Convert` для предпросмотра из образа/инструмента или это остаётся в `Extract`.
- Утвердить политику переноса аудиометаданных (BPM, key, loop points, BWF, ID3, Vorbis comments): по умолчанию сохранять только совместимые и проверенные поля, честно показывая потери.
- Решить, выполнять ли автоматическое индексирование созданных файлов после задания.
- Утвердить пороги и правила склейки/удаления слишком коротких фрагментов в пакетном Split; сверить с существующим `SplitService`.
- Зафиксировать судьбу loop/cue-маркеров и sidecar-файлов при каждом шаге, особенно при Split и перезаписи оригиналов.

Планирование не означает реализацию. При начале работ сверить документ с текущей архитектурой, бэклогом и доступными кодеками.
