# Сбор данных для обучения через Cloudflare Worker — дизайн

Статус: черновик на согласование. Бэклог: пункт 12 (`docs/BACKLOG.md`), `Sonicator Features.md`.

## Зачем

Sonicator учится на подтверждениях пользователя локально: когда тип или теги сэмпла подтверждены,
`ml_feedback_samples` хранит вектор акустических признаков с меткой, а `core/ml/AdaptiveClassifier`
строит по ним прототипы. Эти знания остаются на одном компьютере. Цель — с согласия пользователя
собирать их со всех установок, чтобы:

- обучать глобальные прототипы (а позже ONNX-модель) и поставлять их в следующих билдах;
- находить частые кастомные теги и типы и добавлять их в билды как стандартные;
- со временем выложить открытый датасет (признаки и метки, без аудио).

Канал отзывов (баги, фичи, форматы) уже есть — Settings → REPORT открывает issue на GitHub. Здесь он
только дополняется GitHub Discussions.

## Цели

1. Бесплатно: $0 в месяц на бесплатных лимитах Cloudflare (Workers, R2, `*.workers.dev`).
2. Безопасно: в открытом бинарнике нет ни одного секрета; на сервер не уходит ничего, что указывает на
   человека, его файлы или пути.
3. Только с согласием: по умолчанию выключено; вопрос при первом запуске и переключатель в Settings.
4. Прозрачно: пользователь видит точный JSON, который уйдёт, и может удалить всё отправленное.
5. Надёжно: отправка не мешает работе, переживает отсутствие сети и повторы без дублей.

## Не цели (в этом этапе)

- Обучение модели, агрегация, публикация датасета — отдельный этап; здесь только сбор и выгрузка.
- Отправка аудио, фрагментов аудио, спектрограмм.
- Автоматическая отправка багов и крэшей: остаются ручными через браузер, как сейчас.
- Аккаунты, логины, панель администратора.

## Анти-цели (провал, даже если «работает»)

- В данных или логах сервера оказывается путь, имя файла или папки, имя пользователя, IP или хэш
  содержимого файла.
- Хоть один байт уходит при выключенном переключателе или до ответа на вопрос о согласии.
- В репозитории или бинарнике появляется токен, ключ API или иной секрет.
- Отправка блокирует UI или поток аудио, или ошибка сети показывается пользователю как сбой.

## Ограничения

- Лицензия AGPL-3.0-or-later, репозиторий публичный: код Worker тоже открыт, адрес приёмника публичен.
- Приложение сейчас не делает сетевых вызовов, и `docs/DIAGNOSTICS.md` это обещает. Отправка вкладов
  становится единственным исключением и документируется там же.
- Плагин VST3/AU работает в чужом процессе хоста: в этом этапе отправляет только приложение. Плагин
  копит данные в общем каталоге, и они уйдут при следующем запуске приложения.
- macOS и Windows; сеть через `juce::URL`/`juce::WebInputStream` на фоновом потоке.

## Подходы

| Подход | Цена | Надёжность | Безопасность | Итог |
|---|---|---|---|---|
| **Cloudflare Worker + R2** | $0 (100k запросов/день, 10 GB) | высокая, без засыпания | токена нет: Worker пишет в R2 через binding | **выбран владельцем** |
| Hugging Face Space как приёмник + HF Dataset | $0 | бесплатный Space засыпает при простое | токен HF хранится в Space | отклонён |
| Supabase / Firebase free tier | $0 | Supabase ставит проект на паузу после недели простоя | anon-ключ в бинарнике, нужна настройка RLS | отклонён |
| Ручной экспорт JSON и вложение в GitHub issue | $0 | высокая | максимальная | данных почти не будет; отклонён |

## Что отправляется

Одна запись на подтверждённый сэмпл из `ml_feedback_samples`:

| Поле | Источник | Обработка |
|---|---|---|
| `recordId` | новый столбец `contribution_id` в `ml_feedback_samples` | случайный UUID на строку; новая версия записи с тем же `recordId` заменяет прежнюю при выгрузке |
| `features` | `features` BLOB | 14 нормированных значений 0..1 (`AdaptiveClassifier::extractFeatures`), квантование до шага 0.001 |
| `featureSchema` | версия раскладки вектора | целое; меняется при любом изменении `AdaptiveClassifier::extractFeatures` |
| `type` | `target_type` | как есть; флаг `typeIsCustom`, если тип не встроенный |
| `tags` | `tags` | как есть; у каждого тега флаг встроенный/кастомный |
| `key`, `bpm` | разрешённые smart-поля сэмпла, если есть | тональность строкой, темп с точностью 0.1 |

Длительность уже входит в вектор (`normDuration`), отдельного поля нет.

**Остаточный риск, принятый явно (решение исполнителя дизайна).** Квантованный вектор не обратим в
аудио, но, сравнив его с векторами известного коммерческого пака, можно с хорошей вероятностью узнать,
что у анонимной установки есть сэмпл из этого пака. Поскольку установка не связана ни с человеком, ни с
IP, риск принимается; `PRIVACY.md` говорит об этом прямо.

Обёртка пачки: `schema` (версия формата пачки), `installId`, `appVersion`, `os` (`mac`/`win`),
`sentAt`, `records[]`.

**Не отправляется никогда:** аудио, путь, имя файла и папки, `sample_id`, `file_hash`, имя пакета,
метаданные из файла (artist, comment и т.п.), имя пользователя и компьютера, язык и часовой пояс.
`file_hash` исключён намеренно: хэш содержимого позволяет установить, какие именно файлы есть у
человека.

Кастомные теги и типы — свободный текст, который вводит пользователь, и это единственное поле, где может
случайно оказаться что-то личное. Меры: длина ≤ 32 символа, обрезка пробелов, отбрасывание строк, похожих
на путь (`/`, `\`, `:`), e-mail или URL; окно предпросмотра показывает их явно.

`installId` — случайный UUID v4, генерируется при включении, хранится в настройках. Он нужен для
удаления своих данных и для ограничения веса одной установки при обучении. Отдельной кнопки «Сбросить
ID» нет: новый ID выдаёт только удаление (ниже), поэтому данные под старым ID никогда не остаются без
возможности их удалить.

## Как это работает

### Клиент (приложение)

- Новый модуль `core/contribute/`:
  - `ContributionPayload` — чистая функция «записи каталога → JSON пачки» с фильтрами выше; без сети,
    полностью покрывается тестами.
  - `ContributionUploader` — фоновая задача: при старте (с задержкой ~1 мин) и раз в 24 ч, если
    переключатель включён и согласие дано, берёт из текущего каталога записи с `updated_at` больше
    водяного знака этого каталога, режет на пачки по ≤ 500
    записей и ≤ 256 KB, отправляет `POST /v1/contribute`, при `2xx` сдвигает водяной знак. Ошибка сети или
    `5xx` — тихий повтор в следующий цикл с экспоненциальной паузой; `4xx` — запись в лог, пачка
    пропускается. Каждая пачка несёт `batchId` (UUID) — повтор той же пачки сервер не дублирует.
  - Удаление подтверждения (`removeFeedback`) ничего не отправляет; данные на сервере удаляются только
    целиком по кнопке.
- Каталог (миграция схемы): в `ml_feedback_samples` — столбец `contribution_id` (UUID, заполняется
  при вставке и для старых строк); новая таблица `contribution_state` с одной строкой — водяной знак
  `updated_at` этого каталога. Водяной знак живёт в самом каталоге, поэтому переключение
  `databasePath` ничего не теряет и не дублирует. Плагин пишет в тот каталог, который открыт у него;
  его записи уйдут, когда приложение откроет этот же каталог. Отдельного хранилища для плагина нет.
- Настройки (`AppSettings`): к существующему `contributeTrainingData` добавляются
  `contributionConsentVersion` (0 — не спрашивали), `contributionInstallId`, `contributionEndpoint`
  (по умолчанию адрес production Worker; переопределение только для тестов и разработки).
- Согласие:
  - Отправка идёт, только если `contributeTrainingData == true` **и** `contributionConsentVersion`
    не меньше текущей версии текста согласия.
  - Существующее `contributeTrainingData == true` согласием не считается: оно ставилось, когда
    документация обещала «ничего не отправляется». Такие пользователи тоже видят диалог.
  - Диалог показывается один раз после открытия каталога, если версия согласия устарела. Он
    тематический, как остальные диалоги приложения, с кратким объяснением, ссылкой на
    `docs/PRIVACY.md` и кнопками «Участвовать» / «Нет, спасибо». Текст прямо говорит, что уйдут и
    подтверждения, сделанные раньше. «Участвовать» включает переключатель, отказ или закрытие окна
    выключают его. Оба ответа записывают версию.
  - Включение переключателя в Settings без принятой текущей версии сначала показывает тот же диалог.
- История: после согласия водяной знак стартует с нуля, так что уходят и прежние подтверждения
  (решение исполнителя дизайна: это и есть основная ценность, а диалог говорит об этом явно).
- Settings → Library, рядом с переключателем:
  - «Показать, что будет отправлено…» — диалог с отформатированным JSON следующей пачки;
  - «Удалить мои отправленные данные…» — подтверждение, затем `DELETE /v1/contributions/{installId}`,
    затем новый ID и сброс водяного знака текущего каталога. Если переключатель остаётся включённым,
    данные уйдут заново под новым ID; диалог предлагает заодно выключить участие.
- Выключение переключателя мгновенно останавливает отправку; уже идущий запрос доводится или
  отменяется, водяной знак не сдвигается.
- Ни строки из пачки не пишется в лог приложения: только количество записей и HTTP-статус.

### Сервер (Cloudflare Worker)

- Код в репозитории: `services/contribute-worker/` (TypeScript, `wrangler`), под AGPL, с тестами
  (`vitest` + пул Workers).
- `POST /v1/contribute`:
  - `Content-Type: application/json`, тело ≤ 256 KB, иначе `413`;
  - строгая проверка схемы: неизвестные поля — `400`; размер вектора соответствует `featureSchema`;
    числа конечные и в разумных диапазонах; строки ≤ 32 символа; ≤ 500 записей;
  - ограничение частоты по IP (порядка 30 запросов в час) — `429`; IP используется только для этого и
    нигде не сохраняется;
  - запись в R2 как `raw/{installId}/{batchId}.json` (ключ по `batchId` делает повторы идемпотентными);
    сервер добавляет только `receivedAt`;
  - ответ `204`.
- `DELETE /v1/contributions/{installId}`: удаляет все объекты с префиксом `raw/{installId}/` и
  пишет надгробие `deleted/{installId}` (только ID и время). Ответ `204`, в том числе когда удалять
  нечего: по ответу нельзя узнать, существует ли такой ID. Последующие пачки с этим ID отклоняются с
  `410`, и клиент в ответ берёт новый ID.
- `GET /v1/health` — `200` для проверки после деплоя.
- Логи Worker: без тел запросов и без IP (не включать `console.log` тела, отключить или не использовать
  Logpush с заголовками).
- Секретов нет: доступ к R2 через binding в `wrangler.toml`.
- Деплой делает владелец со своего аккаунта Cloudflare (`wrangler deploy`); адрес вида
  `https://sonicator-contribute.<account>.workers.dev` попадает в `contributionEndpoint` по умолчанию.

### Выгрузка

Скрипт `services/contribute-worker/scripts/export` (через `wrangler r2 object` или S3-совместимый
доступ с ключом владельца, который хранится только у владельца) собирает все пачки в один JSONL для
следующего этапа и печатает отчёт: число установок, записей, частота кастомных тегов и типов.
Скрипт:

- оставляет для каждого `recordId` только запись с самым поздним `receivedAt`;
- пропускает всё, что подпадает под надгробия `deleted/*`.

Открытый датасет и обученные прототипы всегда пересобираются из R2 этим скриптом. Поэтому удаление
попадает в следующий выпуск датасета или модели. Копии, которые кто-то уже скачал раньше, отозвать
нельзя, и `PRIVACY.md` говорит об этом прямо.

## Проверка

- `[contribute]` тесты клиента: пачка не содержит путей, имён файлов, `file_hash`, `sample_id`;
  фильтр кастомных строк; округление; пачки режутся по лимитам; водяной знак двигается только при
  `2xx`; при выключенном переключателе, без согласия и с устаревшей версией согласия `Uploader` не
  создаёт ни одного запроса (подменный транспорт); водяной знак свой у каждого каталога; миграция
  заполняет `contribution_id` у старых строк; `410` приводит к новому ID.
- Тесты Worker: валидная пачка → `204` и объект в R2; повтор того же `batchId` → один объект;
  неизвестное поле, неверная длина вектора, NaN, длинная строка → `400`; > 256 KB → `413`; превышение
  частоты → `429`; `DELETE` удаляет префикс, пишет надгробие и отвечает `204` для несуществующего ID;
  пачка с удалённым ID → `410`. Тест скрипта выгрузки: последняя версия по `recordId`, надгробия
  применяются.
- Ручная проверка после деплоя: `GET /v1/health`, одна реальная пачка из приложения, её удаление кнопкой.

## Оставлено исполнителю

- Точные числа: интервалы, лимиты частоты, корзины длительности — в пределах указанного.
- Способ ограничения частоты в Worker (Rate Limiting binding или счётчик), если он бесплатен.
- Текст диалога согласия и `PRIVACY.md` — коротко и простым языком, на английском, как остальной UI.
- Раскладка модуля и имена классов клиента.
