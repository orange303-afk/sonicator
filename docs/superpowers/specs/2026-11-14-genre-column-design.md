# Колонка Genre — план и ТЗ

Дата: 2026-11-14. Статус: идея будущей функции; реализация не начата.

## Задача

Добавить в библиотеку Sonicator колонку `Genre`. Значение извлекается из метаданных аудиофайла и, если их нет или они неоднозначны, определяется по названиям файла и родительских папок. Пользователь должен понимать происхождение значения и иметь возможность исправить его вручную.

Это поле описывает **музыкальный жанр**, а не тип звука (`Kick`, `Pad`, `Riser`), структуру (`loop` / `one-shot`) или стиль отдельного инструмента. Не следует назначать жанр там, где данных недостаточно.

## Источники и приоритет

1. Ручное значение пользователя имеет высший приоритет и не перезаписывается переанализом.
2. Явный genre/style из встроенной метадаты файла или поддерживаемого sidecar — основной автоматический источник. Хранить исходное написание и нормализованное отображаемое значение отдельно.
3. Название ближайшей осмысленной папки и имя файла — дополнительные источники. Дальние родительские папки учитывать осторожно: название общей библиотеки или диска не должно автоматически назначать один жанр всем семплам.
4. Совпадение независимых источников может укрепить выбор. Конфликт сильных источников показывать как `Ambiguous`/пустое значение с доступными кандидатами, а не выбирать случайно.

Парсер имён должен распознавать жанровые слова и устойчивые синонимы как отдельные токены, с учётом разделителей, регистра и Unicode. Не угадывать по коротким подстрокам внутри других слов. Первоначальный словарь жанров и синонимов хранить версионированно; пользовательские жанры не терять при обновлениях. Не выводить жанр только из BPM, тональности или типа семпла.

## Поведение UI

- Колонка `Genre` доступна в таблице библиотеки с сортировкой и текстовым поиском/фильтром по жанру; пустое значение отображается как `—`.
- В карточке/подсказке показывать итоговое значение, источник (`metadata`, `folder`, `filename`, `manual`), исходный фрагмент и конфликтующие кандидаты.
- Правый клик по одному или нескольким файлам → `Genre ▶`: назначить жанр, очистить ручное значение, выбрать `Unknown`. Массовое действие относится только к выбранным строкам.
- `Unknown` как ручной выбор отличается от отсутствия результата: он запрещает автоматическую догадку, пока пользователь не снимет override.
- После изменения файла или пути автоматическое значение помечается устаревшим и пересчитывается в фоне. Во время пересчёта последнее значение не выдаётся за актуальное.

## Модель данных и интеграция

Использовать принципы текущего smart-анализа: отдельные кандидаты с extractor ID/версией и источником, итоговый результат с состоянием, ручной override отдельно. Расширение схемы должно сохранять стабильные sample ID, теги, звёзды и текущие результаты Type/BPM/Key. Индекс/запрос для сортировки и фильтра должен работать на большом каталоге без декодирования аудио на UI-потоке.

Возможный будущий компонент `Metadata Importer` или `Tagging Provider` сможет давать кандидатов Genre через версионированный API пользовательских компонентов, но не менять ручное значение напрямую. Связанный документ: `docs/superpowers/specs/2026-11-14-user-plugins-design.md`.

## Этапы

1. Исследовать реальные метаданные и имена в библиотеке; собрать небольшой набор примеров с ожидаемым жанром, отсутствием жанра и конфликтами.
2. Определить словарь/синонимы и правила разрешения кандидатов; добавить хранение источника, состояния и ручного значения.
3. Добавить фоновое извлечение из метадаты, имени файла и пути с инкрементальным обновлением.
4. Добавить колонку, сортировку/поиск, просмотр происхождения и массовое ручное исправление.
5. Проверить качество на сохранённом наборе примеров и на большом каталоге; расширять словарь только по подтверждённым ошибкам.

## Критерии приёмки

- Файл с явным Genre в метадате получает это значение с правильным источником.
- Файл без Genre, но с однозначным жанром в имени или ближайшей папке, получает значение; нерелевантные или конфликтующие названия не приводят к уверенной догадке.
- Ручное значение и `Unknown` переживают переанализ, переименование и пересканирование; очистка override возвращает автоматическое значение.
- Сортировка и поиск по Genre работают на полном каталоге; колонка не тормозит прокрутку.
- Изменение файла или пути обновляет кандидатов без потери других полей и пользовательских данных.
