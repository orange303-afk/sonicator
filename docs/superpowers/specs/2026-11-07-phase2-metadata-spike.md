### Ableton ASD (Live 12, version byte 6)

Выборка 4 003 ASD:

- заголовок и schema разобраны: 4 001 (100%);
- **warp-маркеров ≥ 2: 31 файл (0.8%)**;
- `AufTaktData.UnbiasedTempoEstimate`: `IsSet = true` в 49 файлах, но **значение tempo = 0.0 во всех 49**;
- вычислимый темп по warp-маркерам: 31 файл, все 20–400 BPM, переменного темпа не обнаружено;
- `frame_count` ASD совпал с числом кадров WAV в **2 995 из 2 995** сравнимых случаев.

Вывод: в этой библиотеке ASD — **не источник BPM**. Он полезен как индикатор устаревания sidecar (`frame_count`) и как редкий источник warp-темпа (0.8%). Наличие полей в ASD не означает пригодного значения — это подтверждено измерением.

### SoundFont 2

SF2 в библиотеке — один пакет E-MU Emulator II (1 638 файлов) и 1 файл из `_presets`:

- 61 файл в основной выборке, 300 в дополнительной;
- RIFF/pdta разобраны: 300/300;
- размер: median 0.84 MB, p90 ~1.0 MB, max 1.1 MB;
- пресетов: median 3–4, max 30;
- **bank 128 встречается редко** (1 банк в выборке);
- drum-подобные пресеты находятся по именам (`Drums`, `Big Drum Kit`, `PERC SET`, `KIT #1` и т. п.);
- drum-пресеты заданы **key-range зонами**: например `Big Drums` → key ranges 79–96 и 60–77;
- velocity-слоёв в этой коллекции не обнаружено;
- stereo-linked samples: 0;
- sample original pitch: 60 у всей коллекции (это mapping, не тональность).

Вывод: для этой библиотеки нужен renderer, соблюдающий **key ranges** и sample pitch; bank 128 нельзя использовать как единственный признак drum-kit.

## Решения, которые следуют из spike

1. **BPM**: metadata-first даёт ~16% для WAV, но 100% для Apple Loops и RX2. Для остального нужен DSP-анализ; нельзя заполнять BPM по номеру в имени.
2. **Key**: metadata даёт ~3%. Без DSP Key будет почти всегда unknown. DSP pitch/key — обязательная часть первого среза, а не «later».
3. **Type**: имена дают ~33% строгих совпадений, папки добавляют контекст, но требуют калибровки и ручных overrides.
4. **ASD** читать как источник только при валидных warp-маркерах; `UnbiasedTempoEstimate = 0` не считать значением. `frame_count` использовать для staleness.
5. **ACID/`smpl`/`inst`** — sampler metadata; не превращать в musical key.
6. **IKEY** — keywords; не классифицировать как key без явного разбора.
7. **REX2**: GLOB tempo и SLCE boundaries пригодны; 2 файла превышают 128 слайсов; нужен явный лимит/сообщение.
8. **SF2**: drum-пресеты определять по имени + bank 128 + фактическим key-range зонам; renderer обязан соблюдать key ranges, sample pitch, velocity ranges (даже если в этой коллекции их нет) и mono/stereo links.
9. **Строгая выборка**: предыдущая эвристика «55% type» не подтверждается строгими границами токенов; в отчёте нельзя обещать больше измеренного.

## Ограничения spike

- Выборка стратифицирована по пакетам, но библиотека неоднородна; доли не являются гарантией для другой библиотеки.
- MP3/OGG теги не разбирались глубоко: BPM/key в них не подтверждены.
- xattrs/Spotlight, `.als/.adg` и архивы не разбирались.
- SF2-коллекция в этой библиотеке не содержит GM-банков; вывод о drum-превью ограничен наблюдаемыми банками.
- Реальные аудиобуферы RX2/SF2 в этом spike не декодировались; проверялись структуры и metadata.
- Windows и Intel macOS не проверялись.


## Проверка C++-реализации на реальных файлах

После переноса парсеров в `core/smart` выполнен opt-in тест:

```sh
SONICATOR_METADATA_ROOT=/Volumes/1TBSSD/samples \
  build/tests/SonicatorTests '[.real-metadata]'
```

Результат: 120 WAV, 120 AIFF, 120 RX2, 120 ASD; 0 структурных ошибок; 120 валидных BPM-кандидатов; 2510 playable REX2 slices; все численные значения конечны и в допустимых диапазонах. Это подтверждает, что C++-порт читает реальные файлы так же безопасно, как исследовательский скрипт.
