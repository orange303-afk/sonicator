# Sonicator — Batch Processing v1: подробное техническое задание

Дата: 2026-11-15. Статус: проект на согласование, не разрешение на реализацию.
Документ подготовлен в Plan mode; код и документы репозитория не изменялись.

## 1. Назначение и связь с предыдущим ТЗ

Дать пользователю один инструмент для пакетной конвертации и подготовки аудиофайлов:
выбрать файлы/папку, настроить последовательность операций, проверить один пример,
сохранить результаты в нескольких форматах и получить понятный отчёт.

Основания:
- внешний бэклог: `~/Documents/orange303/Sonicator Features.md`, многофункциональный конвертер;
- общее ТЗ: `docs/superpowers/specs/2026-11-14-batch-audio-converter-design.md`;
- текущие `AudioFileWriter`, `NormalizeService`, `registerSonicatorFormats`, `CommandRegistry`.

Этот документ конкретизирует **первый законченный этап**, а не отменяет общий замысел.
При конфликте по объёму v1 действует этот документ; остальные возможности остаются будущими.
Приведённые ниже значения по умолчанию и технические решения — предложения автора для
согласования, а не ранее подтверждённые пожелания владельца.

## 2. Объём поставки

### Входит

- `Batch Processing...` для строки, выделения и физической папки библиотеки, рекурсивно.
- Обычные отдельные аудиофайлы с подтверждённым потоковым PCM reader.
- Вывод WAV, AIFF, FLAC; выбор нескольких форматов одновременно.
- Частота, mono/stereo, разрядность, FLAC compression level, dither.
- Упорядоченная цепочка Remove DC, Trim silence, Normalize, Gain, Fade in, Fade out.
- Предпросмотр одного источника, сохранение пресетов, прогресс/отмена, итоговый отчёт.
- Только новые копии; безопасная замена ранее существующего выходного файла — отдельная политика.
- Тесты, независимое ревью, release-сборка macOS; Windows — проверка через доступный CI.

### Не входит

- Перезапись оригиналов, удаление/перемещение входных файлов.
- Split в этой цепочке: существующий Split by silence продолжает работать отдельно.
- MP3/OGG и другие выходные кодеки; их отсутствие не мешает принимать поддерживаемые lossy-входы.
- Вложенные объекты банков, инструменты, REX, tracker songs и содержимое образов; для них остаётся Extract.
- LUFS/true-peak normalization, limiter, time stretch, pitch shift, VST/компоненты обработки.
- Интеграция Finder/Explorer, очередь нескольких заданий, возобновление после перезапуска.
- Автоматическое наследование тегов/Genre/ручных исправлений новыми файлами.

## 3. Основные пользовательские сценарии

1. Несколько WAV → только FLAC без обработки: несколько самостоятельных lossless-копий.
2. Папка → Remove DC → Trim → Normalize → Fade out → WAV и FLAC с сохранённой вложенностью.
3. Стереофайлы → mono, 48 кГц, WAV 24-bit; исходники остаются неизменными.
4. Создать пресет подготовки семплов и повторно применить к другому выделению.
5. Отменить длинное задание: завершённые результаты остаются, незавершённые временные файлы удаляются.

Простая конвертация — цепочка без включённых операций. Она всё равно создаёт копию;
`unchanged` у операции не означает пропуск выбранной конвертации.

## 4. Состав входов и снимок задания

### 4.1 Строки и выделение

- Обрабатывать ровно снимок выделенных строк на момент открытия диалога.
- Не читать выделение повторно после Start и не зависеть от текущей страницы таблицы.
- Игнорируемые пути исключать даже при включённом Show ignored; объяснять причину.
- Если строка представляет объединённую mono L/R-пару, v1 разворачивает её в оба физических
  mono-файла, без скрытого создания стереофайла. Число входов и это правило видны в диалоге.

### 4.2 Папка

- Охват — уже каталогизированные физические файлы папки и всех её подпапок.
- Поиск, звёзды, теги, скрытие дублей, Hide empty и пагинация охват не ограничивают.
- Учитывать `ignored_paths`; включать скрытых физических партнёров stereo pairs.
- Не сканировать диск заново и не включать появившиеся после снимка файлы. Для новых файлов
  пользователь сначала запускает Scan/New files.
- Виртуальные All samples и узлы образов не являются допустимыми папками для команды.

### 4.3 Пригодность источника

- Проверять существование, обычный файл, доступ к чтению, reader, положительные длину/частоту,
  конечные значения частоты, целое число Гц и 1–2 канала. Расширение само по себе не является доказательством.
- Список кандидатов строить из обычных аудиоформатов, а не через AudioEngine, который умеет
  проигрывать также инструменты и целые tracker songs. Не добавлять формат только потому, что его можно прослушать.
- Встроенные WAV/AIFF/FLAC/OGG/MP3 и VOC/одиночные EBL допускаются лишь когда общий reader
  подтверждает полное одиночное аудио. Проверить каждый заявленный формат фикстурой.
- Каталоговая запись с `container_path`, синтетический путь или metadata-only формат исключается.
- Более двух каналов — `unsupported_channels`, без неявного downmix/отбрасывания каналов.
- Пустой файл — `empty_source`, отсутствующий — `missing_source`, повреждённый — `decode_failed`.
- Символические ссылки на входы в v1 пропускать с `symlink_source_unsupported`, не следовать им молча.
  Hard links распознавать как одну физическую идентичность для защиты путей, но отдельные выбранные
  имена могут создавать отдельные результаты; это не скрытая дедупликация библиотеки.
- При несохранённых изменениях выбранного источника в редакторе исключать его с
  `unsaved_editor_changes`; не экспортировать устаревшие байты вместо видимого результата.
- В результатах подготовки хранить как принятые входы, так и каждый пропуск с причиной.
- До анализа/каждого повторного прохода/публикации сверять размер, mtime и доступную физическую
  идентичность источника. Изменение → `source_changed`, текущий temp удаляется. Это не защита от
  злонамеренной подмены с восстановленными атрибутами; такого обещания v1 не даёт.

## 5. Выходные настройки

### 5.1 Форматы

- WAV: `.wav`, PCM 16/24-bit или IEEE 32-bit float.
- AIFF: `.aif`, PCM 16/24-bit. 32-bit float недоступен, не заменяется молча на 24-bit.
- FLAC: `.flac`, integer PCM 16/24-bit, уровень сжатия 1–8, по умолчанию 5.
  Уровень 0 не показывать, пока не проверено, что JUCE writer действительно устанавливает его,
  а не оставляет внутренний уровень по умолчанию.
- Разрядность задаётся отдельно для каждого выбранного формата; нельзя применять float к FLAC.
- `Same as source` для разрядности допустим только при точном соответствии исходного представления
  выбранному writer. Для float→FLAC, integer32→поддерживаемый набор и lossy-входа показывать
  необходимость явного выбора 16/24-bit, не делать скрытый fallback.
- Первоначальный пресет: WAV 24-bit, другие форматы выключены.
- Число ожидаемых результатов без ошибок/пропусков = принятые источники × выбранные форматы.
- Ограничения длины контейнера проверять до записи: в v1 без RF64 WAV/AIFF с ожидаемым
  размером контейнера ≥ 2^32 байт не создавать; FLAC проверять по пределу writer/frame count.
  Ошибка конкретного формата не должна запрещать другой поддерживаемый выход этого источника.

### 5.2 Частота и каналы

- Общая настройка частоты: Same as source; 44 100, 48 000, 88 200, 96 000, 192 000 Гц.
- Same as source проверять отдельно для каждой пары вход/формат; неподдерживаемую частоту
  явно показывать в preflight. Применимость определяет проверенный контракт кодека, не список UI.
- Общие каналы: Same as source, Mono, Stereo. Mono→Stereo дублирует канал.
- Stereo→Mono: `(L + R) / 2`, double при вычислении суммы, без скрытой нормализации.
  Антифазное содержимое может взаимно уничтожиться; показывать это предупреждение рядом с Mono.
- Channel conversion и Resample идут после пользовательской цепочки и видны как фиксированные
  выходные этапы, не выдаются за переставляемые шаги.
- При изменении частоты сохраняются высота тона и время; это не playback-rate/pitch shift.

## 6. Операции: точная семантика

Максимум 16 шагов. Можно добавлять, выключать, удалять, дублировать и перемещать шаги.
Дубли допустимы и выполняются последовательно. Выключенный шаг не анализируется и не влияет
на длину, метаданные, dither или оценку результата.

Все операции работают над потоком текущего промежуточного результата на частоте источника.
Тишина определяется по максимуму абсолютных значений **по всем каналам**, а не по среднему stereo.
Глобальные суммы/счётчики — double/int64; рабочее аудио — float32. Не обещать bit-perfect
сохранение 32-bit integer входа при прохождении через float32. Отдельный byte-copy fast path не обязателен.

### Remove DC offset

- Для каждого канала вычислить среднее текущего результата компенсированным суммированием
  в double; вычесть это среднее только из соответствующего канала.
- Это офлайновое вычитание среднего, не high-pass filter и не рекурсивный фильтр.
- Полностью постоянный сигнал может стать нулём. Повышение пика после удаления DC не скрывать.
- В отчёте: исходное смещение каждого канала и факт изменения.

### Trim silence

- Threshold: −120…−6 dBFS, по умолчанию −60 dBFS. Padding: 0…1000 мс, по умолчанию 5 мс.
- Звуковым считать кадр, если хотя бы один канал строго выше линейного порога.
- Найти первый/последний звуковой кадр. Сохранить `[first−padding, last+1+padding)` с ограничением
  границами текущего результата. Padding переводить в кадры через `ceil(ms * Fs / 1000)`.
- Внутренние паузы не удалять. Нет звуковых кадров → сохранить текущую длину целиком,
  статус шага `unchanged_silent`, никогда не создавать файл нулевой длины.
- Однокадровое содержимое сохранять; следующий Fade не должен уничтожать его молча.

### Normalize

- Peak target: −24…0 dBFS, по умолчанию −0.1 dBFS. Это sample peak, не LUFS и не true peak.
- `peak = max(abs(sample))`; один коэффициент `10^(targetDb/20)/peak` на все каналы.
- Peak ≤ 1e−6 → no change. Нулевой сигнал не делить на ноль, шум не добавлять этой операцией.
- Normalize относится к позиции шага. Последующий Gain/Resample может изменить конечный пик;
  нельзя незаметно нормализовать ещё раз в конце. При уже нужном пике результат сохраняется.

### Gain

- −60…+24 dB, по умолчанию 0 dB; коэффициент `10^(gainDb/20)`, общий для каналов.
- Никаких встроенных compressor/limiter/auto-normalize. 0 dB — точный bypass шага.
- Потенциальный клиппинг показывается в UI; реальный проверяется после всей цепочки и ресемплинга.

### Fade in / Fade out

- 0…10 000 мс, по умолчанию 5 мс; кривые Linear и Cosine, первоначально Linear.
- `M = min(round(ms * Fs / 1000), currentFrames)`; 0 мс и M < 2 — no change с объяснением.
- Fade in на первых M кадрах: `t = n/(M−1)`; Linear `g=t`, Cosine `g=(1−cos(pi*t))/2`.
- Fade out на последних M кадрах: те же кривые в обратном порядке. Конечный кадр равен нулю.
- Если Fade in и Fade out перекрываются, применяются оба коэффициента в порядке шагов;
  длительность не меняется и скрытого сокращения fade нет.
- Привязка всегда к текущим границам после предыдущих Trim. Не рассчитывать envelope заново
  от начала каждого блока: между блоками не должно быть разрывов.

### Порядок и штатные пресеты

- Начальное состояние — пустая цепочка, то есть конвертер без обработки.
- Встроенный `Sample cleanup`: DC → Trim(−60 dB,5 ms) → Normalize(−0.1 dB) → Fade out(2 ms,Linear).
- `Normalize → Gain(+6)` не эквивалентен `Gain(+6) → Normalize`; тест обязан это показать.
- Частота и число кадров каждого шага входят в приготовленный план, а не пересчитываются
  независимо в каждом выходном writer.

## 7. Ресемплинг, квантование и клиппинг

### Ресемплинг

- Предложенное решение: статическая libsamplerate 0.2.2, `SRC_SINC_BEST_QUALITY`, потоковый
  `src_process`; лицензия BSD-2-Clause, включить лицензию/атрибуцию в About/дистрибутив.
- Зафиксировать архив/коммит и SHA256, не зависеть от установленного Homebrew или сети в runtime.
- Не использовать линейную интерполяцию или sinc без anti-alias cutoff как «качественное» понижение частоты.
- Состояние непрерывно между блоками; на источник/новый проход — новое состояние. EOF корректно
  подаётся и дренируется. Короткие входы, хвост и единичный кадр не теряются.
- Контракт длины: `Nout=max(1,llround(NafterSteps * Fout / Fin))` с проверкой переполнения.
  Обёртка отдаёт ровно Nout кадров: детерминированно обрезает служебный хвост/дополняет только
  документированный конечный zero-extension при необходимости. Значительная нехватка кадров — ошибка,
  не повод молча дописать произвольную тишину; порог и EOF-поведение закрепить reference-тестами адаптера.
- Компенсацию задержки/начала проверить импульсом и сравнением блочной и неблочной обработки.

### Dither и integer output

- Настройка: Auto (по умолчанию), TPDF, Off. Noise shaping в v1 отсутствует.
- Auto включает TPDF при уменьшении точности, float/lossy→integer и после реальных операций
  над амплитудой/ресемплинга; для неизменённого PCM16→PCM24 или PCM24→PCM24 шум не нужен.
  Если Same as source выявляет неясную точность lossy-входа, требовать явную output depth.
- TPDF: перед округлением в единицах целевого LSB прибавить U1−U2, где U1/U2 независимы в [0,1).
  Для B-bit integer: `q=round(x*2^(B−1)+dither)`, ограничение допустимым signed B-bit диапазоном.
- Integer writer получает уже квантованные left-aligned int32 слова; исключить повторный dither
  и знаковый сдвиг отрицательного C++ integer. Для float WAV dither не применяется.
- Отдельный PRNG на источник/формат, фиксированный seed из идентичности входа и настроек;
  его последовательность не зависит от размера блока и выходного имени. Для одинакового потока
  float-отсчётов квантование воспроизводимо; различия SRC между разными разбиениями/платформами
  оцениваются по численному допуску, не обещанием bit-identical encoded файла на всех сборках.
- В тестах случайность можно задавать seed; в продуктовых классах не делать test-only методов.

### Клиппинг

- После цепочки, channel conversion и SRC выполнить анализ конечных отсчётов до публикации.
- По умолчанию integer-выход с пиком > 1.0 + 1e−7 не записывать: `clipping_prevented` с величиной
  пика и советом уменьшить Gain/target. Законченные другие выходы не удалять.
- Явный флажок `Allow integer clipping` по умолчанию выключен; при включении насыщение
  документируется в отчёте числом затронутых исходных отсчётов, без скрытого limiter.
- Float WAV может сохранить значения > 0 dBFS с предупреждением `float_over_unity`.
- SRC может дать overshoot после Normalize; финальный safety-анализ нужен и в этом случае.
- NaN/Inf на входе или после любого этапа → ошибка источника; не подменять нулями и не кодировать.

## 8. Архитектура потоковой обработки и ресурсы

- Нельзя использовать `AudioEditBuffer::load` как пакетный движок: он хранит весь файл/undo в RAM.
- Один job worker, один физический источник и один выходной encoder одновременно.
- Размер блока по умолчанию 16 384 кадров; все позиции/длины — int64 с проверенной арифметикой.
- Цепочка — повторно читаемый поток. Перед глобальным шагом анализируется уже приготовленный
  префикс: DC узнаёт среднее, Trim границы, Normalize пик. Затем параметры этого шага фиксируются.
- Допустимы повторные проходы по исходнику. В v1 не требуется однократное декодирование для
  всех трёх выходов; допустим один render на формат. Не сохранять каждый шаг в длинный PCM temp.
- Потребление аудиобуферов не зависит от длительности. Ориентир дополнительной рабочей RAM
  движка ≤ 64 MiB для stereo, 16 шагов и любого поддержанного отношения частот; отдельно
  ограничиваются маленькие preview-файлы. Измерять аллокации/буферы, а не общий RSS приложения.
- Список входов O(N) допустим, аудио O(duration) в RAM — нет. Более 100 000 входов отклонять
  до создания большого задания с предложением выбрать подпапку. Запрос папки ограничивается
  первыми 100 001 physical entries; превышение лимита обнаруживается без загрузки всего каталога.
- Cancel проверяется при обходе входов, в каждом блоке анализа/render/validation и перед commit.
  На обычных локальных тестовых файлах реакция ≤ 1 с; зависший системный I/O не маскировать
  обещанием жёсткого realtime-таймаута.
- Прогресс отражает Preparing / Analyzing / Encoding / Validating / Publishing и реальные
  счётчики. При неизвестной работе — indeterminate; нельзя выдавать ложные 99% на весь анализ.

## 9. Назначение, имена и защита данных

### Пути

- По умолчанию `Save next to originals`: `<stem> processed.<ext>`.
- Выбранная общая папка: сохранить относительный путь в выбранной исходной папке, затем
  `<stem> processed.<ext>`. Для выделения из одного корня использовать этот корень как базу;
  без зарегистрированного корня — родитель источника.
- Для нескольких исходных корней добавить стабильную группу `<root-name>-<root-path-hash8>`.
  Длиннейший зарегистрированный корень определяет базу; одинаковые имена корней не сливаются.
- Коллизии внутри задания разрешать детерминированно по отсортированному полному пути входов.
  При одинаковом stem у WAV/MP3 первый результат не должен быть перезаписан вторым.
- Не допускать выход за выбранную папку через `..`, недопустимые компоненты или symlink-каталоги.
  Путь назначения и каждый существующий родитель проверяются, включая конечную проверку перед commit.

### Политики коллизий

- Rename (default): `processed`, `processed 2`, `processed 3` и т.д. Резервировать пути внутри задания.
- Skip: существующий выход пропускается, причина видна в отчёте; источник не считается ошибочным.
- Replace existing output: отдельное подтверждение числа замен, после полной записи и проверки temp.
- **Ни одна политика не разрешает заменить какой-либо вход задания**, в том числе пропущенный
  вход, другой источник, hard link на него или путь, который стал такой ссылкой перед commit.
- Для `Replace` фиксировать идентичность прежнего выхода; если он изменён после preflight,
  отказать с `destination_changed`, а не заменить более новый файл.
- При Rename внешняя гонка за именем приводит к следующему свободному имени; операция
  публикации должна быть no-clobber. Предварительный exists() не является защитой от гонки.

### Публикация

- Temp с уникальным именем создаётся в конечной директории. После закрытия encoder открыть
  новым reader, проверить контейнер, rate/channels/bit-depth/float flag, точное число кадров,
  прочитать весь поток чанками для обнаружения позднего decode failure и NaN/Inf.
- Только после validation — same-volume atomic rename/replace. Никакого delete-old-then-copy
  и fallback на неатомарную замену. Если файловая система не даёт требуемую семантику, отказать.
- Граница Cancel/commit определена: отмена до commit сохраняет старый выход; после успешного
  commit результат считается completed, даже если Cancel поступил сразу следом.
- При ошибке старый выход и входы сохраняются; удаляется только собственный незавершённый temp.
- Не обещать транзакцию на всю партию или сохранность при физической потере питания.
  Успешно опубликованные результаты остаются при последующей ошибке/отмене.
- При аварийном завершении могут остаться temps с job ID; удалять их при следующем запуске
  только по собственному манифесту и подтверждённому временному шаблону. Не чистить пользовательские папки маской.

### Диск

- До Start оценить верхнюю границу по длине/форматам: для FLAC использовать несжатый PCM
  плюс запас, не обещать коэффициент сжатия. Учесть контейнеры, temps и preview.
- Резерв: max(256 MiB, 10% оценки). При известном недостатке места Start заблокирован;
  при невозможности узнать место — явное предупреждение, не «места достаточно».
- Повторять проверку перед каждым выходом. ENOSPC даёт ошибку/пропуски на затронутом диске;
  не удалять уже завершённые выходы ради продолжения. На другом доступном назначении можно продолжать.
- Ночные проверки: только небольшие фикстуры/копии, суммарный тестовый вывод ≤ 1 GiB;
  не запускать партию на `/Volumes/1TBSSD/samples` целиком.

## 10. Метаданные и каталог

- Не копировать целиком `reader.metadataValues` в произвольный writer.
- Политика v1: проверенный whitelist для WAV→WAV (совместимые INFO-поля, sampler root,
  проверенные smpl loop/cue при неизменной временной сетке). Неверифицированные chunks не переносить.
- При Trim с реальным изменением длины или SRC loop/cue/BWF time-reference **удаляются с
  предупреждением**, а не остаются со старыми позициями. Root pitch можно сохранить.
- Для AIFF/FLAC и cross-container в v1 не обещать сохранение текстовых/временных метаданных:
  явно показать `metadata_not_preserved` и перечислить обнаруженные теряемые категории.
- Не выдумывать BPM/key/Genre из каталога и не экспортировать ручные override без отдельного решения.
- `.asd`, `.pk` и другие sidecars не менять и не копировать к результатам; исходники не меняются,
  поэтому старые sidecars по-прежнему принадлежат только оригиналам.
- Каталог исходников остаётся байтово/семантически неизменным этой операцией: ID, теги, звёзды,
  Genre, Type, BPM, Key, feedback и overrides не редактируются.
- После успеха **не индексировать автоматически**. В отчёте предложить `Scan new files` только
  для затронутых директорий внутри зарегистрированных корней, после освобождения worker.
  Использовать bounded `startFoldersNewOnly`, не глобальный rescan. Для внешнего назначения
  предложить `Open output folder`; добавление нового корня — отдельное явное действие.
- Завершённые выходы получают обычный независимый анализ при таком сканировании, не наследуют
  ID/ручные поля/feedback источника. Temp/preview-файлы никогда не попадают в индексирование.

## 11. Диалог и preview

### Состав диалога

- Заголовок и источник: «N catalogued files, M eligible, K skipped», путь/выделение, рекурсивность.
- Область Steps: упорядоченные строки с enable, типом, параметрами, Up/Down, Duplicate, Remove;
  Add step, Preset, Save preset, Delete custom preset.
- Output: destination, три флажка форматов и отдельные depth/FLAC level, общие rate/channels,
  dither, clipping policy, conflict policy, пример пути и ожидаемое число выходов.
- Preview: выбор одного принятого файла, Prepare preview, Original, Processed, Stop, краткие
  измерения длины/peak/DC и предупреждения. После изменения настроек старый preview помечается устаревшим.
- Footer: оценка места, Start, Cancel/Close. Start недоступен при статически невалидном запросе,
  нуле принятых файлов, выборе 0 форматов, незавершённом preflight или несовместимом writer.
- При отдельных source-specific несовместимостях показать их как пропуски/failed outputs;
  разрешить обработать остальные только после явного видимого резюме.
- Использовать Manrope, текущие theme/design tokens, `dialogs::Surface` и themed controls;
  не стандартный «голый JUCE». Встроенные viewports без обрезания при 100%/125%.

### Preview: ограниченный и честный

- Вычислить глобальные параметры цепочки на полном выбранном файле в worker; во время этого
  показывать анализ и разрешать отмену. Не выдавать локальную Normalize/DC по 10 секундам за
  результат полной партии.
- После подготовки создать короткие dry/wet WAV float32, максимум 10 секунд аудио каждый,
  начиная с первого кадра, который остаётся после Trim; dry соответствует исходному участку.
- Wet использует тот же render/каналы/SRC, что партия, но без integer dither/codec roundtrip.
  Подпись: «Processing preview; output quantization is not auditioned».
- A/B не обязан быть sample-aligned после изменения границ, но выбирает соответствующий
  источник/участок и не включает тайно первые 10 секунд обрезанной тишины в dry.
- `BatchPreviewService` готовит файлы, UI/owner прослушивает через существующий AudioEngine,
  не создавая второе аудиоустройство. Только одно preview одновременно.
- Перед takeover остановить текущий preview и запросить решение по несохранённому редактору.
  Если редактирование не закрыто, A/B недоступно, но сама обработка других пригодных файлов возможна.
- Закрытие/Start останавливает A/B, освобождает reader, удаляет только свои temps; прежнюю
  выбранную запись при возможности загрузить без autoplay. Temporary paths не сохранять как lastSamplePath.

## 12. Пресеты и настройки

- Хранить в `<settings-directory>/batch-presets.json`, schemaVersion=1, отдельно от SQLite.
  Путь выводить из активного `SettingsStore::file()`, тесты не касаются живых настроек.
- Пресет хранит id/name, ordered steps с enabled/params, outputs, sample rate/channels,
  dither/clipping/conflict policy; не хранит выделение, source paths или подтверждения Replace.
- Выбранный destination не включать в переносимый пресет; последние destination/rate/etc можно
  хранить отдельным `lastUsed` в том же документе. Новое задание всё равно заново подтверждает Replace.
- Сохранение атомарное, без потери существующего файла при ошибке. Названия trim/nonempty,
  дубли имён без учёта регистра требуют явного Replace preset. Встроенные пресеты неизменяемы.
- Повреждённый JSON: показать ошибку и штатные пресеты, не перетирать повреждённый файл автоматически.
  Более новая версия: открыть read-only/объяснить; неизвестные шаги/поля не заменять молча.
- Восстановление последнего состояния не запускает задание и не включает запись оригиналов.

## 13. Потоки, владение и конкурирующие операции

- SonicatorCore не включает UI; BatchService владеет worker, immutable request и результатами.
- UI poll прогресса ~10 Гц, без callbacks на каждый аудиоблок. SafePointer и generation ID
  защищают от устаревших результатов preflight/preview после изменения параметров или закрытия.
- На v1 диалог модальный для Sonicator, но не блокирует message loop. Во время работы
  параметры заморожены. Закрытие предлагает Stay / Cancel job and close; молча бросать worker нельзя.
- Один активный Batch/preview/preflight на владельца. Preview и job не выполняются параллельно;
  Start отменяет и дожидается завершения preview вне message-thread join.
- Взаимно исключить файловые writer-задачи, сканирование/анализ, Split, Extract, Normalize,
  bulk tagging/AutoTag и bulk Genre. Повторно проверить доступность в handler, а не только в меню.
- Catalog switch, relocation, удаление папки и сохранение редактора при активном job блокируются
  с объяснением; публичные API не должны обходить защиту. Простое воспроизведение может оставаться доступным.
- Shutdown: signal cancellation → worker завершает текущий bounded участок → join → остановка
  preview/readers → cleanup temps → уничтожение repository/engine. Не держать DB/UI mutex во время join.
- VST3/AU spike в v1 не получает Batch UI/новые device paths; не заявлять поддержку хостового режима.

## 14. Отчёт и состояния

- На уровне output: completed, skipped, failed, cancelled; до него отдельные source/step outcomes.
- Структурированные error codes: missing_source, unsupported_source/channels, decode_failed,
  source_changed, destination_changed, unsafe_destination, insufficient_space, clipping_prevented,
  encode_failed, validate_failed, publish_failed, cancelled; не парсить английскую строку для логики.
- Сохранять фактический destination, формат, параметры, длительность/кадры, peak, step outcomes,
  предупреждения, время начала/конца, recipe fingerprint и связь с источником.
- Итог различает «всего источников» и «выходов»; частичный успех допустим и явно виден.
- После Cancel не начатые запланированные выходы отражаются как cancelled/not_started, не исчезают.
- Отчёт остаётся в диалоге и экспортируется по явному действию в JSON/UTF-8 text. Локальная
  диагностическая копия в job cache: максимум 20 отчётов/30 дней, без аудио; можно удалить через UI.
- Не отправлять отчёты/пути/аудио по сети. Лог — без sample buffers и без неограниченных stack traces.

## 15. Критерии приёмки и численные проверки

1. Один источник × WAV+FLAC = два читаемых файла с выбранными параметрами; источник byte-identical.
2. Все шесть операций, отключение/дубли/перестановка соответствуют разделу 6; block size 1/257/16384
   не меняет семантику. Для фиксированного seed и одинакового float input quantizer воспроизводим;
   SRC streams сравниваются с абсолютным допуском 2e−6, без обещания bit identity после округления.
3. Trim знает обе stereo-дорожки, сохраняет однокадровый сигнал и all-silent длину; DC constant→0.
4. Normalize без SRC достигает target с абсолютной ошибкой peak ≤ 2e−6 до квантования;
   integer-проверка учитывает ±2 LSB и dither. Stereo ratio не изменяется.
5. Fade endpoints/границы блоков/перекрытие проверены на явных массивах; Gain порядок проверен численно.
6. SRC: 44.1↔48, 96→44.1, 192→48; точный Nout, 1 кГц steady-state amplitude error ≤0.1 dB,
   начало импульса не получает произвольного сдвига. Для 96→44.1: 30 кГц вход подавлен до <−80 dBFS
   вне переходных участков; тихий вход не получает DC/NaN. Тестировать EOF и короткие файлы отдельно.
7. Quantizer: целевые границы, 16/24-bit, отсутствие double dither; TPDF mean <0.02 LSB,
   variance 1/6 LSB² ±5% на ≥100 000 значений до округления, стабильность seed и channel state.
8. Antiphase Stereo→Mono даёт ноль; Mono→Stereo совпадает побитно по каналам до encoding.
9. Клиппинг после Gain и после SRC не прячется; integer reject/explicit clipping/float warning
   дают разные ожидаемые состояния и не портят уже существующий выход.
10. Rename/Skip/Replace, case-insensitive имена, Unicode, одинаковые stems, несколько корней,
    symlink/hardlink alias и внешняя коллизия проверены. Ни один вход не заменён даже при Replace.
11. Сбои feed/flush/validation/rename/ENOSPC, Cancel в каждой фазе: вход и старый выход неизменны,
    собственные temps очищены, завершённые выходы сохранены, отчёт полный.
12. WAV whitelist и удаление time-indexed metadata при Trim/SRC проверены повторным чтением
    chunks; root не становится выдуманным C4. Cross-container losses имеют предупреждение.
13. Папка рекурсивна, table filters не ограничивают; ignored/virtual/unsupported и unsaved sources
    объяснены; поздние файлы/результаты текущей партии в состав не попадают.
14. Длинный синтетический поток не выделяет RAM пропорционально длине; счётчики после 2^31
    кадров не переполняются. Отмена в середине потока не ждёт завершения всего файла.
15. Пресет round-trip и повтор рендера сохраняют порядок/параметры; corrupt/future JSON и
    settings isolation проверены. A/B использует глобальные stats и не остаётся после закрытия.
16. Busy state, закрытие, смена каталога и освобождение preview проверены управляемыми
    барьерами, а не тестом «подождать 50 мс и надеяться, что worker ещё работает».
17. Полный существующий debug ctest зелёный; release собирается и проходит codesign verification.
    Скриншоты реального диалога в 100% и 125%, обе темы. Windows build/tests — через доступный CI;
    без него результат честно маркируется macOS-verified, а не «кроссплатформенность проверена».
