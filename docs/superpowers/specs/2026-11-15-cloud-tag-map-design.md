# Облако тегов и акустическая карта — ТЗ

Дата: 2026-11-15. Статус: утверждено и реализовано (см. `docs/CLOUD_MAP.md`).

## Зачем

Список отвечает на вопрос «что у меня есть по имени, тегу, типу». На вопрос «что звучит похоже»
он не отвечает: соседние строки — это алфавит, а не звук. Владелец хочет второе представление
той же библиотеки: карту, где области — теги, а внутри области рядом стоят похожие по звуку файлы.
Наведение мышью проигрывает файл, один щелчок выбирает его.

**Критерий успеха:** включаю «Облако», вижу узнаваемые области тегов; навожу на Kick — слышу
кик; рядом с ним стоят другие кики, а не случайные файлы; щелчок выбирает файл так же, как строка
списка, и ничего не теряет из текущего выделения, правок волны и проекта.

## Цели

- Переключатель «Список / Облако» в области библиотеки; тот же каталог, те же фильтры, без
  копирования базы и без повторного анализа аудио.
- Один узел — один файл с тегами. Положение: теговые острова задают структуру, реальные
  акустические признаки — локальное соседство. Файл с несколькими тегами садится на переход
  между островами, его цвет — смесь цветов тегов.
- Раскладка воспроизводима: одинаковый каталог и теги дают одинаковые координаты; камера
  (панорама, зум) никогда не пересчитывает карту.
- Фоновый расчёт с отменой; смена фильтра не пересчитывает раскладку; устаревший результат
  отбрасывается.
- Наведение: подсветка, подпись и прослушивание с плавным затуханием при уходе курсора.
  Один щелчок — выбор файла и небольшой плавный шаг камеры к нему.
- Колесо — зум к курсору, перетаскивание поля — панорама, «Назад» — история камеры,
  «Общий вид» — вписать всё.
- 35 636 размеченных файлов рисуются и опрашиваются под курсором без просадок; никакого
  компонента на точку и никакого обхода библиотеки на кадр.
- Всё с тестами, без новых зависимостей.

## Не цели

- Новый анализ аудио, повторная экстракция признаков, обучение модели, embeddings.
- Новое хранилище признаков и миграция каталога ради v2 у файлов без строки обучения: плагин
  не имеет права мигрировать каталог, а `backfillFeatureV2` дозаполняет только схему 1.
- Показ неразмеченных файлов (в каталоге их 340 192 из 375 828) и «всех вообще» точек.
- Grid/плиточное представление и дерево как третье представление библиотеки.
- Автоматическая кластеризация без тегов, «умные» названия островов, ручное перетаскивание
  островов пользователем.
- Синхронизация камеры между окнами и экземплярами плагина.

## Анти-цели (провал, даже если «работает»)

- Случайные или псевдослучайные координаты, выданные за акустическую похожесть.
- Обещание одинаковой точности соседства для файлов без подробных признаков.
- Карта «прыгает» после каждой смены фильтра, тега или камеры.
- Наведение меняет выделение, открывает диалог о несохранённых правках волны или сбрасывает
  текущий preview.
- Щелчок по точке теряет несохранённые правки волны или выбирает не тот файл.
- Прослушивание при наведении щёлкает при остановке, продолжает звучать после ухода курсора
  или запускает декодирование на каждое движение мыши.
- 35k точек рисуются по одной через отдельный Component, кадр опрашивает всю библиотеку,
  прокрутка карты идёт ниже 60 fps на каталоге владельца.
- Плагин в DAW строит карту в аудиопотоке или блокирует редактор на время расчёта.

- `FileListPanel::selectSampleById` выбирает строку без вызова действия выбора — пригодится,
  чтобы синхронизировать список и карту.
- Оформление: `ui/shell/Theme.h`, `ui/shell/StudioControls.h`; раскладка панелей —
  `ui/MainComponent.cpp::resized` (область `library`).

## Подходы

**A. Острова тегов + акустическое уточнение (выбран).** 50 тегов раскладываются по совместной
встречаемости (теги, которые часто стоят вместе, оказываются рядом); файл садится в среднее
своих островов; внутри острова смещение задаёт проекция реальных признаков. Многотеговые файлы
сами образуют перемычки. Детерминированно, считается один раз, структура читаема, обещание
«похожесть» ограничено локальным соседством — ровно то, что просил владелец.

**B. Глобальная акустическая проекция (PCA/UMAP-подобная) по признакам, теги только как цвет.**
Честнее по звуку между тегами, но: у 53 % карты нет 84-мерных признаков, их координаты —
вторичная проекция по слабым базовым дескрипторам; острова могут размазаться, а Dubtechno
(9 339 файлов) накроет полкарты. Дороже: kNN-граф и итерации, обязательный кэш. Карта перестаёт
быть картой тегов, а именно её просил владелец.

**C. Сетка/плитки по тегам без акустики.** Дёшево и честно, но это не «облако»: нет соседства
звуков, наведение не помогает найти альтернативу. Отпадает.

Решение: **A**. Внутри A два подвопроса решены так:

- **Где стоят острова:** раскладка по совместной встречаемости 50 узлов (пружины по весу
  co-occurrence, отталкивание), фиксированное число итераций, без ГСЧ. Не кольцо по алфавиту:
  тогда перемычки между Kick и Drums были бы случайными.
- **Чем задано смещение внутри острова:** базовые дескрипторы (есть у 95 % карты) дают
  общую проекцию — одна система координат, без «дыр»; 84-мерные v2 (39 % карты, перекос по
  островам) уточняют соседство только там, где они есть, с ограниченной амплитудой. Файлы без
  дескрипторов (metadata-only) стоят в центре своего острова и помечены как «без звуковой
  позиции». Это даёт связную карту и не выдаёт базовые признаки за подробный анализ.

## Решение

### 1. Данные и расчёт (`core/cloud/`)

`CloudSource` — один пакетный запрос к каталогу: id, имя, путь, теги, наличие v1/v2, базовые
дескрипторы (duration, rms, peak, centroid, rolloff, flatness, rate, channels), размер, формат.
Не страница таблицы и не запрос на файл. Возвращает `CloudInput { std::vector<CloudNode> nodes;
std::vector<Tag> tags; std::vector<Clash> cooccurrence; uint64_t fingerprint; }`.

`CloudLayoutBuilder` — чистая функция `CloudInput → CloudLayout`, без потоков, без БД, без JUCE
Component:

1. **Острова.** Узлы — теги с ненулевым количеством. Вес ребра `w_ij = cooccurrence_ij /
   sqrt(n_i * n_j)`. Начальные позиции — спираль по возрастанию `tag.id` (детерминированно).
   Пружины по `w_ij`, отталкивание всех пар, 300 итераций с охлаждением, затем раздвижка
   пересекающихся окружностей. Радиус острова `r_i = r0 + a * sqrt(n_i)`, `r0` даёт видимую
   область тегу с одной записью, `a` не даёт Dubtechno съесть карту; конкретные константы
   подбираются замером, а не на глаз.
2. **Якорь файла.** Среднее центров его тегов (равные веса, а не по частоте тега). Один тег —
   центр острова; несколько — точка на перемычке.
3. **Смещение от звука.** Базовые дескрипторы z-нормализуются (устойчиво, по 5–95 перцентилям),
   две главные компоненты считаются степенным методом по ковариации 8×8, координата
   масштабируется в радиус острова. Для файлов с v2: kNN (k = 8) по 84-мерному пространству
   среди 13 991 точки с v2 через ту же равномерную сетку, 2–3 итерации притяжения к соседям;
   полное смещение ограничено долей радиуса острова, поэтому уточнение не рвёт остров и не
   переставляет точки между островами. Там, где v2 почти нет (Dubtechno, Chord, Stab),
   остров держится на базовой проекции — так и задумано.
4. **Вырожденные случаи.** Одинаковые векторы разводятся детерминированной спиралью
   (золотой угол, по возрастанию id). NaN/бесконечности в признаках отбрасываются до
   нормализации. Файлы без дескрипторов (1 774 metadata-only/нечитаемых) получают
   `hasPosition = false`, стоят в центре острова и не участвуют в kNN — их нечем сравнивать.
5. **Воспроизводимость.** Никакого ГСЧ, никакого порядка из хеш-таблиц; вход сортируется по id.
   Один и тот же `CloudInput` даёт побитово одинаковый `CloudLayout` (проверяется тестом).

`CloudLayout` — массивы `x, y, radiusPx, colour, flags (hasV2 / hasPosition / multiTag),
islandIndex`, границы, `fingerprint`. Флаги честно различают три уровня: подробное соседство
(v2), грубое (базовые дескрипторы) и «без звуковой позиции» (metadata-only).

`CloudCache` — двоичный файл в `~/Library/Sonicator/cache/cloud/layout-<fingerprint>.bin`:
версия формата, fingerprint, координаты. Чтение — если fingerprint совпал; иначе пересчёт.
Кэш — ускорение, не источник истины: битый файл просто пересчитывается. Старые файлы
удаляются по количеству (не больше двух), а не «очисткой папки».

**Fingerprint** (FNV-1a 64) считается по явному списку: версия алгоритма раскладки; версия
фич-схемы; отсортированные `(tag.id, tag.colour, count)`; хеш назначений
`(sample_id, sorted tag ids)`; битовая карта наличия базовых дескрипторов и v2; максимум
`analyzed`/`modified` размеченных файлов. Цвет тега входит, потому что он запечён в
`CloudLayout::colour`; перекраска тега — новый файл кэша, но пересчёт дешёвый.

`CloudBuildService` — воркер с отменой и поколением: `start()`, `cancel()`, `progress()`,
`poll()` на message thread. Расчёт не на message thread, не в аудиопотоке, с индикатором в
статусе. Смена фильтра **не** строит раскладку: фильтр — это видимость, а `CloudInput` зависит
только от каталога и назначений тегов. Пересчёт запускают явные точки: публикация результатов
индексации, удаление/перемещение файлов, reanalyze (меняет дескрипторы), запись назначений
тегов (`TaggingService`/AutoTag), смена каталога, старт приложения, если кэш устарел.
События склеиваются дебаунсом 500 мс, чтобы AutoTag пачкой не запускал десять пересчётов.
Устаревший результат (другое поколение) не публикуется.

### 2. Представление (`ui/cloud/`)

`CloudView` — один Component на всю область библиотеки, без дочерних компонентов на точку.

- **Рисование.** Точки рисуются одним проходом в `juce::Image` (или одним `Path` из квадратов
  2–3 px), кэш кадра инвалидируется камерой, наведением, выбором и фильтром. Порядок — по
  глубине/цвету, стабильный. При малом зуме точки плотных островов сливаются в пятно
  (уровень детализации), подписи островов появляются с порога зума, подписи файлов — только
  у наведённой и выбранной точки.
- **Попадание под курсор.** Равномерная сетка (spatial hash) строится один раз на раскладку,
  ячейка ~24 px; поиск ближайшей точки в радиусе курсора — O(1) в среднем. Никакого обхода
  35k на `mouseMove`.
- **Камера.** `offset + scale`, анимация шага с 60 Hz таймером и затуханием; остановка, когда
  шаг меньше пикселя. Колесо — зум к курсору (точка под курсором остаётся на месте).
  Перетаскивание поля — панорама. «Назад» — стек до 20 состояний камеры. «Общий вид» — вписать
  границы раскладки с полями. Изменение размера панели сохраняет центр и масштаб.
- **Наведение.** Подсветка точки (растущий ореол, плавно гаснущий), подпись «имя · теги ·
  длительность · формат», курсор-hand. Уход курсора гасит подсветку и останавливает звук.
- **Щелчок.** Выбор файла через `MainComponent::selectSample` (с подтверждением несохранённых
  правок, как из списка), синхронизация строки списка через `selectSampleById`, небольшой
  плавный шаг камеры к точке. Если файла нет на загруженной странице списка (страница по
  умолчанию — 10 000 из 35 636), строка не выбирается: список остаётся без выделения, а
  preview показывает файл из карты. Подменять выделение чужим файлом или молча листать
  страницу нельзя — это ровно тот провал, который запрещён. Двойной щелчок — «приблизить к
  острову», правый клик — то же контекстное меню, что у строки (если это дёшево; иначе — вне
  этого этапа, см. «Что осталось строителю»).
- **Фильтры.** Текущий `LibraryFilter` применяется к видимости: совпавшие точки — полная
  яркость и ореол, остальные — 12 % яркости; раскладка не меняется. Погашенные точки
  показывают подпись при наведении, но не выбираются щелчком: пользователь фильтром попросил
  другое, и клик по «не тому» не должен менять выбор. Пустой результат фильтра показывает
  «Ничего не найдено» поверх карты, не стирая её.
- **Переключатель.** Сегмент «Список / Облако» в шапке LIBRARY; режим запоминается в сессии и
  настройках приложения. При возврате в «Список» выделение и прокрутка списка сохраняются.
- **Тема и масштаб.** Цвета — из `Theme`; точки окрашены цветом тега, поэтому на светлой теме
  меняется фон/подписи/ореол, а не цвета тегов. Работает при 100 % и 125 %.

### 3. Прослушивание при наведении (`core/audio/HoverAudition`)

Отдельный голос, не транспорт preview и не `selectSample`:

- `PreviewOutput` получает `HoverAudition` и микширует его вместе с остальными источниками.
  У голоса свой gain и 8–12 мс рампа на старт и на стоп (щелчка нет), громкость — как у
  обычного preview.
- Декодирование — на воркере, первые ≤ 10 с файла (как `AnalysisAudio` с `maxSeconds`),
  поколение на каждый запрос; запоздавшее декодирование отбрасывается. Небольшой LRU
  (8 клипов) и очередь не больше одного запроса: быстрое движение мышью не устраивает шторм.
- Пока играет транспорт (Play в preview), наведение молчит: два звука одновременно — не
  прослушивание. После остановки транспорта наведение снова работает.
- Уход курсора, щелчок, смена фильтра, уход из «Облака», закрытие окна — стоп с затуханием.
  Звук никогда не «висит» после того, как карта скрыта.
- **Границы этапа по форматам.** Звучат только файлы, которые открывает общий путь
  декодирования (базовые форматы + EBL + VOC) — это 33 862 размеченных файла из 35 636.
  RX2, EXS, NKI, SF2, AKAI и документы трекеров (1 771 файл, 5 %) в этом этапе молчат:
  отдельный диспетчер форматов, выбор слота/пресета и чтение образа — не задача карты.
  Такая точка не притворяется звучащей: в подписи стоит «прослушивание — в preview», и она
  помечена как «без звуковой позиции», если у неё вообще нет дескрипторов.

### 4. Drag из карты

Перетаскивание точки использует существующий экспорт и кэш drag (`ExternalFileDrag`,
`dragCacheFolder`), не трогает `exports/` и оригиналы. Выбор файла для drag не идёт через
подтверждение правок волны: это отдельный, неразрушающий путь. Если существующий путь
экспорта жёстко привязан к выделению `PreviewPanel`, в этом этапе drag откладывается
(см. «Что осталось строителю») — карта работает без него.

### 5. Проверка на реальных звуках

Владелец решил: проверка идёт параллельно с интерфейсом, без остановки этапа. Инструмент —
часть этапа, а не отдельная приёмка: его результаты читаются до показа карты владельцу, а
плохая раскладка чинится константами по ходу.

Отдельный инструмент (тест-бинарь или `tools/`) на живом каталоге:

- считает раскладку для размеченных файлов и печатает CSV координат;
- для 10–15 опорных файлов (по одному из Kick, Snare, Hat, Bass, Pad, Chord, FX, Loop, Vocal,
  Dubtechno, Stab, Riser) печатает 5 ближайших соседей с путями и расстоянием;
- пишет SVG/PNG-эскиз карты, чтобы увидеть острова до UI;
- печатает время расчёта и счётчики по флагам (v2 / только базовые / без позиции) — чтобы
  сразу было видно, на какой доле карты соседство подробное.

Владелец слушает соседей и говорит, похожи ли они. Критерий приёмки раскладки: у большинства
опорных точек 4 из 5 соседей — тот же тип звука; ни один остров не пуст и не наезжает на
другой; точки без v2 не выглядят «мусором» внутри острова. Если критерий не выполняется,
меняются константы и/или порядок шагов (острова → базовые → v2), UI не строится на плохой
раскладке.

## Тесты

- `CloudLayoutBuilder`: детерминизм (два прогона побитово равны), отсутствие NaN, все точки
  внутри границ, острова не пересекаются, многотеговый файл лежит между своими тегами
  (расстояние до перемычки меньше, чем до центров), файл без признаков — в центре острова,
  одинаковые векторы не совпадают точно, вырожденные входы (0/1/все теги на одном файле,
  признаки из NaN).
- `CloudSource`: пакетное чтение = эталонный набор, только размеченные, цвет/флаги верны,
  fingerprint меняется при изменении назначений тегов и не меняется от фильтра.
- `CloudBuildService`: отмена, устаревшее поколение не публикуется, повторный старт не течёт,
  кэш читается и перезаписывается, битый кэш пересчитывается.
- `CloudIndex`: попадание под курсор на границах, пустые ячейки, плотные кластеры, скорость
  на 35 636 точках.
- `HoverAudition`: рампа на старт/стоп, стоп при уходе, отмена запоздавшего декодирования,
  молчание при играющем транспорте, лимит 10 с, LRU.
- UI: переключатель, щелчок выбирает файл и уважает несохранённые правки, наведение не меняет
  выделение, колесо держит точку под курсором, «Назад»/«Общий вид», фильтр только гасит точки,
  раскладка не меняется от фильтра.
- Замеры на каталоге владельца (35 636 точек): время расчёта, время кадра при панораме/зуме,
  отклик наведения; Debug и Release; снимки 100 %/125 %, светлая тема, два экземпляра плагина.
- Дымовой прогон в плагине: карта строится в редакторе, аудио-поток не блокируется.

## Риски и что с ними делаем

- **Качество раскладки.** 84-мерный вектор — не человеческая похожесть. Поэтому сначала
  проверка на реальных звуках и только потом UI; константы подбираются по прослушиванию.
- **39.3 % с подробными признаками, и перекос не в пользу больших островов.** У Dubtechno
  1.9 %, у Chord 10 %, у Stab 5 %; у Kick 75 %, у Loop почти 100 %. Значит, «акустическое
  уточнение» усиливает в основном ударные и лупы, а большие жанровые острова держатся на
  базовых дескрипторах и теге. UI это не скрывает; backfill v2 — не тихая подмена, а отдельное
  решение, и в этом этапе его нет: все строки обучения уже `feature_schema=2`, а дописать v2
  файлу без строки в `ml_feedback_samples` некуда (нужно новое хранилище признаков и миграция
  каталога, которую плагин делать не имеет права).
- **1 774 файла без звука** (metadata-only и нечитаемые, 5 %): стоят в центре острова,
  помечены, не звучат при наведении, не участвуют в kNN.
- **Неравномерность тегов.** Dubtechno 26 % карты. Радиусы растут как корень, у острова есть
  минимальный размер; визуально проверяется на реальных данных.
- **Производительность.** Основной риск — кадр и hit-test на 35k, а не расчёт. Отсюда кэш кадра,
  один Path, сетка и LOD; замеры до приёмки. kNN по 13 991 вектору идёт через сетку, не
  полным перебором: полный перебор — ~98 млн пар и секунды в Debug, что для экземпляра плагина
  на первом открытии неприемлемо без прогресса.
- **Наведение и память.** Быстрое движение мышью может вызвать шторм декодирований; лечится
  очередью из одного запроса, генерацией и LRU. Долгие семплы ограничены 10 с.
- **Плагин.** Несколько экземпляров читают один кэш; каждый может посчитать заново — это
  допустимо (расчёт дешёвый), блокировать редактор нельзя; при промахе кэша показывается
  прогресс, а не пустая панель.

## Что осталось строителю

- Константы раскладки (`r0`, `a`, число итераций, k, амплитуды) — подбираются замерами и
  прослушиванием, с записью в `docs/CLOUD_MAP.md`.
- Правый клик и контекстное меню карты: переиспользовать меню строки, если оно отделяется от
  `TableListBox` без переделки; иначе — следующий этап.
- Drag из карты: если существующий экспорт нельзя вызвать без выделения `PreviewPanel` —
  отложить, зафиксировав это в отчёте этапа.
- Точная форма подписи и вид ореола — по месту, в рамках токенов темы.
- Поведение при пустом результате и при ошибке чтения каталога — по месту, по образцу списка.
- Нужен ли отдельный пункт меню/горячая клавиша «Переключить представление» — по образцу
  существующих команд.
