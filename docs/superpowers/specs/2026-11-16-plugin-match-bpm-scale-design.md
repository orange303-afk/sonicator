# SONICATOR Plugin: Match BPM / Match Scale — ТЗ

Дата: 2026-11-16. Статус: проект ТЗ на утверждение; реализация не начиналась.

## Цель и согласованные требования

В VST3/AU прослушивать семпл в темпе проекта и выбранной тональности, затем перетащить в DAW именно услышанный результат. Standalone не меняется.

Пользователь выбрал **preview и drag**, не только обработку экспорта.
Пользователь указал расположение: **две независимые отключаемые галочки рядом с Play/Stop**.
Названия: `Match BPM`, `Match Scale`. Обе выключены по умолчанию; любое сочетание допустимо.

Опора: `docs/superpowers/specs/2026-11-15-match-bpm-scale-requirements.md`, `docs/PLUGIN.md`, внешний `~/Documents/orange303/Sonicator Features.md`.

## Подходы и решение

1. **Подготовленная WAV-копия в фоне — выбранный инженерный подход.** Один результат для preview и drag, возможность точной проверки длины, отсутствие time-stretch DSP в аудиопотоке. Недостаток: ожидание подготовки после выбора/смены настроек.
2. Realtime time-stretch preview плюс отдельный offline экспорт: быстрее реагирует на изменение темпа, но сложнее, вводит latency/состояния и риск несовпадения preview и drag. Не входит в этот этап.
3. Только обработанный drag: меньше работы, но пользователь выбрал прослушивание результата; отклонён.

Это не пара галочек поверх существующего ресемплера: необходима независимая обработка времени и высоты. Инженерный выбор — Rubber Band offline (R3/Finer), при условии проверки сборки на обеих платформах. Upstream README подтверждает независимые time/pitch ratios и GPL-2.0-or-later; проект AGPL-3.0-or-later допускает совместимое распространение. Зафиксировать release/commit и checksum, зависимости и notices. Не использовать Homebrew, внешнюю CLI или неопределённый HEAD. Если сборка/лицензии выбранной конфигурации препятствуют включению — остановиться и предложить альтернативу, не заменять алгоритм самописным вокодером молча.

## Интерфейс

- Галочки находятся в существующей transport-области preview рядом с Play/Stop; при узком окне допускается соседняя строка той же группы, без перекрытия громкости и Loop.
- Область видна только при переданном plugin match context; не проверять это лишь глобальным флагом сборки, поскольку MainComponent общий.
- Рядом компактный статус: `120 → 128 BPM`, `A min → C min (+3 st)`, `Preparing…`, `Ready`, конкретная причина недоступности.
- Match Scale показывает ручной выбор целевой тоники (12 нот) и лада major/minor. DAW key автоматически не обещается: стандартный JUCE playhead не предоставляет его универсально.
- Галочки хранят пользовательское намерение отдельно от доступности: временная потеря BPM хоста не снимает сохранённый флажок. Match BPM при этом неактивен с пояснением; Play/drag обработанного результата недоступны до восстановления контекста или выключения флажка.
- Изменение галочки/целевой тональности/исходного файла запускает подготовку в фоне. Пока результат не готов, не проигрывать оригинал под видом обработанного и не отдавать предыдущий результат.
- После подготовки Auto Preview может запустить выбранный результат, только если выбор всё ещё актуален и пользователь не нажал Stop. Восстановление проекта само звук не запускает.
- Режим сохраняется отдельно для экземпляра, в проекте DAW; глобальные standalone settings не содержат match-параметров.

## Match BPM

- BPM проекта читается в `PluginProcessor::processBlock` через JUCE `getPlayHead()->getPosition()->getBpm()`; публикуется компактный atomic snapshot, без SQLite, файлов и locks UI/state на аудиопотоке.
- Читаем BPM и при остановленном транспорте, если хост присылает блоки; отсутствие playhead/валидного BPM — честное `Host tempo unavailable`, не 120 по умолчанию.
- Последнее значение допустимо между блоками, включая приостановивший обработку хост; явный невалидный context и releaseResources его инвалидируют. UI различает «последний полученный» и «обновляется». Не считать возраст снапшота единственным доказательством отсутствия темпа.
- Исходный BPM — эффективное сохранённое значение с учётом ручной правки; unknown/conflict/stale не использовать. Не запускать анализ всей библиотеки.
- Применяется только к явно определённому лупу: эффективная структура `Loop` (или эквивалент текущего enum), либо REX-loop; не угадывать по одной длительности. One-shot не растягивается, в статусе `BPM: not applicable to one-shot`.
- Приоритет: сначала applicability, затем host/source BPM. Подтверждённый one-shot не требует host tempo даже при сохранённом Match BPM: BPM-only даёт bypass, BPM+Scale допускает независимый pitch-only результат. Указанная выше блокировка при отсутствующем host BPM относится только к применимому BPM-match лупа.
- `timeRatio = sourceBpm / targetBpm`, выходные кадры `round(sourceFrames × timeRatio)`. Размерность — кадры источника при неизменном sample rate.
- Пример: четыре такта 4/4 при 120 BPM = 8 с; при 128 BPM = 7.5 с. Допуск длины — один выходной кадр после обработки, и в любом случае не больше 1 мс.
- Не менять высоту звука при одном Match BPM. Не округлять исходник к ближайшему такту, не менять размер проекта и не обещать выравнивание старта воспроизведения с transport/bar.
- Безопасный диапазон timeRatio 0.5…2.0, конечные положительные BPM. За пределами — явный отказ без молчаливого clamp.
- Изменения BPM склеиваются 250 мс. Стабилизировавшийся новый темп готовит новый результат; промежуточные отменяются. Для темповой автоматизации внутри клипа и realtime follow ramp эта версия не предназначена.

## Match Scale

- Тональность цели задаётся вручную: не выдавать её за прочитанную из проекта.
- Для материала с известным key — транспонирование кратчайшим интервалом между тониками, диапазон −6…+6 полутонов; тритон детерминированно +6. `pitchRatio = 2^(semitones/12)`.
- Am → Cm = +3 полутона. Длина при одном Match Scale не меняется.
- **Лад не конвертируется.** Am → C major не может получиться простым pitch shift: показываем `Mode mismatch; cannot match scale`, обработку с этим запросом не считаем Ready. Пользователь может выбрать C minor или выключить Match Scale.
- Для однонотного one-shot известные root/pitch позволяют подстроить к тонике цели (без обещания определить лад одиночной ноты). Root/pitch и музыкальный key не смешиваются в каталоге; это отдельная ветка расчёта.
- Без пригодной тоники/root/pitch — `Source pitch/key unknown`. Барабаны без тональной опоры не транспонировать по случайной оценке. Никакой автоматической коррекции каждой ноты и major↔minor reharmonization.
- В выходных метаданных root/key соответствуют результату, а не исходнику; не копировать неподтверждённый лад.

## Preview, waveform, MIDI и правки

- Подтверждённый выбор из списка или облака по-прежнему открывает семпл в waveform; не обходить существующее подтверждение несохранённых правок.
- При фактической обработке waveform показывает подготовленный WAV с его длительностью. Сохранить исходную catalog identity отдельно: теги, имя и Analysis относятся к исходному ID; temporary WAV не становится новой строкой каталога и не записывается в lastSamplePath.
- Трансформированный preview только для чтения: Save/Normalize/edit-команды недоступны с пояснением. Оригинальные edit-функции возвращаются после выключения обработки. Не предлагать overwrite исходника подготовленной копией.
- При включении match с несохранёнными правками — существующий Save/Discard/Cancel guard. Cancel сохраняет прежние флажки/выбор/звук. При смене темпа во время подготовки ничего из этих правок не уничтожается.
- Waveform selection измеряется в секундах уже обработанного WAV. Экспорт выделения — crop этого результата, без второго stretch/pitch. При пересборке результата selection очищается; источник уже обработанного файла явно помечен в запросах.
- MIDI Preview остаётся оригинальным инструментом/источником и не проходит через match. Нужны раздельно удерживаемые **original MIDI source** и **matched transport source** в AudioEngine: простой loadFile(preparedWav) непригоден, он сейчас заменяет также MIDI sampler и container state. Prepared transport не очищает original sampler, REX slices/root mapping. Первая NoteOn после matched Play сразу играет исходник, без перезагрузки через UI/callback и без двойного транспонирования.
- Selection обработанного waveform относится только к matched Play/drag, **не меняет диапазон original MIDI**: transformed seconds не пересылаются в setMidiSelection, original MIDI играет полный исходник/слайс. При включении Match прежний MIDI range очищается; обе off возвращают обычное связывание waveform selection с MIDI. Это подписано в UI.
- Hover-preview облака в этом этапе остаётся оригинальным и не запускает обработку для каждой точки; это явно подписано в plugin UI. Match относится к подтверждённому выбору и его обычному Play/drag.
- При переключении обработанного/исходного источника — безопасный stop/fade через существующий engine lifecycle; не менять reader/буфер из worker или audio callback.

## Drag и форматы

- Для одиночного выбранного файла drag из списка, точки облака и кнопки/волны preview получает **один и тот же актуальный подготовленный WAV**. Метаданные записаны до Ready.
- Если запрос не Ready, drag не стартует и показывает `Preparing…` или причину ошибки; не отдаёт оригинал как будто Match применён. Потребуется повторить gesture после Ready: ОС-drag не запускается из запоздалого callback.
- Пакетный drag при включённом match в v1 недоступен с пояснением `Select one sample for Match`; выключенные флажки сохраняют прежний batch drag.
- Базовый объём: обычные mono/stereo файлы общего декодера, EBL, полный декодированный REX-loop и существующее waveform selection после обработки. Для неподдержанных sampler banks, tracker songs, disc entries и составных L/R источников не делать молчаливую обработку только первой части: явный unsupported. Новые адаптеры не являются условием v1.
- Путь к результату долговечный: `~/Library/Sonicator/exports/match/<key>/<name>.wav`. Не считать его временным мусором и не очищать автоматически. Уже экспортированные файлы, `exports/drag/` и originals не удалять/перезаписывать.
- Смена BPM/Scale делает новый файл; ранее брошенный в DAW файл не изменяется.
- Ключ результата: algorithm/dependency version, catalog/source identity, size/mtime, metadata revision, исходный диапазон в кадрах, sample rate/channels, source/target BPM, pitch interval, режимы. Повторное чтение identity после рендера ловит изменение источника; partial файл не становится Ready.
- Атомарная публикация с уникальным partial и no-clobber: два экземпляра могут получить один и тот же ключ без повреждения файла. Перед переиспользованием проверять WAV и параметры, а не только имя файла.
- Формат результата: WAV PCM24, исходный sample rate, 1/2 канала. Выделения и loop ranges должны оставаться валидны; не переносить устаревшие offsets `smpl`/REX slices из исходника без пересчёта.
- При обеих выключенных галочках полностью сохраняется существующий путь preview/drag, включая его текущий формат/metadata policy. Требование «байт-в-байт» означает равенство текущему bypass-пути, не обязательное равенство WAV-копии исходнику.

## Потоки, лимиты и состояние

- Worker один постоянный, очередь latest-wins из одного запроса, generation и отмена между блоками. submit не join-ит worker в message thread. Ошибка перехватывается, UI живёт дальше.
- Предел source duration 10 мин; чтение/DSP блочно, scratch/working buffers с учётом лимита 256 MiB; целевой размер/число кадров проверяются на переполнение до создания writer. Свободное место оценивается по ожидаемому output + partial; ошибка места не повреждает оригинал.
- Обработка offline study/process/retrieve с корректным drain; численная проверка NaN/Inf, stereo coherence, сохранение pitch при stretch. Компенсация latency по контракту offline-библиотеки, не произвольное обрезание атаки. Plugin setLatencySamples не добавляет задержку: realtime DSP в этом этапе нет.
- Точное доведение output length допустимо лишь для малого остатка ≤1 мс; большая ошибка — failure, не маскировать её длинной тишиной/обрезкой.
- Никакой работы с DSP/SQLite/кэшем/декодированием в processBlock. Там только получение host BPM и существующее воспроизведение.
- Plugin state v2: flags, target tonic/mode. Старые v1 проекты загружаются с флажками off. Host tempo не сохраняется как истина проекта. State restore при открытом editor/нескольких экземплярах не смешивает настройки и не запускает autoplay.

## Приёмка

1. Галочки рядом с Play/Stop, только плагин, независимые, defaults off, сохраняются в DAW project.
2. Loop 8 с / 120 BPM при host 128 становится 7.5 с; pitch сохраняется в пределах 5 cents на устойчивом тестовом тоне.
3. A minor → C minor: +3 st, исходная длительность; режимы вместе дают целевую длину и pitch без двойной обработки.
4. Preview и drag full-file используют один WAV/ключ; waveform показывает обработанную длительность, source ID остаётся прежним.
5. Unknown BPM/key, mismatch mode, unsupported, повреждённый WAV, disk-full и rapid A→B→A не дают ложного Ready/не того файла/утраты edits.
6. Старый экспорт в DAW не меняется при смене темпа/тональности; bypass не регрессирует; MIDI не меняется.
7. Debug/Release тесты, VST3/AU сборка и validators, CI macOS/Windows; ручная проверка Cubase и Logic при наличии. Это отдельные фактические результаты, не вывод из unit-тестов.

## Не цели

Realtime warp/tempo ramps, следование bar/transport, harmony conversion major↔minor, DAW key autodetect, standalone UI, batch matched export, обработка hover-облака и эмуляция банков/инструментов. Существующие схемы каталога/обучение не меняются.
