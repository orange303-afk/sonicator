# Match BPM / Match Scale: требования к P2 (без реализации)

Запрос владельца (backlog): «Для плагин-версии галочки match bpm и match scale для синхронизации
темпа и тона с DAW». Это требования, а не дизайн: DSP сегодня не внедряется.

## 1. Что делает галочка

- **Match BPM** — экспортируемый для drag файл растягивается по времени так, чтобы его длина
  соответствовала сетке проекта: луп на 4 такта при 120 BPM, брошенный в проект на 128 BPM,
  звучит и выглядит как 4 такта на 128 BPM.
- **Match Scale** — высота тона сдвигается к выбранной пользователем тональности проекта, чтобы
  луп в Am не звучал фальшиво в Cm.

Галочки относятся к **drag-экспорту** (и, если решим, к preview). Одна из них или обе могут быть
включены; обе выключены по умолчанию.

## 2. Что хост реально даёт

| Данные | VST3 | AU |
|---|---|---|
| Темп проекта | `ProcessContext::tempo` при `kTempoValid`, плюс `kTempoValid` меняется на ходу | `kAudioUnitProperty_MusicalContextBlock` (`tempo`, `beatPosition`); не все хосты его заполняют |
| Доля/такт и позиция | `kProjectTimeMusicValid`, `kBarPositionValid`, `kTimeSigValid` | тот же musical context block |
| Тональность проекта | **нет** в VST3 ProcessContext | **нет** в AU |
| Состояние транспорта | `kPlaying` | `beatPosition`/`transportState` |

Вывод: **темп брать из хоста**, тональность — из настройки пользователя. «Match Scale к
тональности DAW» в общем случае невозможно; формулировка в UI должна быть «Match Scale → тоника
и лад», с явным выбором (например, `C min`, `A min`) и запоминанием в состоянии проекта.

Если хост не сообщает темп (AU в части DAW, VST3 до первого блока), галочка должна быть
неактивна с пояснением, а не молча выключена.

## 3. Область применения

- Только лупы: у одного выстрела нет своей BPM-сетки, и растяжение убивает атаку. Критерий
  «это луп» — уже есть (`Loop`, `One-shot`, длительность, стерео-пары, REX).
- Один выстрел при Match BPM: без изменений (только Match Scale, если включён).
- Preview внутри плагина: решение открыто. Предложение — preview играет оригинал, чтобы
  сравнение было честным, а растянутым звучит только drag-файл.
- MIDI-клавиатура: не затрагивается.

## 4. Качество и реализация (для планирования)

- Нужен time-stretch/pitch-shift. Кандидаты: Rubber Band (GPL-2.0-or-later, совместим с
  AGPL-3.0-or-later проекта), SoundTouch (LGPL-2.1). `libsamplerate` уже есть, но это ресемплинг,
  не растяжение.
- Растяжение выполняется в фоновом экспортёре (`SelectionExporter`/`AudioExporter`), не в
  `processBlock`: цена — секунды на луп, зато нет realtime-риска. Кэш — по (путь, BPM, тональность,
  режим), рядом с `exports/`.
- Точность: длина результата должна отличаться от целевой не более чем на 1 мс; метаданные
  (`acid`, `bwav`/`tempo`, `smpl`) пишутся уже сейчас (`docs/PLUGIN.md`, drag metadata).
- Никакого растяжения при выключенных галочках: файл остаётся байт-в-байт тем же, что сегодня.

## 5. Критерии приёмки P2

1. Галочки видны в плагине (не в приложении: у приложения нет хоста), состояние — в проекте DAW.
2. При включённой Match BPM drag-файл на 4 такта в проекте 128 BPM занимает ровно 4 такта.
3. При включённой Match Scale луп в Am, брошенный в Cm, звучит в Cm; сдвиг указан в статусе.
4. Хост без темпа: галочка неактивна и объясняет почему.
5. Смена темпа в хосте при открытом окне: следующий drag использует новый темп.
6. Выключенные галочки дают побитово тот же файл, что и сейчас (регрессия существующего drag).
7. Тесты: расчёт целевой длины, кэш, отказ без темпа, отсутствие работы в audio-thread.
