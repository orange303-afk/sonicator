# Признаки v2 и обучение на открытых датасетах — дизайн

Статус: утверждено владельцем 2026-11-12. Вариант B: `featureSchema 2` + публичные датасеты + исправленная
сборка модели. ONNX Runtime в этом этапе не используется (решение о нём — отдельно, см. часть 9).
Продолжает `docs/superpowers/specs/2026-11-11-training-and-tag-promotion-design.md`.

Реализация разбита на планы; первый — `docs/superpowers/plans/2026-11-12-stage3-prototype-assembly.md`
(этапы 0 и 1: реестр лицензий и сборка прототипов).

## 1. Зачем

- Потолок нынешней схемы (14 чисел) около 85% на ваших 4363 записях; слабые места `fx` (42%), `snare` (56%),
  `hat` (64%), `downfilter`, `impact` — перекрытия, которых в 14 числах нет.
- Глобальные прототипы пусты (`records: 0`), потому что порог требует 3 установки, а установка одна.
  Публичные датасеты дают размеченные данные сразу, без ожидания пользователей.
- Перспектива: анализ не только музыкальных сэмплов, но и foley (шаги, двери, стекло, вода, ткань, ambience).
  Признаки и конвейер должны быть независимы от набора меток.

## 2. Цели

1. `featureSchema 2`: богатое спектральное и временное описание звука, считается в C++ одним кодом и для
   приложения, и для обучения.
2. Конвейер «датасет → признаки → обучение → оценка → файл в билде» воспроизводим и без Python.
3. Обучение на всех подходящих бесплатных датасетах с учётом лицензий; атрибуция в About и в репозитории.
4. Измеримое улучшение на независимой выборке — вашей библиотеке — с отчётом.
5. Модель и конвейер готовы принимать foley-метки без переделки.

## 3. Не цели

- ONNX-модель и нейросеть в приложении. Допустим линейный/softmax-слой, считаемый на C++.
- Аудио датасетов в репозитории или в билде. В репозиторий попадают только производные числа.
- Автоматическое включение foley-типов в интерфейс (отдельное решение владельца, часть 8).
- Сетевые вызовы в приложении (сохраняется правило этапа 2).
- Python, внешние зависимости в `services/training` (правило проекта).

## 4. Анти-цели

- Прототипы, обученные на чистых студийных ваншотах, перебивают подтверждения пользователя.
- Файл модели с данными, лицензия которых несовместима с распространением проекта.
- Новая схема ломает старые каталоги, локальные прототипы или уже отправленные вклады.
- Анализ одного файла заметно замедляется (бюджет: не более +30% к нынешнему времени).

## 5. Датасеты и лицензии

Лицензии получены поиском 2026-11-12; перед включением каждого датасета сверять с файлами лицензий внутри архива
(`licenses.json`, `dev_clips_info_FSD50K.json` и т.п.). Раздача чужого аудио не планируется: наружу идут
статистики признаков, не звук.

### 5.1. Правила допуска

| Уровень | Что допускается | Куда попадает |
|---|---|---|
| A | CC0, CC-BY | обучение, поставляемый файл модели, атрибуция |
| B | CC-BY-NC, CC-BY-SA, «только для исследований», ND | **обучение и поставляемая модель** (решение владельца 2026-11-12: проект бесплатный и некоммерческий), с атрибуцией |
| C | запрет обучения ML, YouTube-аудио без явной лицензии, неясное происхождение | не используется |

Уровни остаются в реестре и в каждой строке признаков (`license`, `tier`), чтобы модель можно было пересобрать
без источников B, если лицензионная ситуация изменится (например, проект станет коммерческим или потребуется
выпуск без NC-данных). `train.mjs` получает флаг `--max-tier A|B`; поставляемый файл по умолчанию собирается с `B`,
в `global_model.json` записывается список использованных датасетов и уровень. Риски, которые принимает владелец:
NC и SA-условия переходят к форкам (AGPL допускает коммерческое использование кода); условие ND у
IDMT-SMT-Drums трактуется как неприменимое к статистикам признаков, но это не юридическая оценка; датасеты с
исследовательской лицензией (ENST-Drums, MedleyDB) требуют согласия с условиями при получении.

## 6. Признаки `featureSchema 2`

### 6.1. Принципы

- Один код: `core/dsp/FeatureExtractorV2` (рядом с `AcousticFeatures`), используется приложением и
  `sonicator-features`. Никакой другой реализации (librosa и т.п.) для обучения.
- Значения нормализуются в 0..1, округляются до 0.001 при отправке, как в схеме 1.
- Первые 14 чисел — те же, что в схеме 1 и в том же порядке (совместимость, откат, сравнение).
- Частотные границы заданы в герцах и не зависят от частоты дискретизации файла.
- Инвариантность к уровню: признаки считаются после пиковой нормализации; RMS остаётся только в legacy-части и не
  участвует в сходстве (в тестах схемы 1 его удаление дало −0.3 пункта).
- Детерминизм: одинаковый файл даёт одинаковый вектор побайтно (фиксированные окна, без случайности).

### 6.2. Группы (пул кандидатов, итоговый набор выбирается абляцией, часть 7.4)

| Группа | Признаки | Чисел |
|---|---|---|
| G1 legacy | 14 чисел схемы 1 | 14 |
| G2 форма спектра | centroid, spread, skewness, kurtosis, rolloff 85/95, flatness, entropy, slope; среднее и σ по кадрам | ~20 |
| G3 контраст | peak/valley по 6 поддиапазонам | 12 |
| G4 MFCC | коэффициенты 1–13, среднее и σ | 26 |
| G5 огибающие по полосам | attack и decay отдельно в 4 полосах; доли энергии в первые 50 мс, 200 мс, остаток | ~11 |
| G6 гармоническое/ударное | HPSS-подобное отношение (медианная фильтрация спектрограммы), гармоничность | 3 |
| G7 модуляция | плотность onset, периодичность огибающей онсетов (петли, шаги, дождь) | 4 |
| G8 стерео | ширина, корреляция каналов | 2 |
| G9 band-limit | флаг эффективной полосы файла | 1 |

Итого ~95 чисел. Верхней границы нет: набор определяется абляцией по точности; рост размера модели допустим.

### 6.3. Ограниченная полоса

NSynth и One-Shot — 16 кГц, то есть выше 8 кГц ничего нет, а граница «Air >7 кГц» у `Hat`, `Cymbal`, `FX` важна. Решение:

- у каждого файла вычисляется эффективная полоса (по порогу энергии спектра, не по заголовку);
- признаки выше 8 кГц помечаются недоступными (`null`, в файле признаков маска);
- сходство и модель работают по маске: недоступные измерения исключаются у обеих сторон;
- обучение на высоких частотах — только по источникам с полной полосой (FSD50K 44,1 кГц, Slakh, ваша библиотека);
- аугментация: часть полнополосных примеров дополнительно считается ограниченной до 8 кГц, чтобы модель умела
  оба случая (и пользовательские lo-fi файлы).

### 6.4. Длинные звуки (foley, ambience, петли)

- окно анализа сейчас — первые 10 с (`AnalysisAudioOptions::maxSeconds`); для v2 — до 10 с, при большей длине
  дополнительно 3 фрагмента (начало, середина, конец), статистики усредняются;
- G7 (модуляция) считается по всему анализируемому участку;
- проверить `readAnalysisAudio`: сейчас ли обрезается тишина перед атакой; если нет — обрезать (порог −50 дБ).

### 6.5. Тесты `[features]` (Catch2)

- побайтная повторяемость; инвариантность к усилению (±12 дБ); инвариантность к частоте дискретизации
  (один сигнал в 16/22,05/44,1/48 кГц → расхождение ≤ 0.02 по общей полосе);
- синтетические эталоны: синус, белый шум, импульс, свип, барабанный удар — значения лежат в ожидаемых диапазонах;
- маска: сигнал, ограниченный до 8 кГц, имеет недоступные признаки выше;
- первые 14 чисел равны выходу `AdaptiveClassifier::extractFeatures` (регрессия);
- бенчмарк: 1000 файлов; время v2 ≤ 1,3 × время v1.

### 6.6. Решения исполнителя (этап 2, 2026-11-12)

- Маски полосы нет. Вместо неё вся схема считается в полосе 40–8000 Гц, включая верхнюю пятую
  подполосу `7000–8000 Гц` вместо «всё выше 7 кГц». Тогда каждый источник — 16 кГц из NSynth и
  44,1 кГц из библиотеки — даёт одну и ту же определённость, и ни одно измерение не нужно исключать
  при сравнении. Цена: содержимое выше 8 кГц (воздух у тарелок и хай-хэтов) в схему не входит.
  Решение подлежит проверке на этапе 5: если `hat` и `cymbal` останутся слабыми, маска и
  высокочастотная группа вернутся.
- Приведение частоты дискретизации не делается: ресемплер ухудшал совпадение (0.05–0.08 на
  статистиках, зависящих от утечки окна), поэтому инвариантность обеспечивает только полоса.
  Тест меряет среднюю абсолютную разницу по вектору (≤ 0.06 на свипе 100 Гц–6 кГц между 16 и 48 кГц)
  и отдельно сообщает худшее измерение.
- Скewness и kurtosis (индексы 16, 17, 25, 26) помечены как зависящие от разрешения: это третьи и
  четвёртые моменты узкого спектрального пика, они следуют ширине бина. Отдельно: они переводятся
  мягкими отображениями, а не отсечением, иначе разные звуки становились одинаковыми.
- «Наклон спектра» — это наклон в дБ между 500–1500 и 3000–7000 Гц, а не регрессия: регрессия
  следовала утечке окна и была неустойчива.
- Раскладка — 84 измерения, а не ~95. Контраст 6 полос, MFCC 13, огибающие 4 полосы.
- Отдельный CLI `sonicator-features` собирается только с `-DSONICATOR_BUILD_TRAINING_TOOLS=ON`.

## 7. Конвейер обучения

### 7.1. Каталоги

```
tools/sonicator-features/        C++ CLI (CMake-опция SONICATOR_BUILD_TRAINING_TOOLS), использует core/dsp
services/training/
  datasets/<name>/               fetch.md (ручная загрузка), ingest.mjs, labels.map.json
  datasets/manifest.json         реестр (часть 5.3)
  build-features.mjs             обход каталога датасета → вызов CLI → features.jsonl
  train.mjs                      объединение источников, баланс, обучение
  evaluate.mjs                   отчёты (часть 7.5)
```

Датасеты лежат вне репозитория и вне iCloud, например `/Volumes/1TBSSD/Datasets/<name>` (ваша память: репозиторий
в iCloud тормозит). Объёмы — десятки гигабайт; в репозиторий не попадают, `.gitignore` проверяется тестом.

### 7.2. Формат строки признаков

```json
{"source":"nsynth","clipId":"bass_synthetic_033-092-100","license":"CC-BY-4.0","group":"tonal",
 "label":"bass","labelRaw":"bass","domain":"music","featureSchema":2,
 "bandwidthHz":8000,"features":[0.62,"…"],"mask":[1,1,"…"],"durationSec":4.0}
```

`clipId` и источник нужны для разбиения без утечки; в поставляемый файл не попадают.

### 7.3. Сопоставление меток

`labels.map.json` на датасет переводит исходные метки в таксономию Sonicator (`kick`, `snare`, `hat`, `bass`, …) и в
группу (`percussion`, `tonal`, `vocal`, `fx`, `foley`, `ambience`, `loop`). Правила:

- неоднозначные метки (`keyboard` у NSynth → `keys`, но `mallet`, `flute`, `reed` не имеют типа в меню) идут в
  отдельный список «нет соответствия», а не угадываются;
- метки, которых нет среди стандартных типов, не попадают в поставляемый файл, но остаются в обучающем наборе
  для групповой классификации и foley;
- сопоставление проверяется Node-тестом: нет неизвестных целевых меток; все не-сопоставленные перечислены.

Баланс: не более N клипов на метку на источник (стартово 2000), для NSynth — не более 5 нот на инструмент и
семейство; вес источников записывается в отчёт.

### 7.4. Модель и выбор

Два кандидата, оба считаются в `train.mjs`:

- **M1. Центроиды.** k-means на косинусной метрике, 4–8 центроидов на метку (вместо farthest-first). Подходит в
  существующий `AdaptiveClassifier` почти без изменений.
- **M2. Softmax-слой.** Стандартизация + линейный слой по всем меткам, обучение градиентным спуском в Node
  (без зависимостей), L2, калибровка температурой на отложенной выборке. Файл `global_model.json`
  (`schema: model.v1`, `featureSchema: 2`, `mu`, `sd`, `W`, `b`, `labels`, `groups`, `calibration`).
  В C++ — отдельный маленький класс `GlobalLinearModel` (матрично-векторное умножение, без аллокаций в горячем пути).

Выбор: поставляется M2, если превосходит M1 не менее чем на 2 пункта top-1 на внешней выборке, иначе M1. Абляция по
группам признаков (G2–G8): каждая группа включается в итоговый набор, только если даёт ≥ 0,5 пункта; результат в отчёт.

Приоритет локального над глобальным сохраняется: штраф 0.95, зазор 0.02; для M2 вероятность переводится в шкалу
сходства монотонным отображением, подбираемым так, чтобы пороги приёма (0.80 тип, 0.85 тег) давали ту же точность,
что и сейчас; таблица отображения лежит в файле калибровки.

### 7.5. Оценка

Разбиения без утечки: по инструменту (NSynth — официальные train/valid/test), по автору (Freesound), по dev/eval
(FSD50K), по установке (вклады).

Внешняя «золотая» выборка — ваша библиотека. 4526 записей на сервере хранят только 14 чисел и для v2 непригодны.
Поэтому:

- `sonicator-features --catalog <путь к БД>` читает локальный каталог и для подтверждённых строк
  `ml_feedback_samples` (origin `user` и `approved`) считает признаки v2 из аудиофайлов на диске;
- результат лежит в `~/…/gold-v2.jsonl` вне репозитория; аудио, пути и имена файлов не покидают машину;
- метрики из `training-report.md`: top-1 и top-3 по типам, по группам, доля покрытия и точность при пороге приёма,
  матрица ошибок для `snare/clap/hat`, `fx/impact/riser`, худшие 10 меток; отдельный раздел для foley-меток по
  FSD50K (метки есть, золотой выборки пока нет).

Сравнения в отчёте (на золотой выборке):

1. v1, локальный косинус, leave-one-out (текущий уровень, ~83%);
2. v2, локальные данные, leave-one-out;
3. v2, только публичные данные, без единой пользовательской записи (холодный старт);
4. v2, публичные + локальные (боевой режим).

### 7.6. Критерии приёмки

- (3) ≥ 70% top-1 на пересечении меток (kick, snare, hat, clap, bass, synth/lead/pad, fx, vocal…);
- (4) ≥ (1) + 5 пунктов; ни одна из групп percussion/tonal не хуже, чем в (1);
- точность при пороге приёма не ниже 0.90 на покрытии не ниже нынешнего;
- Node-тесты: воспроизводимость файла побайтно, отказ на неизвестной схеме и на значениях вне 0..1 / NaN, маска,
  баланс; C++-тесты: загрузка корректного и отказ на битом файле модели, приоритет локального, источник кандидата.
Если критерии не выполнены — поставка по решению владельца с цифрами отчёта (как в этапе 2).

## 8. Изменения в приложении

1. **Схема БД 16.** `ml_feedback_samples` получает `feature_schema INTEGER NOT NULL DEFAULT 1` и столбец
   `features_v2 BLOB` (или JSON). Старые строки остаются, локальные прототипы схемы 1 работают, пока не пересчитаны.
2. **Пересчёт признаков** фоновой задачей: для строк с `feature_schema=1` и файлом на диске считается v2
   (по одному декодированию на файл, отменяемо, как Smart-анализ); отсутствующие файлы остаются на схеме 1.
3. **AdaptiveClassifier:** поддержка двух схем и маски; сравнение только внутри одной схемы; загрузка
   `global_model.json` (M2) или `global_prototypes.json` v2 (M1).
4. **Резолвер:** источник `global_model` / `global_adaptive` в группе `adaptive`, ниже `user_adaptive`, ниже `dsp`
   и `asd_warp`, выше `path` (как в этапе 2).
5. **Вклады (contribute):** `featureSchema: 2`, число признаков берётся из схемы; `services/contribute-worker`
   принимает обе схемы; экспорт и обучение — обе. Версия согласия поднимается до 4 (содержание вклада стало
   богаче) — решение владельца, часть 10, п.2.
6. **About:** дата модели, число меток, строка атрибуции (часть 5.3). UI показывает источник типа без изменений.
7. `graphify update .`, `docs/ARCHITECTURE.md`, `docs/SMART_ANALYSIS.md`, `docs/DEPENDENCIES.md`, `docs/BACKLOG.md`.

## 9. Foley

В этом этапе — только подготовка; в UI foley-типы не выходят.

- Таксономия: `domain` (music / foley / ambience) и `group` у каждой метки; foley-метки берутся из FSD50K
  (Door, Glass, Water, Footsteps и аналоги из онтологии AudioSet, итоговый список — по `labels.map.json`).
- Обучение групповое: сначала `group`, потом метка внутри группы, это устойчивее на редких классах.
- Модель поставляется с foley-метками в файле, но `AdaptiveClassifier` отдаёт кандидатом только метки из списка
  стандартных типов; добавление foley-типов в список — отдельный шаг через `docs/TAG_PROMOTION.md` по решению владельца.
- Для foley нужны свойства не только «какой тип», но и «одиночное событие / петля / текстура»: G7 и длинное окно
  (часть 6.4) закладываются сейчас, интерфейс — позже.
- Золотой выборки для foley нет; пока оценка по FSD50K eval и по ESC-50/UrbanSound8K (уровень B, только отчёт).

ONNX: после этапа сравнить с эмбеддингами предобученной сети (YAMNet/CLAP-подобной в `.onnx`) на тех же разбиениях и
том же отчёте. Это отдельное решение; результат поможет решить, оставлять ли ONNX Runtime (52 МБ) в сборке.

## 10. Решения владельца

Приняты 2026-11-12:

1. Уровень B используется для обучения и входит в поставляемую модель (проект бесплатный и некоммерческий).
   Уровень C по-прежнему не используется. Остаётся флаг `--max-tier` для пересборки без B.
2. Версия согласия поднимается до 4.
3. Philharmonia (CC BY-SA 3.0) остаётся в плане, как датасет уровня B, то есть участвует в обучении.
4. Потолок размера модели снят: критерий — качество и точность. Рабочий ориентир: до нескольких мегабайт,
   выше — только если абляция показывает выигрыш; размер и время загрузки записываются в отчёт.
   Число признаков v2 больше не ограничивается 64–80: итоговый набор выбирается абляцией по точности.
5. Путь датасетов: `/Volumes/1TBSSD/Datasets/`.

## 12. Риски

| Риск | Что делаем |
|---|---|
| Сдвиг домена: студийные ваншоты ≠ ваши паки | вес пользовательских данных выше; золотая выборка; приоритет локального |

| Вклады схемы 1 несовместимы со схемой 2 | обе схемы в экспорте; старые записи служат для v1-базы |
| Время анализа | бенчмарк в этапе 2, бюджет +30% |
| Размер репозитория | датасеты и признаки вне репозитория; в репозитории только итоговый JSON |
