# Пользовательские компоненты Sonicator — план и ТЗ

Дата: 2026-11-14. Статус: проектное ТЗ; реализация не начата.

## Замысел

Пользователь устанавливает **компоненты, расширяющие само приложение Sonicator**: новые декодеры и форматы, команды меню, средства обработки и анализа, панели интерфейса и интеграции. Разработчик пишет компонент на публичном SDK Sonicator и распространяет готовый пакет. Пользователь устанавливает его из архива или по ссылке на репозиторий через Settings → Components.

Ориентир — модель [компонентов foobar2000](https://www.foobar2000.org/components): там компоненты добавляют декодеры, DSP, панели UI, средства тегирования и другие функции. Установка архивов через Preferences → Components описана в [официальном FAQ](https://www.foobar2000.org/FAQ). Sonicator использует собственный пакет и SDK. Эти компоненты не являются VST3/AU-сборкой самого Sonicator из `plugin/` или загрузчиком сторонних VST.

Пункт внешнего бэклога `~/Documents/orange303/Sonicator Features.md` уже предусматривает пользовательские плагины для форматов и сетевых сервисов.

## Установка и управление

- **Из архива:** Settings → Components → `Install from file…` принимает `.sonicator-component` (ZIP с манифестом и готовым бинарным компонентом для платформы). Перед установкой показывать название, автора, версию, совместимость, функции и сведения о происхождении. После подтверждения проверить пакет и установить. Для загрузки нового кода допустим перезапуск приложения.
- **Из репозитория:** `Install from repository…` принимает HTTPS URL репозитория или конкретного релиза. Sonicator находит опубликованный готовый пакет для текущей ОС/архитектуры и проводит его через тот же процесс проверки. Исходники не компилируются, скрипты из репозитория не запускаются. Если совместимого релиза нет, показать причину. Первый поддерживаемый хостинг и соглашение о релизах определить до реализации.
- **Управление:** список показывает ID, автора, версию, источник, типы возможностей, состояние и ошибку. Действия: включить/выключить, обновить, удалить, открыть страницу проекта и журнал. Обновления не устанавливаются молча. Изменение установленного нативного кода может требовать перезапуска.
- **Сохранность:** удаление компонента не удаляет исходные файлы, записи библиотеки, теги и оценки. Для файла, которому нужен отключённый декодер, показывать объяснение вместо удаления записи.

## Точки расширения SDK

| Тип компонента | Возможность | Место в Sonicator |
|---|---|---|
| Формат | Определение сигнатуры, метаданные, потоковый PCM reader, элементы контейнера, необязательный writer | Сканирование, каталог, предпросмотр, Extract, Convert |
| Команда | Действие над файлом, выделением, папкой или каталогом | Контекстное меню, Tools |
| Обработка | Офлайновая аудиооперация или конвертация | Tools, Convert, редактор при совместимом контракте |
| Анализ | Тип, BPM, тональность, метаданные, теги с указанием происхождения | Фоновые задания, каталог |
| UI | Панель, вкладка, визуализация, собственные настройки | Зарезервированные области и Settings |
| Интеграция | Внешнее приложение или сетевой сервис | Команды и отдельные настройки |

Первый выпуск SDK должен поддержать **reader формата, команду контекстного меню и страницу настроек компонента**. Остальные возможности добавлять по этапам через тот же реестр сервисов. Для UI-панелей нужен отдельный жизненный цикл и правила совместимости.

### Контракт формата

- `Probe` по ограниченному префиксу и сигнатуре; расширение файла служит подсказкой.
- `Metadata` различает одиночный звук, контейнер и инструмент. Неизвестные свойства остаются неизвестными.
- Потоковые `Open/Read/Seek/Close` для PCM; контейнер дополнительно перечисляет вложенные объекты и открывает выбранный.
- Необязательный `Encode` объявляет поддерживаемые частоты, каналы, PCM-типы и параметры качества. Без него формат не предлагается как выходной в Convert.
- Встроенные декодеры Sonicator имеют приоритет по умолчанию. Конфликт двух компонентов показывать пользователю; настройка приоритета — отдельный этап.

### Контракт функций

Команда объявляет ID, название, точку меню, подходящие типы объектов и параметры. Получает снимок выделения, запускает длинную работу в фоновом задании с прогрессом и отменой. Анализатор публикует результаты через API Sonicator с источником и версией алгоритма; пользовательские исправления не перезаписываются. Компонент может иметь свою страницу Settings. Публичный SDK включает документацию, заголовки, шаблон сборки, примеры и валидатор пакета.

## Нативная модель и риски

По аналогии с компонентами foobar2000 базовый путь — **нативный бинарный компонент внутри процесса Sonicator** через стабильный C ABI и версионированные таблицы сервисов. На macOS — библиотека/бандл, на Windows — DLL. Это позволяет регистрировать декодеры, команды и UI. Без доказанной безопасной выгрузки изменение компонентов требует перезапуска.

**Нативный компонент имеет доступ к процессу Sonicator и способен привести к сбою или повредить данные.** Архив, хеш, подпись и перечисление функций не изолируют его. Перед установкой стороннего кода нужно прямое предупреждение. Отдельный процесс можно позже предложить для отдельных сетевых или ненадёжных обработчиков, но это не базовая модель всей системы.

- Архив проверять на `../`, абсолютные пути, ссылки за пределы пакета, дубликаты, чрезмерную распаковку и неподходящую архитектуру. Установка через временную директорию и атомарное переключение версии с возможностью отката.
- Манифест содержит стабильный ID, автора, версию, диапазон Sonicator/API/ABI, платформу, архитектуру, зависимости, способности, сайт, хеши файлов и сведения о подписи. URL репозитория сам по себе не является подтверждением доверия.
- Перед сетевой отправкой содержимого файлов или метаданных показывать отдельное согласие. Для официального каталога компонентов предусмотреть проверяемую подпись издателя; неподписанный локальный пакет требует явного подтверждения.
- Диагностика записывает ID и версии компонентов. После сбоя при загрузке должен быть доступен запуск без сторонних компонентов и отключение проблемного пакета.
- VST3/AU-версия Sonicator работает в процессе DAW и в первой версии **не загружает пользовательские нативные компоненты**. Это отдельная задача.

## Связь с текущей архитектурой

Сейчас обычные форматы частично заданы в `FileScanner`, встроенные декодеры регистрируются в `registerSonicatorFormats`, а часть контейнеров отдельно выбирается в `AudioEngine`. Перед расширением нужен единый реестр способностей для сканера, предпросмотра, Extract и будущего Convert. `SonicatorCore` владеет реестром и API; `SonicatorUI` — точками меню, панелями и Settings. Состояние компонентов хранить отдельно от SQLite-каталога семплов.

## Этапы

1. Зафиксировать ABI, версионирование, манифест, SDK, правила загрузки и восстановления после сбоя; собрать образцовый компонент.
2. Добавить Settings → Components и установку из архива, проверки, включение/выключение, удаление, журнал и запуск без сторонних компонентов.
3. Ввести единый реестр форматов; провести внешний decoder от сканера до предпросмотра и Extract.
4. Добавить регистрацию команд контекстного меню, фоновых заданий и страницы настроек компонента.
5. Добавить установку готового пакета по HTTPS URL репозитория/релиза и обновления.
6. Расширить SDK для writers, анализа и UI-панелей; подключить к Convert после появления его стабильного API.

## Каталог идей пользовательских компонентов

Это **кандидаты для сторонних или демонстрационных компонентов**, а не обещание встроить их все в Sonicator. Перед разработкой каждого проверить, какую точку SDK он использует, какие данные меняет и как пользователь отменяет или проверяет результат.

| Компонент | Функция | Нужные точки SDK |
|---|---|---|
| Legacy Format Pack | Чтение старых семплов и контейнеров: IFF/8SVX, AU, дополнительные варианты VOC и tracker-форматов | Probe, metadata, потоковый reader, перечисление элементов контейнера |
| Sampler Bank Explorer | Просмотр пресетов, зон и отдельных семплов в банке, выборочное извлечение | Reader контейнера, панель UI, команда Extract |
| Batch Rename | Переименование по шаблонам из типа, BPM, тональности, номера и имени папки с предпросмотром изменений | Команда выделения/папки, доступ к метаданным, безопасные операции над файлами и обновление каталога |
| Metadata Importer | Импорт BPM, тональности, тегов и loop points из sidecar-файлов и библиотек других приложений | Metadata provider, фоновое задание, запись результатов с происхождением |
| Audio Toolkit | Пакетные trim silence, normalize, remove DC, mono и fades | Офлайновая обработка, команда, безопасный вывод файлов |
| Converter Codec Pack | Дополнительные выходные кодеки и параметры качества для конвертера | Writer/Encode API, декларация ограничений кодека |
| Duplicate Inspector | Группы семплов, похожих по звучанию, сравнение и прослушивание | Чтение каталога и аудио, анализатор, панель UI |
| Tagging Provider | Альтернативный локальный классификатор или инструмент полуавтоматической разметки | Анализатор, предложения тегов, происхождение результатов, подтверждение пользователя |
| AI Analysis Provider | Подключение локальной модели или внешнего сервиса для описаний и тегов | Анализатор, настройки, отдельное согласие на передачу аудио/метаданных по сети |
| DAW Bridge | Команды `Send to Sample Dicer`, `Loop Dicer`, `Drum Dicer` и другие передачи в DAW | Команда выделения, экспорт/IPC, настройки интеграции |
| Library Panel | Альтернативное представление каталога, например облако тегов с точками-семплами и предпрослушиванием при наведении | UI-панель, запросы каталога, управление preview |
| Workflow Actions | Команды «собрать в папку проекта», «экспортировать список», «подготовить набор для DAW» | Команда, доступ к выделению/метаданным, безопасные файловые операции |

Первые три образца для проверки архитектуры SDK: **один декодер редкого формата**, **Batch Rename** как команда контекстного меню и **простая панель каталога**. Они проверяют три независимых направления расширения: чтение файлов, действия и UI. Декодер и команда входят в первый этап SDK; панель следует после фиксации её жизненного цикла и правил совместимости. Выбор конкретного редкого формата сверять с текущими встроенными декодерами и `docs/EXOTIC_FORMATS.md`, чтобы пример не дублировал уже реализованное.

## Критерии приёмки первого выпуска

- Архив устанавливается через Settings после проверки и предупреждения; после перезапуска доступны decoder и команда.
- Репозиторий с готовым совместимым релизом проходит тот же путь; исходники не собираются и не выполняются.
- Повреждённый пакет, неподходящая ОС/ABI и конфликт ID не ломают установленную версию; причина видна пользователю.
- Отключение или удаление убирает функции после перезапуска, сохраняя файлы и пользовательские данные каталога.
- Команда принимает выделение, показывает прогресс/отмену и не работает на audio callback.
- После сбоя при загрузке Sonicator можно запустить без сторонних компонентов.
- Образцовые компоненты и оба способа установки проверены на поддерживаемых macOS и Windows. Пользователю ясно, что код компонента работает внутри процесса приложения.

## Открытые решения

- Точный C ABI и жизненный цикл сервисов на macOS/Windows.
- Контракт UI-панелей: нативный JUCE виджет или ограниченный декларативный интерфейс.
- Первый хостинг репозиториев и формат публикации релизов.
- Требования к подписи для ручной установки и будущего официального каталога.
