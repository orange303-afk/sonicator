# Akai S3000 BIN/CUE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the samples on the two Robert Miles Akai S3000 discs (BIN/CUE) play, index and
export, and prove the PCM bit-exact against the independent `Converted` WAVs.

**Architecture:** One local change in the decoder: accept the 192-byte S3000 header alongside
150, using an exact size equation, behind a new header-parsing function. Everything else
(cue, FAT, browser, indexer, export) already exists and is proven by generalised opt-in tests
against the real images. No UI or schema changes.

**Tech Stack:** C++20, JUCE, Catch2 v3, CMake presets (`release` →
`~/Library/Caches/sonicator-build/release`).

**Spec:** `/Users/ilyaorange/.opencode/plan/2026-11-12-akai-s3000-bincue-tz.md`. In Task 0 it is
copied to `docs/superpowers/specs/2026-11-12-akai-s3000-bincue-design.md`, and this plan to
`docs/superpowers/plans/2026-11-12-akai-s3000-bincue.md`.

## Global Constraints

- Images and `Converted` are read-only: never written, renamed or mounted. Opt-in tests verify
  size, mtime and SHA-256 of each image afterwards.
- Header length: only 150 or 192, chosen by `L + 2*frames == declaredBytes`. Anything else
  (including 190) → `DiscStatus::unsupported`, and the error text contains `unverified`.
- Decode and export return **all** frames of the sample. start/end are used for verification
  only.
- Tests never touch `~/Library/Sonicator/sonicator.sqlite`: catalog checks use a `TestDirectory`
  database.
- The repo is in iCloud: no `grep -r` or `git log` without `-n` from the root. Before every commit,
  `git ls-files | grep -E ' [0-9]+\.'` must be empty.
- Build: `cmake --build --preset release` (if no build preset exists, use
  `cmake --build ~/Library/Caches/sonicator-build/release`). Tests:
  `~/Library/Caches/sonicator-build/release/tests/SonicatorTests "<tag>"`.
- Branch `feature/akai-s3000-bincue`. At the end: merge into main (ff), full `ctest`, push, delete
  the branch.
- Stop conditions from the spec (an unknown header length or id, any byte mismatch in the
  reference check, PCM changed by the converter): stop and report to the user.

## Review Focus

1. **The right half of a stereo pair.** It is hidden from the listing (merged), but it must decode
   with the 192 header too. Task 2 decodes every record, including `entry.partner`.
2. **A 192-byte header with mismatched frames** (corrupt record). It must be refused, not read
   at 150. Task 1, test `S3000 header with inconsistent frames is refused`.
3. **Header split across a CD sector boundary.** The header is read through
   `AkaiChainByteSource` over a 2352 track. This is covered by decoding every record of both
   discs in Task 2 (headers start at 8192 boundaries, and sectors are 2048 bytes of user data,
   but the chain does cross sectors).
4. **Duplicate names across volumes and leading spaces in `Converted` names.** Matching uses
   trim + case-insensitive comparison, and only unique names on both sides are compared;
   ambiguous ones are counted separately (Task 3).
5. **Regression on Real Mega Rhythm (150).** Synthetic test in Task 1. The real image is run in
   Task 4 if found (`find /Volumes -iname '*Real Mega Rhythm*' -maxdepth 4`); otherwise this is
   stated in the report.

### Task 1: S3000 header in the decoder

**Files:**
- Modify: `core/disc/AkaiSampleReader.h`, `core/disc/AkaiSampleReader.cpp`
- Modify (comments only): `core/disc/AkaiFilesystem.h:27-30` ("Verified raw variant only: 150…"
  → "150-byte S1000 or 192-byte S3000 header + signed 16-bit LE mono")
- Test: `tests/TestAkaiSampleReader.cpp`

**Interfaces:**
- Produces:
  ```cpp
  struct AkaiSampleHeader
  {
      unsigned id = 0;            // byte 0x00
      uint32_t headerBytes = 0;   // 150 or 192
      uint32_t frames = 0;        // u32 LE @0x1a
      uint32_t startFrame = 0;    // u32 LE @0x1e
      uint32_t endFrame = 0;      // u32 LE @0x22
      uint16_t sampleRate = 0;    // u16 LE @0x8a
      uint8_t rootNote = 0;       // byte 0x02
  };
  DiscResult<AkaiSampleHeader> readAkaiSampleHeader(const ReadOnlyByteSource& source,
                                                    uint64_t declaredBytes, CancelCheck cancel);
  ```
  `decodeAkaiSample` keeps its signature. It calls `readAkaiSampleHeader` and reads data from
  `header.headerBytes`.
- Error rules in `readAkaiSampleHeader`:
  - `declaredBytes > source.size()` → malformed;
  - `declaredBytes < 152` → malformed "shorter than its header";
  - id is not 1 or 3 → unsupported "unverified Akai sample header id";
  - neither 150 nor 192 satisfies the equation, or frames == 0 → unsupported "unverified Akai
    sample header variant (header/data size mismatch)";
  - rate outside 8000..96000 → malformed.
  - Read `min(192, declaredBytes)` bytes; for the 150 variant the fields at offsets ≤ 0x8b are
    inside it.

- [ ] **Step 1: tests.** In `makeSample` add a `startFrame`/`endFrame`/`root` parameter (written
  at 0x1e/0x22/0x02) and an optional frame override for the header. New cases:
  - `S3000 192-byte header decodes from offset 192`: `makeSample(t,"s3k.aki",6,44100,192)` →
    `ok`, `frames==6`, `left[1]==Approx(32767/32768)`, `left[2]==Approx(-1)`.
  - `Header fields are parsed`: 192 header, frames 10, start 2, end 8, root 60, rate 44100 →
    `readAkaiSampleHeader` gives `headerBytes==192, frames==10, startFrame==2, endFrame==8,
    rootNote==60, sampleRate==44100, id==3`; for the same 150 file `headerBytes==150`.
  - `S3000 header with inconsistent frames is refused`: file of 192 + 2*10 bytes, header says
    frames 11 → `status==unsupported`, error contains `unverified`.
  - Keep the existing 190 test as is (it must still be refused).
- [ ] **Step 2:** build, run `SonicatorTests "[disc-akai-pcm]"` → the new ones FAIL, the old ones
  PASS.

  the 12-byte decoding into the test, or make `decodeName` public static — **decision: make it

**Interfaces:**

- [ ] **Step 1: test.**
  - Env vars: `SONICATOR_DISC_IMAGE` and `SONICATOR_DISC_REFERENCE_DIR` (recursive `*.wav`,
    excluding `*.asd`/`*.reapeaks`).
  - Read the reference WAVs as raw int16: a small RIFF parser in the test (`fmt ` → format 1,
    16 bit, 1–2 channels; `data` → frames). Anything else is counted as `skippedFormat`.
    Don't use the JUCE float reader, so the comparison stays integer.

    header, trimmed, uppercased), records only (not merged entries).

    separated by `;`, which is supported) are compared; the rest are `ambiguous`.
  - Comparison: the reference is mono → disc frames `[start, end)` as int16 are equal to
    reference frames `[0, end-start)`. Count `lengthOther` if
    `refFrames != end-start+1`.
  - A stereo reference is compared against the L/R pair whose base name matches (left/right
    channel against the respective records).
  - Assertions: `mismatches == 0`, `compared >= 500`. INFO with all counters and the first 20
    mismatches (name, first differing frame).
  - Int16 is read directly from the disc data: add
    `DiscResult<std::vector<int16_t>> readAkaiPcm16(ByteSourcePtr, const AkaiSampleHeader&, CancelCheck)`
